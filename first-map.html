Rustic Maps SDK

Your first map

Install the SDK, register a map provider with your API key, and draw a first rendered map surface. Choose your platform’s tab and follow its steps top to bottom; every snippet is a complete step and compiles against the FFI contract.

Before you start

Android Studio with the SDK 36 toolchain, a project with minSdk = 24, and a downloaded release AAR copied into app/libs/, and a map-platform API key for the provider you register.

Install the artifact

In your application module’s build.gradle.kts, add the local AAR and the two runtime dependencies the Kotlin bindings need:

repositories {
    flatDir { dirs("libs") }
}

dependencies {
    implementation(files("libs/rustic-maps-sdk-android-v0.1.0.aar"))
    implementation("net.java.dev.jna:jna:5.18.1@aar")   // the UniFFI runtime
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-core:1.10.2")
}

The version in the file name is the release you downloaded; keep it exact.

Build the SDK and register the provider

Construct the SDK object and install the map-platform provider set in one call, as the reference application does at startup:

import uniffi.rustic_maps.MapSdk

val mapSdk = MapSdk()
mapSdk.setProviderCredential(mapQuestApiKey)

The call throws verbatim when the key is refused, so surface it in your error state rather than continuing.

Read the key at runtime — from your app’s own secure configuration or a settings surface — never from source and never baked into the build. The reference application’s settings view takes it at runtime, and its UI automation injects it through a launch intent. The registration call itself is explicit, as shown.

Show the map in your layout

The package ships a lifecycle-aware MapView that owns the surface, the frame pump, resizing, gestures and the camera animation. Drop it into your composition and give it the SDK:

import com.angoratek.rusticmaps.compose.MapView

MapView(
    sdk = mapSdk,
    listener = mapViewListener,
    modifier = Modifier.fillMaxSize(),
)

Place it with AndroidView when you are not using Compose; the widget is a plain SurfaceView subclass. Either way you never touch a native window pointer, never attach, and never pump frames — the view does all of it, and pauses itself when the host stops or the window detaches.

Open the map

Set the camera the view draws with. The shared demo camera on every platform is Capitol Park, Sacramento at zoom 12, north-up and top-down:

val mapCamera = MapCameraPose(
    latitudeDegrees = 38.5766,
    longitudeDegrees = -121.4944,
    zoomLevel = 12.0,
    bearingDegrees = 0.0,
    pitchDegrees = 0.0,
)
mapView.setCamera(mapCamera)

animateCamera eases to a pose over a duration instead, and fitBounds frames a box inside a viewport with edge insets — the two calls the reference application’s search results and route preview use.

Pan the camera from a gesture

Gesture recognition stays in your platform view; the camera algebra is the SDK’s. Forward the drag delta to the camera member and keep the pose it answers (the ground point the pointer grabbed becomes the new center):

val pannedCamera = camera.panByScreenPixels(
    deltaXPixels = dragDeltaXPixels,
    deltaYPixels = dragDeltaYPixels,
    viewport = ViewportSize(
        widthPixels = viewportWidthPixels,
        heightPixels = viewportHeightPixels,
    ),
    fieldOfViewDegrees = 60.0,
)
center = pannedCamera.center()

MapView already applies pan, pinch and rotation from its own gesture handlers, so this is the member to reach for only when you drive the camera from a control of your own or from a test.

zoomByLevelsAroundScreenPoint and rotateByDegreesAroundScreenPoint apply the pinch and twist deltas with the same focal-point correction, so every platform computes identical results.

Add your first overlay

Draw more than tiles by setting the overlay list the surface draws every frame. A route polyline over the demo’s two waypoints (Capitol Park to Tower Bridge):

import uniffi.rustic_maps.GeographicCoordinate
import uniffi.rustic_maps.MapOverlay
import uniffi.rustic_maps.MapOverlayKind
import uniffi.rustic_maps.OverlayColor

mapView.setOverlays(
    listOf(
        MapOverlay(
            kind = MapOverlayKind.ROUTE_POLYLINE,
            coordinates = listOf(
                GeographicCoordinate(38.5766, -121.4944),
                GeographicCoordinate(38.5802, -121.5083),
            ),
            rgbaColor = OverlayColor(red = 0.2, green = 0.4, blue = 0.9, alpha = 0.9),
            widthPixels = 3.0,
            // The other payload fields stay null for this kind.
            ringCoordinates = null,
            pointMarkerPositions = null,
            pointMarkerRadiusPixels = null,
            trafficFlowSegments = null,
        ),
    ),
)

setOverlays is the bulk call for a list you own whole: it replaces the drawn list in one go. For overlays you keep across frames, address them individually — addOverlay answers an opaque identifier, updateOverlay replaces that entry in its draw position, and removeOverlay answers whether it was present:

val routeOverlayId = mapView.addOverlay(routePolylineOverlay)
// ...later, when the route changes:
mapView.updateOverlay(routeOverlayId, replacementPolylineOverlay)
// ...and when it is dismissed:
mapView.removeOverlay(routeOverlayId)

Identifiers are monotonic per view and never reused; clearOverlays() clears both the bulk list and the addressed overlays.

Build the SDK and register the provider

The reference application constructs the session SDK exactly like this:

import RusticMapsSDK

Pass a key read at runtime (app settings, a secure configuration store, or a launch environment used by automation). Do not add it to Info.plist or to an xcconfig that ships in the app; the reference app’s settings sheet takes it at runtime.

Fit the map to what you show

For a bounded region, let the camera fit the box instead of hand-tuning zoom, exactly as the route-preview flow does:

let fittedCamera = try MapCamera.fitBounds(
    boundingBox: regionBox,
    viewport: viewport,
    edgeInsets: EdgeInsets(
        left: 224, top: 48, right: 48, bottom: 96
    ),
    maximumZoomLevel: 22
)

Before you start

An initialized React Native (bare workflow) application on Android arm64-v8a or iOS, and a downloaded release tarball, and a map-platform API key for the provider you register.

Install the artifact

Install the release tarball from your checked-in copy; no registry is involved:

npm install ./rustic-maps-sdk-rn-v0.1.0.tgz

The package carries the TurboModule glue; link it with your React Native version’s normal autolinking (pod install on the iOS side).

Build the SDK and register the provider

Importing the package entry installs the Rust module into Hermes once, and the generated classes are named exports of it. Construct the SDK and register the provider set:

import { MapSdk } from '@angoratek/rustic-maps-sdk';

export async function createMapSdk(mapQuestApiKey) {
  const mapSdk = await new MapSdk();
  await mapSdk.setProviderCredential(mapQuestApiKey);
  return mapSdk;
}

The returned promise rejects verbatim when the key is refused.

Take the key at runtime — a settings screen, secure storage, or a launch environment for automated tests. Do not bake it into the JS bundle or a native build file; the reference app reads it from its settings surface and keeps it only when the user opts in.

Draw a map surface

The package ships a typed <MapView> component over the native widget (Android SurfaceView, iOS CAMetalLayer): it owns the surface lifecycle, frame pump, gestures, camera verbs, id-addressed overlays and the callback set, so the host application only composes it. The package also owns the one native SDK instance — construct it through MapsSdk and hand it to the view.

import { MapsSdk } from '@angoratek/rustic-maps-sdk/MapsSdk';
import { MapView, type MapViewHandle } from '@angoratek/rustic-maps-sdk/MapView';

const maps = await MapsSdk.initialize();   // one native SDK per process
await maps.setProviderCredential(mapQuestApiKey);

<MapView
  ref={mapViewRef}
  maps={maps}
  style={{ flex: 1 }}
  onMapReady={() => { /* frame the first camera */ }}
  onCameraChanged={(camera) => { /* reflect the pose in your UI */ }}
  onError={(failure) => { /* the contract's error detail, verbatim */ }}
/>;

The generated contract classes from the package root remain available for advanced use (for example a custom host view), but the component is the documented path: it keeps one SDK instance and one frame pump.

Check the installation with the compiled-version probe:

import { getSdkCompiledVersion } from '@angoratek/rustic-maps-sdk';

getSdkCompiledVersion();
// → "0.1.0": the Rust core loaded and answered through the TurboModule.

Before you start

A Chromium-based browser with WebGPU (flag-free in Chromium since 113; Safari from version 26; Firefox from 141, desktop first) and a downloaded release tarball of the wasm package.

Install the artifact

Unpack the release and serve its directory from any static file server over HTTPS or localhost:

npm install ./rustic-maps-sdk-web-v0.1.0.tgz
cp -r node_modules/@angoratek/rustic-maps-sdk-web ./web
node ./web/server.js   # your own static server; localhost is fine

Load the module and start the core

<canvas id="map-canvas"></canvas>
<script type="module">
  import {
    init,
    initializeSdk,
  } from './web/map_web_bindings.js';
</script>

The page’s entry, exactly as the reference application does it:

import init, {
  MapCamera,
  MapView,
  TileResolution,
  devicePixelRatioThreshold,
  initializeSdk,
  getSdkCompiledVersion,
} from './web/map_web_bindings.js';

const maps = await MapsSdk.create();
console.log(`Maps SDK ready (version ${maps.compiledVersion})`);

The status probe answers the same version string the native surfaces do.

Draw a map surface

MapView claims the canvas element, acquires the WebGPU device, and renders tiles fetched from a same-origin path you host:

const canvas = /** @type {HTMLCanvasElement} */ (
  document.querySelector('#map-canvas')
);
// A page creates one SDK root and hands it to every view; the view's tile
// resolution follows the device pixel ratio (a screenshot or capture tool
// can pin it with the optional third argument: `new MapView(canvas, maps,
// TileResolution.Retina)`).
const maps = await MapsSdk.create();
const mapView = new MapView(canvas, maps);
const adapterDescription = await mapView.initialize();
console.log(`rendering on ${adapterDescription}`);

// The canvas fetches its raster tiles from the same-origin
// /tiles/{zoom}_{tileX}_{tileY}.png path; record or serve imagery there.

// The render frame: build the shared demo camera, present, repeat on
// change. This is the same pose every platform starts from.
const fieldOfViewDegrees = 60;
const camera = new MapCamera(38.5766, -121.4944, 12.0, 0.0, 0.0);
const frameStatistics = await mapView.renderFrame(camera, fieldOfViewDegrees);

If initialize() fails in a browser without WebGPU, give the page the documented degradation message (name navigator.gpu and the missing capability; link the MDN compatibility table) — never a user-agent sniff.

Project and unproject

The same camera answers screen mappings without rendering:

const screenPoint = camera.projectToScreen(
  latitudeDegrees,
  longitudeDegrees,
  canvas.width,
  canvas.height,
  fieldOfViewDegrees,
);
const groundCoordinate = camera.screenToGroundCoordinate(
  screenPoint.x,
  screenPoint.y,
  canvas.width,
  canvas.height,
  fieldOfViewDegrees,
);
const tileKeys = camera.visibleTileKeys(
  canvas.width,
  canvas.height,
  fieldOfViewDegrees,
  tileZoom,
);

The TypeScript types of these value shapes are mirrored in the package’s hand-reviewed type surface; field names are lower camel case.

Pan the camera from a gesture

Keep pointer capture and delta shaping in your page and forward the travel to the camera member; it answers the resulting pose (the ground point the pointer grabbed becomes the new center):

const pannedPose = camera.panByScreenPixels(
  deltaXPixels,
  deltaYPixels,
  canvas.width,
  canvas.height,
  fieldOfViewDegrees,
);
// { latitude, longitude, zoomLevel, bearingDegrees, pitchDegrees }

zoomByLevelsAroundScreenPoint and rotateByDegreesAroundScreenPoint apply pinch and twist deltas with the same focal-point correction; the older free helpers (panCameraByScreenPixels, …) remain as aliases.
