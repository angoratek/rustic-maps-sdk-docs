Rustic Maps SDK

Rustic Maps SDK

Rustic Maps SDK is a native map SDK written in Rust. It gives your application map rendering, search, routing, turn-by-turn navigation, and offline maps from one Rust core, delivered to Android (Kotlin), iOS (Swift), and React Native through UniFFI’s UDL-first bindings. WebAssembly is a first-class target, so the same core renders map tiles in a browser with WebGPU.

What the SDK gives you

One contract, four platforms

The FFI surface is a single UniFFI interface definition. The Kotlin, Swift, and React Native Turbo Module bindings are generated from it, and the WebAssembly TypeScript mirror is regression-checked against it. The contract changes addition-only: existing members keep their signature and meaning.

Search, routing, and traffic

Ten vendor-neutral provider contracts cover geocoding (forward and reverse), routing, the distance matrix, place search, traffic incidents, traffic flow, elevation, raster tiles, vector tiles, and offline routing. A full map-platform provider implementation backs them, rate-limited and retry-aware, with a disk response cache under your own byte budget.

A rendering core that draws anywhere

The renderer spans web-mercator projection, an anchored camera with animations and fit-bounds framing, exact frustum tile listing, a frame-driven tile scheduler with per-frame budgets and parent fallback, and a byte-budget tile texture pool feeding a wgpu renderer. The same scene draws headless in tests, on Android and iOS surfaces, and in the browser through WebGPU.

Turn-by-turn navigation

The navigation state machine follows the Ferrostar model. It composes banner and spoken instructions verbatim from the provider’s text, publishes speech-instruction triggers at documented distance bands, and hands deviation handling and reroute policy to you at clear seams.

Offline maps

A deterministic compiler turns an OpenStreetMap PBF extract into a compact self-describing routing archive. An offline routing provider answers routes over the memory-mapped graph with recorded turn restrictions, and a fallback decorator wraps your online provider when you opt into it.

Structured diagnostics

A bounded, per-subsystem diagnostics ring streams structured log events to a foreign listener with coordinate scrubbing at the sink. Readbacks expose frame tile statistics, cache terms, and provider-failure records, so a screen in your product can show exactly what the SDK is doing.

Versions policy

  • Pin exact versions. Release archives are immutable and carry a version in their file name (rustic-maps-sdk-android-v0.4.0.aar and the like); keep the version you validated against, and upgrade deliberately.
  • One version line. The Cargo workspace version is the single source of truth: the Android Maven publication, the npm packages, and the Swift manifest are all stamped from it at release time. The compiled SDK also answers the version probe (getSdkCompiledVersion across the FFI), so your diagnostics screen can verify the loaded library matches the artifacts you shipped.
  • The FFI contract changes addition-only. Existing members keep their signature and meaning, so a minor-version upgrade keeps your compiled bindings valid; packaging changes (an artifact set or renamed target) bump the minor version while the release is 0.x.
  • Semantic versioning from 0.1.0. Versioned tags (vX.Y.Z) are the release trigger; tags are never moved, and a broken release is superseded by a new tag.
  • Checksums and signatures. Every release carries a per-asset SHA-256 checksum, an aggregated checksum manifest, and Sigstore signature bundles; verifying them is part of the Downloads flow.

Where the numbers come from: the sizes and tool versions above are copied from the packaging design’s recorded measurements and the build scripts that produce the artifacts, and they travel with the release notes of each tag.

Performance and profiling

This page is integration guidance: the practices that keep map rendering, routing, and navigation responsive, and the readbacks the SDK exposes so you can measure your own integration on your own hardware and scenes.

The one figure the project publishes is the browser frame’s own breakdown. A 1920 × 1080 vector base over the demo tiles, in a scripted pan on an Apple Silicon host with hardware WebGPU, spends about 6 ms a frame at the median (6.9 ms at p99), of which 5 ms is overlay tessellation; the raster base on the same ground spends 0.1 ms. Treat those as a starting point for your own measurement, not as a guarantee: any figure you quote should come from your own device and your own route mix.

Construct the SDK once

  • Build one MapSdk object and register your providers once at startup. Re-registration replaces every slot (including a cached tile slot), so an accidental double registration silently reopens the cache and resets its tuning: register, then tune with setRasterTileCacheTimeToLive.
  • Keep a single Navigator around the lifetime of a trip screen; subscriptions are explicit and cheap, but re-subscribing listeners is wasted work on every frame.

Frame the camera with the contract’s helpers

  • Prefer the fit_bounds camera constructor for route previews and search-result framing. It computes a top-down, north-up camera that keeps the whole box visible inside the insets you give it, instead of a hand-tuned zoom level that breaks on another screen size.
  • Give it real insets. Route cards, attribution, and sheets are overlays your application owns; the insets tell the camera what the map may not hide. The insets-aware framing is what keeps the destination inside the visible region on every device.
  • Read the camera back with the attribute getters (center, zoomLevel, bearingDegrees, pitchDegrees) when you need to persist or compare a pose; the camera carries no setters, so a new pose is a new constructor call.

Let the render loop stay explicit

  • Frames are explicit by design: the platform view drives draw from its own cadence (a display link or choreographer callback). Do not add a second render loop; serialize draws and never call draw again while a previous call is still in flight — a draw in flight reports the next frame busy, and the cadence retries it.
  • Poll isFrameSettled in the render pump to skip draw when a re-draw would present the same pixels: true when the camera, overlay list, and location indicator are unchanged and no pending tile pixels remain. This keeps battery cost near zero on a static map.
  • Read FrameStatistics from every draw. The four readiness counts (present, fallback, deferred, unavailable) always add up to the requested count, so a persistent slice of deferred tells you your per-frame fetch budget is the limiter on your network, and a slice of unavailable points at provider refusals rather than slow ones.
  • Feed gesture deltas through the SDK’s camera seam (pan by pixels, focal-point zoom and rotation) instead of moving the viewport yourself; the SDK clamps zoom and pitch through the camera’s own ranges and holds the focal point exactly.

Size the tile cache deliberately

  • Register the tile cache with an absolute byte budget that fits your product (the reference application’s demo budget is 16 MiB for the whole bundled demo region). The budget is a registration-time fact: retuning it means re-registering.
  • Set the tile time-to-live live through setRasterTileCacheTimeToLive. Imagery-provider terms put a ceiling on what the cache may retain; a request above the ceiling is accepted and the ceiling clamps what is stored. Read rasterTileCacheTerms to display the effective value, the ceiling, and the default in a settings or diagnostics screen.
  • Do not set a zero time-to-live; the call is refused because it would expire every entry on capture.

Keep the provider path under your quota

  • The provider implementation carries a shared token-bucket rate limiter and bounded idempotent retries. Treat RateLimitExhausted as “retry after the next refill”, not as an error to surface in the UI.
  • Cache-then-network is the default shape of every provider call, so repeated identical requests inside the time-to-live cost no quota. The tile category defaults to a 30-day time-to-live, the imagery terms ceiling.
  • Batch what the contracts batch: the distance matrix answers every origin-destination pair in one call; fetching matrix cells one by one multiplies your request count for the same data.

Use offline where it pays

  • The offline routing provider answers routes over a memory-mapped archive with A*; no network round trip. Compile an extract sized to the region your users drive in, not the planet: the compiler is deterministic and the archive is self-describing.
  • The offline routing decorator retries over the offline graph when the online provider fails, so a coverage-limited archive is a graceful degradation, not a failure mode. You wire it around your online provider; the SDK registers no fallback on your behalf. Its maneuver texts stay honest where the archive carries no street names.

Profile with the SDK’s own readbacks

  • Subscribe to diagnostics events at Info severity (or Debug for frame-path detail). Events stream fire-and-forget from bounded ring buffers, coordinates are scrubbed at the sink, and a slow listener can never slow the SDK.
  • Drain the backlog with the bounded flush readback from a non-frame context: the flush is synchronous and must stay out of the render path.
  • For provider failures, read latestProviderFailureDiagnostics after a suspicious session; the ring carries the contract, method, timestamp, and verbatim failure text for every failed foreign-callback provider call.
  • Measure on your target device and your real scenes. The SDK reports what it did (tile counts, frame statistics, cache terms, and the frame’s own stage spans in the browser), so a slow frame can be attributed to geometry, encoding or submission instead of guessed at.
  • In the browser, the frame never blocks on the network: missing tiles are fetched on their own tasks and the frame draws what it already holds. A page that renders on demand should listen for the canvas’s map-tile-arrived event and draw again, which is what the live demo page does.

Map concepts

This page explains the ideas every map SDK is built on: tiles, zoom levels, the coordinate system maps are drawn in, and the camera that decides what you see. The guides use these ideas without defining them, so read this page once if you have not worked with a map before, then continue with Your first map.

Positions and regions

A position is a GeographicCoordinate: latitude and longitude in decimal degrees on the WGS 84 ellipsoid. Latitude runs from -90 to 90; longitude runs from -180 to 180.

A region is a BoundingBox between a south-west and a north-east corner, each one a coordinate. A box never spans the antimeridian. If a region crosses it, encode the region as two adjacent boxes.

The examples on this page are Kotlin because that makes them concrete; the same records cross every binding, with each platform’s field naming.

import uniffi.rustic_maps.BoundingBox
import uniffi.rustic_maps.GeographicCoordinate

val capitolPark = GeographicCoordinate(38.5766, -121.4944)
val downtownSacramento = BoundingBox(
    southWest = GeographicCoordinate(38.5700, -121.5030),
    northEast = GeographicCoordinate(38.5850, -121.4850),
)

The world square

The SDK does not draw in latitude and longitude. Before anything is placed on screen, a coordinate is projected onto the Web Mercator world: a square where every position becomes two numbers in [0, 1]. The horizontal number is zero on the antimeridian and grows eastward. The vertical number is zero at the north pole and grows southward.

Only part of the ellipsoid fits in that square. The projection stops at about 85.05 degrees north and south, and latitudes beyond the cutoff clamp to the edge. The top and bottom of the world square are therefore not the poles, and a coordinate near a pole sits on the boundary rather than beyond it.

Mercator also changes scale across the map: it stretches the ground more the farther you move from the equator. At a given zoom, the ground distance covered by one screen pixel shrinks with the cosine of the center latitude. The camera answers that distance for a scale bar through groundMetersPerScreenPixel.

Tiles

A tile is one payload at one zoom level. Its address is a TileKey: a column, a row counted from the north, and the zoom level. This is the web-mercator XYZ scheme. At zoom 0 the whole world is one tile, and each level doubles the columns and rows, so zoom level z has 2^z columns and 2^z rows. A coordinate’s address is the tile cell that contains its position in the world square.

A raster tile is a pre-rendered image. The contract carries one as RasterTileData: the tile address, an image format (Png or Jpeg), a tile resolution, and the encoded bytes. Standard is the plain form; Retina is the @2x form with twice the texels per edge for the same logical tile span, which is what a high-density screen wants.

A vector tile is different: it carries geometry and style rather than pixels. Its vertices are stored in the tile’s own space, with x to the right and y down inside the tile. The SDK converts each vertex through the tile’s web-mercator address into a GeographicCoordinate, so vector geometry and your own overlays share one coordinate space.

Either kind of tile is addressed, fetched and reused by the same key. When the view moves, the SDK asks for the tiles the view now covers and keeps the ones it already holds.

Zoom is continuous

A camera’s zoom is a number, not a whole tile level, and each unit doubles the on-screen scale. The camera accepts zoom 0 through 24.

The tile grid only changes at whole levels, so a smooth pinch gesture passes through fractional zoom while the SDK picks the nearest whole level for a tile fetch: tileZoomLevel. To ask which tiles the view covers, use visibleTileKeys, which lists every tile at a chosen level whose area intersects the visible ground, sorted row-major from the north. A rotated or tilted view can cover tiles you would not guess from the center alone, so read the list instead of computing a rectangle.

The camera

A MapCamera is an anchored pose made of four values.

ValueWhat it means
centerThe ground point rendered at the viewport center
zoom_levelScale; continuous, and each unit doubles the on-screen scale
bearing_degreesThe compass direction the top of the viewport points to, clockwise from north, wrapped into [0, 360)
pitch_degreesTilt from straight down; zero is top-down, and the maximum is 75 degrees so the view keeps ground in it

The camera carries no setters. A new view is a new camera; the getters read the pose back as it was built.

import uniffi.rustic_maps.GeographicCoordinate
import uniffi.rustic_maps.MapCamera

val camera = MapCamera(
    center = GeographicCoordinate(38.5766, -121.4944),
    zoomLevel = 12.0,
    bearingDegrees = 0.0,
    pitchDegrees = 0.0,
)

A camera is also the projection and the tile selector, not only a description. projectToScreen maps a coordinate to viewport pixels and screenToGroundCoordinate maps a pixel back to the ground, returning nothing when the pixel’s ray misses the ground. Both use the camera’s pose, so your own UI and the renderer place things on the same pixel without duplicating the math.

The second constructor, fitBounds, builds a camera that frames a bounding box: top-down and north-up, zoomed to the largest level that keeps the whole box inside the inset region you pass. Insets are the pixels your own UI keeps clear, such as a route card, a sheet panel or an attribution label, so the box never hides beneath them.

Overlays are geography

Everything drawn on top of the tiles is an overlay: a MapOverlay record with a kind and the payload that kind reads.

KindPayload
RoutePolylinecoordinates, a polyline in traversal order
FilledPolygonringCoordinates, one outer ring in traversal order
PointMarkers and PointPinspointMarkerPositions, one coordinate per marker
TrafficFlowtrafficFlowSegments, traffic records whose shapeCoordinates are coordinates

The payload is the point: a list of GeographicCoordinate. An overlay is not a picture and not a set of screen pixels. It is geography plus a style (a color, a line width, a marker radius), and the SDK projects it through the same camera as the tiles in every frame.

That shared space is why an overlay needs no conversion work from your application. A calculated route carries its geometry as coordinates on its steps; flatten those shapes into one list and a RoutePolyline draws over the roads. A place returned by search carries a coordinate; put it in pointMarkerPositions and the marker sits on that place. Panning, zooming, rotating and tilting keep the two layers aligned because every frame re-projects the same geographic inputs.

A frame in order

A frame is one pass through the same few steps:

  1. You choose a MapCamera pose.
  2. The camera lists the tiles the view covers and maps every overlay coordinate into the viewport.
  3. The SDK fetches the missing tiles, draws them, then draws the overlays through the same camera.
  4. A new pose repeats the pass; the coordinate space never changes.

Once those steps are clear, the tutorials are applications of them. Start with Your first map, then continue to Search and routing, Turn-by-turn navigation and Offline maps.

How it works

The SDK is one Rust core behind a single generated interface. This page explains the concepts that interface exposes, so the tutorials’ calls read as applications of them rather than recipes to copy. Every concept below is part of the FFI contract.

Coordinates and the camera

A position is a GeographicCoordinate: latitude and longitude in decimal degrees on the WGS 84 ellipsoid. A region is a BoundingBox between a south-west and a north-east corner, and a box never spans the antimeridian.

The camera is a MapCamera value: an anchored pose of center, zoom, bearing, and pitch. The ground point under the center sits at the viewport center, zoom and pitch are clamped, and bearing wraps into the range from 0 up to but not including 360 degrees.

Camera attributeWhat it means
centerThe coordinate anchored at the viewport center
zoom_levelScale; a continuous level, not necessarily a whole number
bearing_degreesRotation clockwise from north
pitch_degreesTilt from top-down (0) toward the horizon

A camera carries no setters. A new pose is a new constructor call, and the attribute getters read the state back as it was built. The second constructor, fit_bounds, frames a bounding box inside the inset region you give it: top-down, north-up, zoomed to the largest level that keeps the whole box visible, and anchored on the inset region’s center. Insets are the pixels your own overlays keep clear, so route cards and attribution never hide the destination.

The camera answers screen mappings without drawing. projectToScreen and screenToGroundCoordinate convert between a coordinate and viewport pixels, visibleTileKeys lists the tiles the view covers, and groundMetersPerScreenPixel sizes a scale bar.

Zoom levels and tiles

A tile is one payload at a fixed zoom, addressed by a TileKey: a column, a row counted from the north, and the zoom level. The addressing is the web-mercator XYZ scheme. At zoom 0 the world is one tile, and each level doubles the columns and rows.

The camera’s zoom is continuous, so it answers two different questions. tileZoomLevel gives the nearest whole level a tile fetch should use. visibleTileKeys gives every tile at a chosen level that intersects the visible ground, sorted row-major from the north.

A raster tile is a pre-rendered image. The contract carries it as RasterTileData with its encoded bytes, an image format (PNG or JPEG), and a resolution: Standard, or Retina for the doubled-texel @2x form. A vector tile carries geometry and style separately from the pixels and is rendered on the device. The shipped renderer draws raster imagery, and vector rendering is a later path.

Threading and lifecycle

The SDK has no render loop of its own: you decide when a frame is drawn, which is what lets a map sit still without burning battery.

  • Async calls (search, forwardGeocode, calculateRoute, tile fetches) suspend and resume on the platform’s own async runtime — Kotlin coroutines, Swift concurrency, JavaScript promises. They are safe to call from the main thread.
  • Navigation callbacks are delivered in registration order on the runtime that produced the location update. Do no blocking work in them; hand results to your UI layer.
  • Drawing is single-flight: one draw may be in flight per surface, and a second call while it runs reports RenderingSurfaceUnavailable. A render pump should skip a frame when isFrameSettled reports nothing changed.
  • Surface lifecycle is attach → resize → draw… → detach. Attach before the surface exists throws; detach before the platform view goes away. Re-attach after a credential is applied (a keyless start cannot draw provider imagery).

The provider registry

Provider-backed capability reaches you through MapSdk, an object with no providers at construction. You register implementations, then call the contract methods: forward and reverse geocoding, routing, the distance matrix, place search, traffic incidents, traffic flow, and raster tiles. Every call resolves through a registry. A call into a contract with no registration throws ProviderNotConfigured naming the contract, and the elevation contract has no registered implementation today.

There are two registration paths:

  • setProviderCredential installs the whole map-platform provider set from one API key, with the SDK defaults for rate limiting and retries.
  • register_geocoding_provider_from_foreign and register_raster_tile_provider_from_foreign install an implementation your own Kotlin or Swift code supplies through the GeocodingProvider and RasterTileProvider interfaces.

Registration is per object, and re-registration replaces every slot. A second MapSdk object needs its own registration.

Capability comes from whichever provider you register. These ship today:

The keyless vector and raster sources back the live demo’s base map; they carry their own attribution and usage terms, which the SDK surfaces alongside the imagery. Elevation is part of the contract and has no implementation, so call it only after you register a provider for it — otherwise the call throws ProviderNotConfigured naming the capability.

Adding a provider is a provider implementation plus a registration; nothing in your application code names a vendor beyond the key you pass.

The cache path

set_provider_credential_with_tile_cache installs the same provider set and wraps the raster-tile contract in a disk response cache: a SQLite database at a path you own, under an absolute byte budget. A cache hit answers from disk, and a cache miss goes to the network and back-fills.

Cached tile responses are retained under the tiles category’s time-to-live, 30 calendar days by default. That default is also the imagery provider’s terms ceiling. set_raster_tile_cache_time_to_live tunes the value, an override above the ceiling is accepted and clamped, and raster_tile_cache_terms reads back three values: the effective time-to-live, the provider’s declared ceiling, and the category default. The byte budget is fixed when the store opens, so retuning it means registering again, and a fresh registration starts at the category default.

Raster imagery is the layer the cache holds. Offline routing is a separate layer with its own archive (see below).

One contract, four platforms

One UniFFI UDL file defines the surface, and it is the single source of truth: the Kotlin, Swift, React Native and WebAssembly bindings are all generated from it. The contract is pre-1.0, so a release may rename or replace members while the API settles; each change ships with its migration note in the changelog.

Navigation state

Routing returns a Route: legs between consecutive waypoints, and steps inside each leg, each carrying its distance, duration, maneuver label, and instruction texts. Navigation consumes that value rather than extending it.

Navigator holds a trip. You start one with start_navigation(route, unit_system, step_advance_policy, deviation_policy) and deliver one position fix at a time with update_location. The controller publishes four topics: banner instructions, speech triggers, deviation status, and phase changes. A subscription is cancelled explicitly through its handle.

A trip has three phases: Navigating, OffRoute, and Arrived. Rerouting is not a phase; a trip moves between navigating and off route until it arrives. Deviation has two grades:

  • FullyOffRoute freezes progress until a graded fix recovers or a reroute replaces the route.
  • OffStepOnRoute means the fix is off the current step but still on a later part of the route, and the trip keeps navigating.

Guidance uses two policies you choose at trip start. StepAdvancePolicy decides when the trip moves to the next step, and DeviationPolicy decides when a fix counts as off route. A fix without a reported accuracy never advances a step and is never judged for deviation, so a simulated source must carry accuracy like a real one.

Instruction text has two channels. The banner channel carries the display text, and the speech channel carries the text-to-speech text through SpeechInstruction. The SDK decides when a line is newsworthy and supplies the text verbatim. Your application owns playback and synthesis, and utterance_id is a stable identity for deduplication.

A deviation asks for a replacement route through a small gate. begin_reroute_calculation answers true when the request passes the in-flight, cooldown, and movement checks, apply_reroute applies the replacement, and cancel_reroute_calculation abandons it. The trip state’s is_calculating_new_route reports the in-flight fact.

Offline routing

Offline routing answers from a compiled archive rather than a network round trip. The archive is built from an OpenStreetMap extract and is self-describing. It answers routes with an A* search over a memory-mapped graph and honors recorded turn restrictions. Maneuver text derives from the geometry where the extract carries no street names.

The archive’s direct route call joins the native contract in a later release. Today it answers the WebAssembly surface’s offline route seam, and the offline routing decorator wraps your online provider when you choose to fall back; one compiled archive serves every target.

Resolve a query into places

The provider surface runs on Kotlin coroutines: every MapSdk call you see here is a suspend fun. Run it from a coroutine scope. The plan sheet’s two fields each resolve the text a user typed:

val originPlace: Place = mapSdk.forwardGeocode(originSearchQuery).firstOrNull()
    ?: return null
val destinationPlace: Place = mapSdk.forwardGeocode(destinationSearchQuery).firstOrNull()
    ?: return null

forwardGeocode answers every candidate the provider resolved, most likely first; suggest answers fast completion candidates while the user types, and search answers full results for a settled query. Both search calls take an optional BoundingBox boundary that restricts the search.

Plan the route

calculateRoute takes the ordered waypoints and the routing options. This is the shared demo request on every platform: exactly two waypoints, the pedestrian option set the reference applications plan every demo route with, fastest, metric, no avoids.

val routeOptions = RouteOptions(
    transportationMode = TransportationMode.PEDESTRIAN,
    routeStrategy = RouteStrategy.FASTEST,
    unitSystem = UnitSystem.METRIC,
    avoidOptions = AvoidOptions(
        tollRoads = false,
        limitedAccessHighways = false,
        ferries = false,
        unpavedRoads = false,

Scope note

The WebAssembly seam ships the camera, rendering, overlays, the route simulator and offline routing; it does not ship the navigation controller. There is no navigationController or listener, no trip state, no banner, speech, deviation, phase dispatch or rerouting, and no Navigator on this surface. What the browser does carry is RouteSimulator: an immutable walker over the planned route’s own geometry that produces the position fixes the native tabs feed into their controller. It is not a guidance policy, so it carries no instruction text and no phase.

Simulate the trip and follow it

Create the simulator once from the planned route and a pace, then ask it for a fix at an elapsed time. The fix carries a coordinate, the courseHeadingDegrees, the travelled and remaining meters, and isArrived. import { RouteSimulator } from './web/map_web_bindings.js';

/** @type {any} */
const plannedRoute = route;
const routeOverlay = {
  kind: 'routePolyline',
  coordinates: plannedRoute.legs.flatMap(
    (leg) => leg.steps.flatMap((step) => step.shape),
  ),
  color: { red: 0.16, green: 0.47, blue: 1.0, alpha: 0.95 },
  widthPixels: 6.0,
};

const ROUTE_SIMULATOR_SPEED_MULTIPLIER = 20.0;
const FOLLOW_ZOOM_LEVEL = 17.0;
const FOLLOW_PITCH_DEGREES = 45.0;
const fieldOfViewDegrees = 60.0;
const elapsedSeconds = 0.0;

const routeSimulator = new RouteSimulator(plannedRoute, {
  speedMetersPerSecond: ROUTE_SIMULATOR_SPEED_METERS_PER_SECOND,
  speedMultiplier: ROUTE_SIMULATOR_SPEED_MULTIPLIER,
});
const fix = routeSimulator.fixAtElapsedSeconds(elapsedSeconds);

mapView.setOverlays([routeOverlay]);
mapView.setLocationIndicator(
  { coordinate: fix.coordinate, courseHeadingDegrees: fix.courseHeadingDegrees },
  { visualKind: 'guidedCourseArrow' },

  new MapCamera(
    fix.coordinate.latitude,
    fix.coordinate.longitude,
    FOLLOW_ZOOM_LEVEL,
    fix.courseHeadingDegrees ?? 0.0,
    FOLLOW_PITCH_DEGREES,
  ),
  fieldOfViewDegrees,
);

Offline maps

Keep map imagery and routing working without a network. The SDK’s offline story has two layers: a disk response cache that holds raster tile imagery under your byte budget, and a compiled routing archive that answers routes with no network round trip at all.

Versions and support

This page states how versions are chosen, what a released version line receives, and how changes reach it. The workspace version is 0.1.0, and the first stable release is still being prepared; the Downloads page lists the artifacts when it lands. Version numbering

Versions follow semantic versioning as MAJOR.MINOR.PATCH. One workspace version is the single source of truth: the Android, iOS, React Native, and WebAssembly packages are all stamped from it at release time, so one version string identifies one core.

The SDK is pre-1.0. The FFI contract is addition-only, so existing members keep their signature and meaning across an upgrade. Packaging can still change while the release is 0.x: an artifact-set change or a renamed target bumps the minor version, and a pre-1.0 minor may break a build even when the contract did not change. Treat a minor upgrade as one to test, not one to assume.

Pin exact versions

Release archives are immutable and carry the version in the file name, for example rustic-maps-sdk-android-vX.Y.Z.aar. Keep the exact version you validated against and upgrade deliberately. The version you pin also names the notices file that accompanies it.

Imagery and caching

  • All seven MapQuest provider APIs are implemented against recorded provider responses. They cover routes with strategies and multiple legs, the route matrix, forward and reverse geocoding, search prediction, traffic incidents, traffic-flow congestion polylines, and raster tiles in standard and retina resolutions.
  • A SQLite-backed response cache holds provider responses under an absolute byte budget, a share of free disk space, or both. It provides per-category time-to-live, LRU eviction, and cache-then-network behavior around every provider contract. Tile imagery caches heavily by default: 30 calendar days, the common maximum under imagery-provider terms. Each provider contract declares its own caching terms, so an integrator tunes the cache knowingly per provider (setRasterTileCacheTimeToLive, read back through rasterTileCacheTerms). Values above a provider’s declared ceiling stay compliance-clamped.

Rendering

  • The project maintains its own minimal wgpu raster renderer. It implements web-mercator projection with exact frustum tile listing (Sutherland–Hodgman over the six frustum planes, with antimeridian world-copy handling), an anchored camera with fit-bounds and insets-aware framing and a flyTo-style hyperbolic arc, a byte-bounded GPU texture cache, and a tile scheduler with per-frame dedup, parent fallback, and a fetch budget. Route, polygon, marker, and traffic overlay layers sit on top of the tiles, and the renderer owns the location indicator (a tracking dot with accuracy ring, or a guided course arrow).
  • The same renderer scene draws headless (for deterministic tests), into live Android/iOS surfaces, and in the browser through WebGPU. One WGSL/vertex pattern is byte-identical across the wasm and native paths.

Offline routing

  • The offline routing pipeline is in place. A deterministic compiler turns an OpenStreetMap PBF extract into a self-describing routing archive (nodes, a per-edge pack with road class, speed, and access columns, and turn restrictions). A memory-mapped reader validates the container’s alignment invariants. An offline routing provider answers routes with A* over the graph. It honors recorded turn restrictions and derives turn maneuvers (left/right/slight/sharp/U-turn) from the geometry’s bearing change; its texts stay honest where the archive carries no street names. A routing decorator retries over the offline graph when the primary (online) provider fails.
  • The same graph runs in the browser: the wasm surface loads the compiled archive from in-memory bytes and answers the same route-shaped objects and typed refusals, so offline routing behavior is regression-tested in a plain browser run.

Navigation

  • Navigation state is deterministic: the same sequence of location updates always produces the same phase, step and instruction. It implements Ferrostar-pattern step-advance conditions (manual, eager distance-to-end, delayed current-step, Or/And combinators, and the fresh-instance reset contract), deviation detection with accuracy-aware allowances, and provider-verbatim instruction composition (banner and speech text; nothing rewritten).
  • Deviation is graded. A fully-off-route state freezes the guidance and asks for a reroute; an off-step-but-on-route state keeps counting down and reconciles to the projected step. Speed runs advance through many steps per fix, and the advance is bounded and stack-safety-tested. The fully-off-route instruction text suppresses the countdown honestly rather than projecting it from a stale anchor.
  • The SDK owns speech triggering: it publishes a speech-instruction topic over documented distance bands. Platforms voice that topic and keep their own pacing and focus policies.

Camera and gestures

  • The gesture-input camera seam keeps the camera math in the SDK. Platform recognizers forward plain deltas, and the SDK applies them: pan by screen pixels, focal-point zoom and rotation with an exact hold-the-focal-point correction, clamped through the camera’s own ranges.

Bindings and platforms

  • UniFFI drives the generated Kotlin/Swift bindings and the React Native bindings from a frozen, addition-only UDL contract. The wasm surface is a hand-reviewed TypeScript mirror regression-checked against the same UDL. Callback providers (geocoding, tiles) and a navigation controller with per-topic subscriptions cross the foreign callbacks seam. Exported async methods run on an SDK-owned runtime, so your application’s event loop never blocks on a provider call.
  • Reference applications on Android (Compose), iOS (SwiftUI), and the browser reference app implement one shared design language. Each reaches search → route → simulated turn-by-turn with speech through a bottom-sheet home, a five-control cluster (zoom, scale bar, my-location, 2D/3D, compass), a follow camera, an offline tile-cache card, and a readiness-chip diagnostics readout. The web surface reaches reference-app parity with the native demos.

Vector tiles

  • A Mapbox Vector Tile v2.1 decoder turns fetched tiles into layers, features and geometries with typed errors on every malformed path. A data-only style pass maps decoded layers into the renderer’s fill, polyline and point overlays (an optional one-attribute text filter is supported). The OpenStreetMap US Sourdough tileset is the first vector-tile provider, with attribution and terms carried by its source descriptor.

FAQ and troubleshooting

The caveats integrators actually hit, collected from the code and the reference applications. The performance page carries the tuning guidance; this page carries what to check when something misbehaves.

Web GPU and browser support

The browser surface needs WebGPU; there is no WebGL fallback. The wasm canvas fails its initialize() when no WebGPU adapter supports the canvas or the device request fails, and then reports the error verbatim. Your page should catch it and present the degradation message: name the missing capability (navigator.gpu is the feature test), and link MDN’s compatibility table. Version floor: Chromium-based browsers since 113 (flag-free), Safari since 26, Firefox since 141 (desktop first), and always a secure context (HTTPS or localhost). No user-agent sniffing.

The map stays empty on an Android emulator after rendering starts. Android emulators render through SwiftShader over ANGLE, a software graphics stack; that is an expected emulator fact, not a failure. On the emulator the GPU surface negotiates through the GL backend: set WGPU_BACKEND=gl in your build’s environment as the reference application does. On real hardware the line is redundant and harmless.

API key and provider failures

How do I supply the provider key? Read it at runtime — from your app’s own secure configuration or a settings surface — and pass it to the provider registration call. Never commit it or bake it into an app bundle. The reference applications ship keyless and take the key from their settings view, with opt-in secure-device storage; their UI suites inject one through a launch intent/environment for automated runs.

The SDK throws immediately at registration when the key is refused. setProviderCredential answers with the provider’s verbatim detail; surface it, do not catch-and-continue.

Calls throw RateLimitExhausted. The shared token-bucket limiter is exhausted. The bucket refills on its own schedule, so retry after the next refill instead of surfacing an error; cache-then-network behavior around every provider contract keeps repeated identical requests free of quota.

Calls throw ProviderNotConfigured naming a contract. That contract has no registered implementation on the MapSdk object. Registration is per object: re-registration replaces every slot, so a second setProviderCredential call is safe, but a second MapSdk() needs its own registration.

Elevation throws ProviderNotConfigured even with the provider set installed. The elevation contract has no provider implementation yet; its calls keep refusing until one lands.

Offline behavior

Tiles render but routes fail offline, or the other way around. The two offline layers are separate. Tile imagery answers from the disk cache you registered (setProviderCredentialWithTileCache), within its byte budget and time-to-live. Routing answers from a compiled routing archive, independent of the imagery cache; check that the archive you compiled covers the queried region (see the next item).

A route refusal comes back offline. The offline graph refuses, rather than guessing, in three cases: bytes that fail the archive validation, a coordinate outside every node’s snap tolerance, and a request pair the graph cannot connect. Check the archive covers the areas you query; a small extract is the usual cause.

Maneuver text has no street names offline. The archived graph carries no street-name strings, so the offline maneuver texts name the turn direction and the distance and stay honest about what they do not know. Named maneuver text arrives from the online provider.

Tile cache

A tuned time-to-live does not stick after re-registration. Registration is a reset: a freshly registered cache starts again at the category default, so re-apply the override after registering. The rasterTileCacheTerms readback shows the effective value.

A large requested time-to-live is accepted but the cache still expires entries. The installed provider’s declared terms ceiling (compliance-bound at 30 calendar days for the imagery) clamps what the cache retains. Read the ceiling from rasterTileCacheTerms and display it next to the effective value.

Setting a zero time-to-live throws. A zero value would expire every entry on capture; the refusal names the mistake.

API reference (rustdoc)

The reference documentation for every module in the SDK ships at the api/ path of this site: start at geospatial-types, the record and math layer every other module builds on.

It is generated from the source of the current release, so it always describes the version of the SDK this site documents. Start there for a member’s exact signature, return record and error cases; the guides link into it wherever a call needs more context.

The FFI contract

The SDK’s binding surface is one UniFFI UDL contract, map_native_core.udl, published verbatim below and as a plain-text download. This file is the single source of truth: the Kotlin, Swift, React Native and WebAssembly bindings are generated from it, so every platform exposes the same names and records.

The contract is pre-1.0, so it grows rather than churns: a release adds members and records, and an existing member keeps its signature and its meaning. The changelog records what each release adds, and the API reference documents the same surface as generated reference documentation.

The listing below is the contract exactly as the bindings are generated from it.

/// Anchored map camera (geographic center, zoom, bearing, pitch) mirroring
/// the native `map-rendering` camera. The ground point under the center
/// always sits at the viewport center; zoom and pitch are clamped and the
/// bearing wraps into `[0, 360)` exactly like the native constructor.
interface MapCamera {
    [Throws=SdkError]
    constructor(GeographicCoordinate center, double zoom_level, double bearing_degrees, double pitch_degrees);

    /// Builds the camera that frames a bounding box inside the viewport's
    /// inset region: top-down and north-up by construction (pitch and bearing
    /// zero), zoomed to the largest level keeping the whole box inside the
    /// inset area and clamped to `maximum_zoom_level`; the center is anchored
    /// on the inset region's center. Throws when the insets or the maximum
    /// zoom are not finite usable values, when the insets are negative or
    /// leave no inset area, or when the box spans no positive world area.
    [Throws=SdkError, Name=fit_bounds]
    constructor(BoundingBox bounding_box, ViewportSize viewport, EdgeInsets edge_insets, double maximum_zoom_level);

    /// Projects a coordinate to viewport pixels (origin top-left, y down).
    /// Returns null when the point lies behind the camera.
    [Throws=SdkError]
    ScreenPoint? project_to_screen(GeographicCoordinate coordinate, ViewportSize viewport, double field_of_view_degrees);

    /// Unprojects a viewport pixel back onto the ground plane. Returns null
    /// when the ray misses the ground (typically below the horizon at steep
    /// pitch).
    [Throws=SdkError]
    GeographicCoordinate? screen_to_ground_coordinate(ScreenPoint screen_point, ViewportSize viewport, double field_of_view_degrees);

    /// Every tile at `tile_zoom_level` whose area intersects the visible
    /// ground, sorted row-major from the north.
    [Throws=SdkError]
    sequence<TileKey> visible_tile_keys(ViewportSize viewport, double field_of_view_degrees, u8 tile_zoom_level);

    /// Nearest whole zoom level a tile fetch should use for this camera.
    u8 tile_zoom_level();

    /// Pans by a pointer travel of `delta_x_pixels` x `delta_y_pixels`
    /// (screen pixels, x right / y down): the ground point the pointer just
    /// moved over becomes the new camera center, so map content tracks the
    /// pointer exactly. Answers the camera unchanged when the delta's ground
    /// ray misses the plane (above the horizon at steep pitch). Throws when
    /// the viewport extent is not positive. The gesture-input seam every
    /// platform's recognizer feeds (docs/ReferenceAppUX.md §5.1): recognition
    /// stays platform-side, the camera math is the SDK's.
    [Throws=SdkError]
    MapCamera pan_by_screen_pixels(double delta_x_pixels, double delta_y_pixels, ViewportSize viewport, double field_of_view_degrees);

    /// Zooms by `delta_zoom_levels` (levels; positive zooms in) keeping the
    /// world point under `focal_point` fixed under it. Answers the zoom
    /// without the focal correction when the focal ray misses the ground
    /// plane (above the horizon at steep pitch). Zoom clamps to the camera's
    /// own level range before the focal correction applies, so a clamped
    /// zoom still holds the focal point. Throws when the viewport extent is
    /// not positive.
    [Throws=SdkError]
    MapCamera zoom_by_levels_around_screen_point(double delta_zoom_levels, ScreenPoint focal_point, ViewportSize viewport, double field_of_view_degrees);

    /// Rotates the bearing by `delta_bearing_degrees` (degrees clockwise,
    /// wrapping into `[0, 360)`) keeping the world point under `focal_point`
    /// fixed under it. Answers the rotation without the focal correction
    /// when the focal ray misses the ground plane — rotating about the focal
    /// pixel, the touch-point turn a two-finger gesture implies. Throws when
    /// the viewport extent is not positive.
    [Throws=SdkError]
    MapCamera rotate_by_degrees_around_screen_point(double delta_bearing_degrees, ScreenPoint focal_point, ViewportSize viewport, double field_of_view_degrees);

    /// Reads the camera's attribute state back verbatim as it was built
    /// (round-9 asks). The getters make `fit_bounds`' chosen framing
    /// readable: the zoom level the constructor actually fitted, its
    /// anchored center, and the constructed bearing and pitch read back
    /// through these members. Read-only: the camera carries no setters —
    /// a new camera pose is a new constructor call. The UniFFI 0.32 UDL
    /// parser supports no `[Attribute]` member syntax, so the getters are
    /// plain methods.
    GeographicCoordinate center();
    double zoom_level();
    double bearing_degrees();
    double pitch_degrees();

    /// Ground meters represented by one screen pixel at the camera's center
    /// (round 10, the scale bar's helper): the equatorial ground meters per
    /// pixel at the camera's zoom level times the cosine of the center
    /// latitude, so the answer shrinks toward the poles exactly like the
    /// projected ground. At any nonzero pitch this is an approximation valid
    /// at the viewport's center column: the helper is flat-centered (no
    /// unprojection fold of pitch into the answer) and documents that
    /// honestly; the platform scale bars fit the meter magnitude through a
    /// labeled ladder rather than reading a bare value.
    [Throws=SdkError]
    double ground_meters_per_screen_pixel(ViewportSize viewport, double field_of_view_degrees);
};

/// Async provider entry point of the SDK: resolves every call of the
/// implemented `geospatial-traits` contracts through the `map-core`

    [Async, Throws=SdkError]

        u32 tile_y,
        u8 zoom_level,
        RasterImageFormat image_format,
        RasterTileResolution tile_resolution
    );

    /// Rounds 8 (surface slice): registers the seven native MapQuest
    /// provider implementations (geocoding, routing, distance matrix, place
    /// search, traffic incidents, traffic flow, raster tiles) onto the
    /// registry, constructed from the MapQuest consumer key with the SDK
    /// defaults for base URL, rate limiting and retries — the foreign
    /// mirror of the native integrator's `register_*` calls, so foreign
    /// code installs the whole provider set with one call and an API key.
    /// Re-registration replaces every slot. Elevation stays unregistered:
    /// the elevation contract has no MapQuest provider, and elevation calls
    /// keep throwing `ProviderNotConfigured`.
    [Throws=SdkError]
    void set_provider_credential(string credential);

    /// Round 9 (offline-maps demo): registers the seven native MapQuest
    /// provider implementations from one key exactly as
    /// `set_provider_credential`, wrapping the raster-tile contract in
    /// the disk response cache opened (or created) as a SQLite database at
    /// `tile_cache_database_path` under an absolute byte budget of
    /// `tile_cache_absolute_maximum_bytes`. Cached tile responses follow the
    /// tiles category's time-to-live (thirty days by default — the
    /// imagery-provider terms ceiling, PRD §6.7); a cache miss goes to the
    /// network and back-fills the cache, so pre-warmed tiles keep rendering
    /// whenever the network is unavailable. The path must be non-empty and
    /// the byte budget positive; a cache open or quota failure throws with
    /// its verbatim detail. Re-registration replaces the slots (including
    /// the cached raster-tile slot).
    [Throws=SdkError]

    /// Registers a provider-neutral base map (M9's native base-map switch):
    /// any web-mercator XYZ raster tileset that publishes a `{z}/{x}/{y}`
    /// URL template, served by the SDK itself with no provider crate
    /// involved — the mirror of the native integrator's
    /// `register_raster_tile_provider` call for foreign code, so an
    /// application can offer a second base map without a new binding.
    ///
    /// The registration replaces the raster-tile contract slot only; every
    /// other provider slot keeps serving. It also drops any installed tile
    /// cache, because the cache's terms belong to the provider that
    /// installed it — a later `raster_tile_cache_terms` then throws the
    /// honest `TileCache` not-configured error rather than reporting
    /// another provider's ceiling. Re-registering replaces the source.
    ///
    /// A malformed template, a blank source name or an inverted zoom range
    /// throws `InvalidCoordinateInput` with a precise detail, and the slot
    /// keeps whatever it served before the refused call.
    [Throws=SdkError]
    void register_url_template_raster_tile_source(UrlTemplateRasterTileSource source);

    // --- Tile-cache settings surface (M2's remaining developer-facing
    // sub-item; addition-only). The frozen
    // `set_provider_credential_with_tile_cache` signature is untouched:
    // the byte budget stays a registration-time fact (the SQLite store's
    // quota is fixed when the store opens, so retuning it means
    // re-registering through the frozen method), while the tile time-to-live
    // is a property of the installed cache and is tuned live through the two
    // members below. A per-integration registration-time alternative (a
    // second registration method carrying the whole frozen parameter set
    // plus one optional TTL field) was rejected: it duplicates the
    // registration surface for one optional value, and the terms readback
    // below already makes the applied value inspectable, so the override
    // rides the installed cache instead. Re-registration replaces the slots
    // and the tuning: a freshly registered cache starts again at the
    // category default, and the integrator re-applies the override after
    // registering.
    //
    // Validation ruling (PRD §6.7's provider-terms-ceiling intent): a
    // requested time-to-live above the installed provider's declared ceiling
    // is ACCEPTED, and the ceiling clamps what the cache stores — the terms
    // ceiling is a compliance bound on what the cache may retain, not a
    // preference, so the SDK must never retain beyond the provider's terms
    // whatever the integrator asks for; refusing the call would instead
    // break a live integration every time the provider's terms move or the
    // integrator reads a stale ceiling. The ceiling and the effective
    // (clamped) time-to-live are both in the `raster_tile_cache_terms`
    // readback, so an integrator sees exactly what went into force. A zero
    // time-to-live is refused: it would expire every entry on capture
    // (a cache that stores nothing), which is almost certainly a unit
    // mistake in the caller.

    /// Tile-cache settings surface (M2): overrides the raster-tile cache's
    /// time-to-live on the installed cache, in seconds. The tile cache must
    /// be installed (registered through
    /// `set_provider_credential_with_tile_cache`); otherwise this throws
    /// `ProviderNotConfigured` naming `TileCache` as the unconfigured
    /// backing store. A zero value throws `InvalidCoordinateInput` with a
    /// precise detail (a zero time-to-live expires every entry on capture,
    /// storing nothing). A value above the installed provider's declared
    /// terms ceiling is accepted with the ceiling clamping what the cache
    /// stores (see the ruling above); `raster_tile_cache_terms` reports the
    /// effective value.
    [Throws=SdkError]
    void set_raster_tile_cache_time_to_live(u64 time_to_live_seconds);

    /// Tile-cache settings surface (M2): reads the effective raster-tile
    /// caching terms so a developer can display them (a settings page, or
    /// the offline-maps demo's cache panel). Reports the time-to-live
    /// currently in force on the installed cache (the category default
    /// thirty days, or the last override this object accepted, clamped when
    /// it exceeded the provider's terms ceiling), the installed provider's
    /// declared terms ceiling (null when the provider declares no ceiling,
    /// in which case the requested time-to-live applies verbatim), and the
    /// cache category's default time-to-live. The tile cache must be
    /// installed (registered through
    /// `set_provider_credential_with_tile_cache`); otherwise this
    /// throws `ProviderNotConfigured` naming `TileCache` as the
    /// unconfigured backing store. Read-only: the readback never mutates
    /// the cache.
    [Throws=SdkError]
    TileCacheTerms raster_tile_cache_terms();

    /// Round-10 diagnostics (capability 6): subscribes the foreign listener
    /// to the SDK's structured internal log events streamed fire-and-forget
    /// from the crates' bounded ring buffers. Only events at
    /// `minimum_severity` or above are delivered, and coordinates within
    /// event messages are always rounded at the sink (never the API key).
    /// The listener callbacks run on the threads that produce the events and
    /// must never block on the caller; re-subscribing an already subscribed
    /// listener replaces its severity gate.
    void subscribe_to_diagnostic_events(SdkDiagnosticEventListener listener, SdkLogSeverity minimum_severity);

    /// Round-10 diagnostics: drains up to `maximum_count` of the most recent
    /// ring events at `minimum_severity` or above through the listener's
    /// `on_diagnostic_event` (oldest first) and returns how many were
    /// delivered, then (like Organic Maps' and OsmAnd's opt-in capture)
    /// nothing is removed from the ring, so a later flush can redeliver. The
    /// flush is bounded and synchronous: a listener must not block on it.
    u32 flush_recent_diagnostic_events(SdkDiagnosticEventListener listener, SdkLogSeverity minimum_severity, u32 maximum_count);

    /// Round-12 provider-failure diagnostic seam (addition-only): reads the
    /// retained diagnostics of every failed foreign-callback provider call
    /// this object has served — the failures foreign implementations of the
    /// `[Trait, WithForeign]` provider contracts threw, both the typed ones
    /// (the foreign code threw one of the contract's `SdkError` variants) and
    /// the unclassified ones (the foreign code failed without a mapped
    /// error). Returns the ring's retained entries oldest first, in
    /// recency-bounded order: the ring keeps the last
    /// `PROVIDER_FAILURE_DIAGNOSTIC_RING_CAPACITY` failures and drops the
    /// oldest beyond it, and reading is non-destructive. Read-only: the
    /// readback never records anything and never clears the ring. See
    /// `ProviderFailureDiagnostic` for what an entry carries; the frozen
    /// `SdkError` variants are untouched — failures still surface typed at
    /// the throwing call, and this seam only adds where they can be
    /// classified after the fact.
    sequence<ProviderFailureDiagnostic> latest_provider_failure_diagnostics();
};

// Navigation wiring (M6). The `[Trait, WithForeign]`
// `NavigationListener` is the listener contract foreign code
// implements; its subscriptions register on the `Navigator`
// object, which drives the native `map-navigation` reducer session and its
// per-topic broadcaster. The records and enums below mirror the
// `map-navigation` plain-data types field-for-field; the step-advance and
// deviation policies stand in for the native decision objects (trait
// objects), which cannot cross the FFI, as tagged records. Payload-carrying
// native enums mirror as a kind enum plus nullable fields; the instruction
// payload mirrors without the native active maneuver's lane-guidance list,
// which stays native until the frozen route records carry lane guidance.
// ---------------------------------------------------------------------------

/// State-listener contract implemented by foreign code and subscribed on
/// `Navigator` through the `subscribe_to_*` methods; each
/// registered subscription delivers only its own topic.
[Trait, WithForeign]
interface NavigationListener {
    /// Receives the composed instruction payload of every dispatched state
    /// change (the instructions topic).
    void on_navigation_instruction(NavigationInstruction instruction);

    /// Receives a deviation-status stream update (the deviation topic):
    /// off-route on entry and on every recorded measurement update while the
    /// deviation persists, on-route when it clears.
    void on_deviation_status_change(DeviationStatusChange deviation_status_change);

    /// Receives one phase transition per dispatched trip-state transition
    /// (the phase topic).
    void on_navigation_phase_change(NavigationPhaseChange navigation_phase_change);

    /// Round 10 (speech pacing, OQ5's SDK-owned triggers): receives one
    /// utterance trigger when the controller's distance-band policy judges
    /// the fix newsworthy (a trigger band crossed this fix) — the verbatim
    /// composed speech text, never rewritten, so the platform owns only
    /// playback. Subscribers of the speech topic receive exactly the
    /// `subscribe_to_speech_instructions` deliveries.
    void on_speech_instruction(SpeechInstruction speech_instruction);
};

/// Handle coupled to exactly one `(topic, listener)` subscription; cancelling
/// is explicit and idempotent, dropping the handle does not unsubscribe.
interface Subscription {
    /// Cancels this subscription: the listener stops receiving the
    /// subscription's topic from the next dispatch on. Idempotent.
    void cancel();
};

/// The exported navigation controller: drives the native navigation reducer
/// session, broadcasts every state change to the registered listeners, and
/// answers read-only state and instruction queries. Obtain routes from
/// `MapSdk::calculate_route` and start a trip on them with this controller.
///
/// The listener callbacks run synchronously on the thread that drives the
/// controller call; a listener calling back into the controller while a
/// dispatch is still in flight is suppressed by the broadcaster's
/// single-in-flight guard (the state change behind it is already applied,
/// only its broadcast is skipped). The controller never holds its state lock
/// across a listener callback.
interface Navigator {
    /// Builds the controller with no active trip and no subscriptions.
    constructor();

    /// Subscribes the listener to the instructions topic: the composed
    /// instruction payload of every dispatched state change, in registration
    /// order.
    Subscription subscribe_to_navigation_instructions(NavigationListener listener);

    /// Subscribes the listener to the deviation-status topic, in registration
    /// order.
    Subscription subscribe_to_deviation_status(NavigationListener listener);

    /// Subscribes the listener to the phase-transition topic, in registration
    /// order.
    Subscription subscribe_to_phase_changes(NavigationListener listener);

    /// Begins navigating `route` with the given policies, replacing any
    /// active trip. The initial instruction payload is dispatched; no
    /// deviation or phase transitions exist yet. A route without traversable
    /// steps represents an already-arrived trip. Refuses policies with
    /// non-finite or negative thresholds, and route records carrying a step
    /// maneuver label the conversion cannot map.
    [Throws=SdkError]
    void start_navigation(Route route, UnitSystem unit_system, StepAdvancePolicy step_advance_policy, DeviationPolicy deviation_policy);

    /// Delivers one position fix to the active trip; without one the fix is
    /// dropped. Fixes without an accuracy report never trigger a step
    /// advance and are never judged by the deviation detector.
    void update_location(NavigationLocationUpdate location_update);

    /// Replaces the route of the active trip (a reroute). The replacement
    /// route must be anchored at the trip's current snapped coordinate; the
    /// step advance strategy for the new route is configured by
    /// `step_advance_policy` and the deviation policy persists. A reroute
    /// offered to an arrived trip is ignored (no transition); without an
    /// active trip the event is dropped. Round 11: an in-flight reroute
    /// calculation is settled by this call (applied or ignored alike), so
    /// the request-in-flight gate reopens after the integrator acts.
    [Throws=SdkError]
    void apply_reroute(Route route, StepAdvancePolicy step_advance_policy);

    /// Round 11 (Ferrostar B3): applies the reroute-recalculation gates to
    /// one reroute-request signal at the wall clock: true when every gate
    /// passed (no calculation in flight, outside the cooldown window, and
    /// — when both fix references exist — beyond the movement threshold)
    /// and a calculation is now in flight, readable as the trip state's
    /// `is_calculating_new_route`; false when the signal was refused. A
    /// signal without an open, still-navigable trip (no trip, or the trip
    /// has arrived) is refused before the gates are consulted. A passing
    /// caller owes a settle: the eventual `apply_reroute` (applied or
    /// ignored) or `cancel_reroute_calculation`. The initial (trip's first)
    /// attempt always passes the cooldown and movement gates.
    boolean begin_reroute_calculation();

    /// Round 11: settles an in-flight reroute calculation without applying a
    /// route (the integrator abandoned the request): the request-in-flight
    /// gate reopens. The cooldown keeps running from the calculation's
    /// beginning and the movement reference stays where it was. Idempotent.
    void cancel_reroute_calculation();

    /// Round 11: swaps the reroute-recalculation hysteresis policy in force,
    /// keeping the gate's memory as it stands. Both thresholds must be
    /// finite and non-negative (refused with `InvalidNavigationInput`
    /// otherwise, and the policy in force is then untouched).
    [Throws=SdkError]
    void configure_reroute_policy(ReroutePolicy reroute_policy);

    /// The plain state of the active trip, or null without one.
    TripNavigationState? current_trip_state();

    /// The composed turn-by-turn instruction payload of the current trip
    /// state, or null without an active trip; repeated reads of an unchanged
    /// state return the same payload.
    NavigationInstruction? current_instructions();

    /// Round 10 (speech pacing, OQ5): subscribes the listener to the
    /// speech-instruction trigger topic, in registration order. Each fix's
    /// dispatch consults the controller's named-potential policy: the trigger
    /// bands reuse the display phrase's distance bands (so a spoken "in 100
    /// meters" always matches the payload's shown phrase band), each band
    /// announces at most once per step (monotone progress), and a minimum
    /// inter-utterance spacing and repeat distance suppress chatter. The
    /// platform keeps playback (including its fallback speak-latest behavior
    /// when no listener subscribes) and synthesis stays out of scope.
    Subscription subscribe_to_speech_instructions(NavigationListener listener);

    /// Subscribes one listener to all four navigation topics — instructions,
    /// deviation status, phase changes and speech instructions — in one call
    /// and answers the composite subscription that cancels all four. Delivery
    /// semantics stay exactly the four `subscribe_to_*` calls': the listener
    /// receives each topic on its own method, in registration order, and
    /// `cancel()` removes every one of the four registrations (idempotent,
    /// like the single-topic subscription).
    Subscription add_navigation_listener(NavigationListener listener);

    /// Ends the active trip and clears the trip state: after this call
    /// `current_trip_state` and `current_instructions` answer null and
    /// location updates, reroutes and reroute-request signals are dropped
    /// until `start_navigation` begins a new trip. The speech-trigger band
    /// memory and the reroute-recalculation gate are reset with the trip
    /// (utterance identifiers stay monotonic across the stop; the configured
    /// reroute policy persists). Listener subscriptions are untouched — they
    /// are controller configuration and keep delivering the next trip's
    /// events. Stopping without an active trip is a no-op.
    void stop_navigation();
};

/// An immutable simulated trip over one planned route: distance-parameterised
/// interpolation along the route's own polyline at a caller-chosen pace. The
/// SDK carries no pacing policy and no default speed.
interface RouteSimulator {
    /// Builds the simulator over `route`. Refuses a pace whose speed or
    /// multiplier is non-finite or not strictly positive, and a route whose
    /// legs and steps carry no usable geometry.
    [Throws=SdkError]
    constructor(Route route, SimulatedTripPace pace);

    /// Total length of the route's flattened polyline, in meters.
    double total_distance_meters();

    /// Total simulated travel time at the chosen pace, in seconds.
    double total_duration_seconds();

    /// The fix at `travelled_meters` from the route start, clamped into
    /// `[0, total_distance_meters()]`.
    SimulatedTripFix fix_at_travelled_meters(double travelled_meters);

    /// The fix at `elapsed_seconds` of simulated travel, clamped into
    /// `[0, total_duration_seconds()]`.
    SimulatedTripFix fix_at_elapsed_seconds(double elapsed_seconds);
};

/// High-level phase of a trip that has already been started. Rerouting is not
/// a phase of its own: the machine flows Navigating ⇄ OffRoute within a trip
/// and Navigating → Arrived at its end.
enum NavigationPhase {
    /// Following the route's step sequence.
    "Navigating",
    /// The deviation detector judged the last graded fix off route; progress
    /// is frozen at the last on-route values until a graded fix recovers or a
    /// reroute replaces the route.
    "OffRoute",
    /// The final step has been completed; location updates no longer change
    /// the state.
    "Arrived",
};

/// Which grade of deviation a recorded deviation carries: the two-grade
/// distinction between off the current step yet still on the route line and
/// completely off the route. Only the fully-off grade freezes navigation; the
/// wrong-step grade never freezes on its own.
enum DeviationGradeKind {
    /// The fix projects onto neither the current step nor any future step of
    /// the remaining route line: the freezing grade. The trip's progress is
    /// frozen until a graded fix recovers or a reroute replaces the route.
    "FullyOffRoute",
    /// The fix is off the current step but projects onto a future step of the
    /// remaining route line: "on route, wrong step". The trip keeps
    /// navigating and counting down, and is never frozen by this grade alone.
    "OffStepOnRoute",
};

/// Plain-data description of an active deviation from the route. The grade

// Round 11 (Ferrostar adoption batch 2, mechanism adopted from `FerrostarCore`
// under its BSD 3-Clause license; the expressions are our own). The
// reroute-recalculation hysteresis: three gates stand between a fully
// off-route signal and an actual recalculation request — the request-in-flight
// gate, the cooldown and the movement threshold — plus the in-flight
// readback on the trip state, so a jittery off-route bounce cannot spam the
// integrator's routing engine. The gates live at the controller seam with
// the wall clock (exactly like the speech pacing's planner), never in the
// reducer: the reducer stays a pure, clock-free event function. The gates
// close the round-9 contract gap ("no reroute timestamp on the phase
// channel") without an addition there: a reroute timestamp on the phase
// channel is not addition-only (`NavigationPhaseChange` stays a payloadless
// flat enum), so the phase channel stays untouched and the honest closure is
// the gate seam plus the `is_calculating_new_route` readback plus
// `begin_reroute_calculation`'s boolean answer.
// ---------------------------------------------------------------------------

/// The reroute-recalculation hysteresis policy of a navigation controller
/// (round 11, Ferrostar B3's mechanism). Both thresholds must be finite and
/// non-negative; the controller refuses otherwise (`InvalidNavigationInput`),
/// leaving the policy in force untouched.
dictionary ReroutePolicy {
    /// Minimum wall-clock seconds between the beginnings of two reroute
    /// calculations (the SDK default: 5).
    double recalculation_cooldown_seconds;
    /// Minimum displacement, in meters, between the raw position fix current
    /// at a calculation's beginning and the one current at the previous
    /// calculation's beginning (the SDK default: 50).
    double recalculation_movement_meters;
};

// Native surface views (round 8, slice 0). The additions below mirror the
// wasm canvas' overlay plain-object names — `routePolyline`,
// `filledPolygon`, `pointMarkers`, `trafficFlow` — as a kind enum plus
// nullable fields (the round-7 navigation payload pattern: a field-carrying
// native enum lower as a tag with `null` marking the unused payload
// fields), and expose one `MapView` object: the FFI face of the
// `map-rendering` surface renderer, drawn by a platform view the foreign
// code owns (Kotlin `SurfaceView`, Swift `UIView`/`MKMapView`-style view,
// PRD §4.4–4.6). The renderer itself stays native (same `wgpu` machinery as
// the headless capture path); the FFI surface carries the lifecycle
// (attach/resize/detach), the overlay list, and an explicit per-frame draw.
// The platform's own render cadence drives the view — `draw` is per-frame,
// called from a display link or choreographer callback, never an SDK-
// internal loop: no SDK thread this slice, documented below.

/// Which overlay shape one descriptor configures. The kind tags follow the
/// wasm canvas' plain-object `kind` strings (the wasm seam passes the
/// lowercase camel kinds `routePolyline`/`filledPolygon`/`pointMarkers`/
/// `trafficFlow`/`pointPins`; the FFI enum variants are the contract's own
/// CamelCase), mirroring the native `MapOverlay` payloads one to one.
enum MapOverlayKind {
    /// A routed path drawn as a thick line.
    "RoutePolyline",
    /// A filled polygon: one outer ring, ear-clip triangulated.
    "FilledPolygon",
    /// Screen-facing point markers (octagon fans).
    "PointMarkers",
    /// Congestion-colored traffic-flow lines.
    "TrafficFlow",
    /// Screen-facing teardrop pins anchored at their tip with a hollow head
    /// center (the A/B route-endpoint marker); reuses `PointMarkers`' payload
    /// fields.
    "PointPins",
};

/// Solid RGBA overlay style, every channel in `[0, 1]`. Mirrors the wasm
/// canvas' `color` plain object. Null style fields keep the documented
/// `map-rendering` default style of the matching overlay kind.
dictionary OverlayColor {
    /// Red channel in `[0, 1]`.
    double red;
    /// Green channel in `[0, 1]`.
    double green;
    /// Blue channel in `[0, 1]`.
    double blue;
    /// Alpha channel in `[0, 1]` (the overlay pipeline alpha-blends).
    double alpha;
};

/// One overlay shape drawn over the map surface's tiles in every frame,
/// selected by `kind`. Each kind reads exactly its own payload fields and
/// ignores the others; a descriptor whose kind-required payload is absent
/// (or whose style field is unusable) rejects the whole `set_overlays` call
/// and keeps the previous list in force — the wasm canvas' all-or-nothing
/// semantics. Absent style fields keep the documented map-rendering
/// default style; present style fields must be usable (channels in
/// `[0, 1]`, widths and radii positive and finite). The record mirrors the
/// native `map-rendering` overlay structs field-for-field; the wasm canvas
/// plain objects carry the same names in camel case (`ringCoordinates`,
/// `pointMarkerPositions`, `pointMarkerRadiusPixels`,
/// `trafficFlowSegments`).
dictionary MapOverlay {
    /// Which overlay shape this descriptor configures and which payload
    /// fields carry it.
    MapOverlayKind kind;

    /// `RoutePolyline`: the traversal-order polyline; consecutive equal
    /// coordinates skip their degenerate segment. Required for the kind.
    sequence<GeographicCoordinate>? coordinates;
    /// Route polyline, filled polygon and point markers: solid color
    /// override, or null for the kind's documented default.
    OverlayColor? rgba_color;
    /// Route polyline and traffic flow: line width in screen pixels
    /// (positive and finite), or null for the kind's documented default.
    double? width_pixels;

    /// `FilledPolygon`: the outer ring in traversal order without a
    /// repeated closing vertex (a repeated one is tolerated and dropped).
    /// Required for the kind.
    sequence<GeographicCoordinate>? ring_coordinates;

    /// `PointMarkers` and `PointPins`: the geographic anchor of every marker
    /// (a pin's anchor is its tip). Required for both kinds.
    sequence<GeographicCoordinate>? point_marker_positions;
    /// `PointMarkers` and `PointPins`: marker radius in screen pixels
    /// (positive and finite), or null for the documented default. A pin's
    /// radius is its head radius.
    double? point_marker_radius_pixels;

    /// `TrafficFlow`: the flow observations to paint, one per road segment
    /// (or polyline of segments), colored by `congestion_level` — the same
    /// `TrafficFlowData` records the `fetch_traffic_flow` call returns.
    /// Required for the kind.
    sequence<TrafficFlowData>? traffic_flow_segments;
};

/// The platform window surface handle foreign code hands to
/// `MapView::attach`: exactly one platform pointer is set, the rest
/// stay null (a null-or-ambiguous handle is refused with
/// `SdkError::InvalidRenderInput`; a null pointer is `u64 0` or null, never
/// a zeroed pointer passed through). The handle shape is a single record
/// with one nullable pointer per supported platform — one dictionary keeps
/// add-a-platform growth additive and mirrors how uniffi records lower
/// everywhere. The object behind the pointer must outlive the attached
/// view: the raw handles are the caller's validity guarantee (see
/// `wgpu::SurfaceTargetUnsafe`), and detach/drop releases the Rust side
/// first, so dropping the platform view before `detach` is the caller's
/// bug.
dictionary SurfaceHandle {
    /// macOS: pointer to the `NSView` the surface renders into (Metal
    /// creates the layer from the view); null on the other platforms.
    u64? appkit_view_pointer;
    /// iOS: pointer to the `UIView` the surface renders into; null on the
    /// other platforms.
    u64? ios_view_pointer;
    /// Android: pointer to the `ANativeWindow` obtained from the platform
    /// `Surface` (`ANativeWindow_fromSurface`); null on the other platforms.
    u64? android_native_window_pointer;
};

/// The native map surface view: renders the camera-driven tiled map plus
/// the overlay list onto a live platform window surface through the same
/// `wgpu` machinery as the headless capture path. Construct with the
/// `MapSdk` whose registered raster-tile provider the attached surface
/// draws from (the provider resolves through the registry at attach time —
/// with no registered provider, `attach` throws
/// `SdkError::ProviderNotConfigured`).
///
/// # Lifecycle
///
/// `attach` wraps the platform handle, acquires the surface-compatible
/// graphics context, negotiates the surface format, configures the initial
/// extent and resolves the tile provider — every step's failure throws
/// (`SdkError::RenderingSurfaceUnavailable` for the GPU/surface path,
/// `InvalidRenderInput` for a bad handle or extent, `ProviderNotConfigured`
/// for the missing provider slot). `resize` (explicit, called from the
/// platform's surface-size callback) reconfigures the surface; a zero
/// extent rejects. `detach` releases the surface state until a re-attach.
/// Overlay state outlives attach/detach cycles: `set_overlays`,
/// `add_overlay`, `update_overlay`, `remove_overlay` and `clear_overlays`
/// all work detached, and the next attach draws the stored list. The
/// generated identifiers and the identifier sequence also survive
/// detach/attach: an overlay added detached stays addressable.
///
/// # Draw model
///
/// Frames are explicit: the foreign platform view calls `draw` once per
/// rendered frame from its own cadence (a display link, a choreographer, a
/// resize-then-once pattern) with the current `MapCamera` value — there is
/// deliberately no SDK-internal render thread or continuous redraw loop in
/// this slice. Each draw lists the camera's visible tiles, fetches the
/// pooled misses from the surface-attached provider (budgeted per frame,
/// parent fallback like the headless path), and renders tiles then
/// overlays alpha-blended, presenting to the surface. A failed frame
/// throws and leaves the previous frame on screen. Draws on one view are
/// serialized: a draw holding the view's render state (the fetch phase
/// spans network await) reports a concurrent `draw` or `resize` with
/// `RenderingSurfaceUnavailable`, the foreign cadence retrying the next
/// frame.
interface MapView {
    /// Builds the view over the SDK state it draws from.
    constructor(MapSdk map_sdk);

    /// Attaches the platform surface of the given initial physical-pixel
    /// extent (the extent must be non-zero; a platform view not laid out
    /// yet waits for `resize`). The wrap validates the handle, acquires
    /// the context, negotiates the format, configures and resolves the
    /// raster provider. Attaching an attached view is refused.
    [Throws=SdkError]
    void attach(SurfaceHandle surface_handle, u32 width_pixels, u32 height_pixels);

    /// Reconfigures the surface to the new physical-pixel extent (both
    /// non-zero); a mid-draw resize surfaces the busy state and the next
    /// frame's draw or the next resize call picks it up.
    [Throws=SdkError]
    void resize(u32 width_pixels, u32 height_pixels);

    /// Detaches: releases the surface, its renderer and its scheduler.
    /// Overlay state persists; re-attach rebuilds the drawing machinery.
    /// Safe against a draw still in flight (its frame completes and the
    /// state is then dropped without being restored).
    void detach();

    /// Replaces the drawn overlay list in one call, in order (later entries
    /// draw over earlier ones); an empty list clears. Every descriptor must
    /// be valid for its kind: no partial lists are kept. This is the bulk
    /// call: it replaces the whole drawn list, including overlays added
    /// through `add_overlay`, and drops the addressed bookkeeping — an
    /// identifier `add_overlay` returned before this call no longer
    /// addresses anything afterwards. Use this call for a list owned whole
    /// and `add_overlay`/`update_overlay`/`remove_overlay` for individually
    /// managed overlays; a later `add_overlay` appends to the replaced list
    /// and works alongside its unaddressed entries.
    [Throws=SdkError]
    void set_overlays(sequence<MapOverlay> overlay_descriptors);

    /// Adds one overlay to the drawn list and answers the generated opaque
    /// identifier addressing it (a monotonic per-view sequence such as
    /// `overlay-1`; identifiers are never reused, not even after
    /// `clear_overlays` or `set_overlays`). Validation is exactly
    /// `set_overlays`' all-or-nothing validation for the single descriptor:
    /// a refused descriptor throws and adds nothing, leaving the drawn list
    /// and the identifier sequence unchanged. The new overlay draws last,
    /// over the entries already in the list.
    [Throws=SdkError]
    string add_overlay(MapOverlay overlay);

    /// Replaces the overlay addressed by `overlay_identifier`. An unknown
    /// identifier (never generated, or invalidated by a later
    /// `set_overlays`/`clear_overlays`, or already removed) throws
    /// `SdkError` with a precise detail. The descriptor is validated exactly
    /// like `add_overlay`'s; an invalid descriptor throws and keeps the
    /// previously addressed overlay in force. The replacement keeps its
    /// position in the draw order.
    [Throws=SdkError]
    void update_overlay(string overlay_identifier, MapOverlay overlay);

    /// Removes the overlay addressed by `overlay_identifier` and answers
    /// whether that identifier was present. Removing an unknown identifier
    /// is not an error: it answers false and leaves the drawn list
    /// unchanged.
    boolean remove_overlay(string overlay_identifier);

    /// Clears the whole drawn overlay list — both the list supplied through
    /// `set_overlays` and every added addressed overlay — so following
    /// frames draw the tiles alone until `set_overlays` or `add_overlay`
    /// supplies new content. Identifiers generated earlier no longer
    /// address anything afterwards.
    void clear_overlays();

    /// Draws one frame for the camera: the camera's visible tiles fetched
    /// and rendered, overlaid, presented. Returns the frame's tile and
    /// overlay statistics (round-9 ask) so the platform render loop can
    /// report exactly what a frame drew: drawn pixels this frame come from
    /// the present and fallback tiles, while the deferred and unavailable
    /// counts are where later frames may still change pixels. Throws when
    /// the view is detached, a draw is already in flight, or the frame's
    /// rendering failed; a thrown draw leaves the previous frame on screen.
    [Async, Throws=SdkError]
    FrameStatistics draw(MapCamera camera);

    /// Round-10 (renderer-owned location indicator): sets the single
    /// location layer drawn after the tile pass and the overlay pass
    /// (topmost SDK layer), replacing any earlier state — mirroring
    /// `set_overlays`' all-or-nothing semantics, so a state or style that
    /// fails validation throws and keeps the earlier indicator. The state
    /// outlives attach/detach cycles like the overlay list; the styled
    /// visuals resolve to the documented map-rendering defaults for every
    /// null style field.
    [Throws=SdkError]
    void set_location_indicator(LocationIndicatorState state, LocationIndicatorStyle style);

    /// Clears the location layer; following frames draw tiles and overlays
    /// alone until `set_location_indicator` supplies new state.
    void clear_location_indicator();

    /// Round-10 (idle-settled redraw discipline): reads whether the view's
    /// presented state would not change if `draw` ran again right now —
    /// true when this camera value equals the last drawn camera, the overlay
    /// list and the location indicator are unchanged since that draw, and
    /// the last frame's tile statistics resolved no pending pixels (no
    /// fallback, deferred or unavailable tiles). A pure query: it never
    /// draws, fetches or mutates state, so a platform render pump can call
    /// it every display frame and skip `draw` when it answers true, letting
    /// the presented frame stand and resuming on any change or on the next
    /// pending detail's arrival. Throws when the view is detached.
    [Throws=SdkError]
    boolean is_frame_settled(MapCamera camera);

    /// M22: installs a vector base map — a provider-neutral vector tileset
    /// painted with one of the SDK's committed styles — replacing any vector
    /// base already installed. The source is validated before anything moves
    /// (the template's placeholders and scheme, the zoom range, the style id),
    /// so a refused call keeps the previously installed base in force.
    ///
    /// Each frame resolves the camera's visible tiles through one shared
    /// scheduler: a tile is fetched and decoded once and restyled from its
    /// cached geometry when the style changes or the camera crosses a style
    /// zoom stop, never refetched for either. The styled base draws over the
    /// raster tiles and beneath the overlay list. A tile that fails to fetch
    /// or decode is skipped and counted; it never fails the frame.
    ///
    /// Throws when a frame draw is in flight (the draw owns the scheduler for
    /// its duration; install after the frame draws). Configuring a base needs
    /// no attached surface: like the overlay list, the source outlives
    /// attach/detach cycles.
    [Throws=SdkError]
    void set_vector_tile_source(UrlTemplateVectorTileSource source);

    /// Removes the vector base map; following frames draw raster tiles and
    /// overlays alone until `set_vector_tile_source` installs a new base.
    /// Like installing, this throws while a frame draw is in flight.
    [Throws=SdkError]
    void clear_vector_tile_source();

    /// Reads the vector base source's status: the configured source and style
    /// plus the last resolved frame's drawn and failed tile counts. A pure
    /// query — it never fetches or draws, and it answers while a frame is in
    /// flight (with the previous frame's counts). It never throws: with no
    /// source installed it answers an honest not-configured status.
    VectorTileSourceStatus vector_tile_source_status();
};

/// One presented frame's tile and overlay accounting, mirroring how the
/// surface renderer resolves its scheduler verdicts. Every requested tile
/// lands in exactly one of the four readiness counts, so
/// `present + fallback + deferred + unavailable` always equals `requested`.
/// The four readiness names mirror the tile scheduler's fetch-state
/// taxonomy (`Present`/`FallsBackTo`/`Deferred`/`Unavailable`).
dictionary FrameStatistics {
    /// Tile requests the frame resolved (per request; a request listing
    /// carrying duplicates costs one fetch but reports per request).
    u32 requested_tile_count;
    /// Tiles drawn at their own zoom level.
    u32 present_tile_count;
    /// Tiles drawn from their nearest pooled ancestor.
    u32 fallback_tile_count;
    /// Tiles whose fetch was deferred by the per-frame budget.
    u32 deferred_tile_count;
    /// Tiles the provider rejected this frame.
    u32 unavailable_tile_count;
    /// Clip-space triangles the overlay layer contributed to the frame.
    u32 overlay_triangle_count;
};

// Round-12 provider-failure diagnostics (addition-only; the owner ruling of
// 2026-10-29 on unclassified foreign provider failures). Foreign
// implementations of the `[Trait, WithForeign]` provider contracts fail in
// two shapes: the typed shape (the foreign code threw one of the contract's
// `SdkError` variants, which round-trips one-to-one) and the unclassified
// shape (the foreign code failed some other way, which the Rust conversion
// reports under `ProviderRequestRejected` with its verbatim reason — the
// honest but thin detail the seam exists for). Every failed foreign-callback
// provider call is recorded on the seam with the contract and the callback
// method it occurred on, a timestamp, the classification, and the verbatim
// failure text; `MapSdk::latest_provider_failure_diagnostics` reads the
// bounded ring back.
//
// Honest limitation of the classification: the unclassified shape is
// recognized by the unclassified-callback conversion's verbatim detail text
// (one Rust-side constant shared by the conversion and the adapter-side
// classifier), so a foreign implementation that itself throws
// `ProviderRequestRejected` carrying exactly that conversion phrasing is
// indistinguishable and lands as unclassified. Richer typed payloads (a
// provider status code, a retriable flag) would need a channel the frozen
// provider traits cannot carry without a contract change; until one exists
// the foreign side's only input to the seam is the failure text it throws,
// which the entries carry verbatim — no data is parsed or invented.
// ---------------------------------------------------------------------------

/// Which shape of foreign provider failure a diagnostic captured
/// (`ProviderFailureDiagnostic::failure_classification`).
enum ProviderFailureClassification {
    /// The foreign implementation failed without a mapped error (an
    /// exception the contract does not spell): the failure text is the
    /// uniffi callback machinery's verbatim reason for it.
    "UnclassifiedCallbackFailure",
    /// The foreign implementation threw one of the contract's `SdkError`
    /// variants, which round-trips typed through the seam: the failure text
    /// is the thrown binding error's verbatim display form.
    "MappedContractError",
};

/// One failed foreign-callback provider call, as retained in
/// `MapSdk::latest_provider_failure_diagnostics`'s bounded per-object ring.
/// Everything carried here is knowable at the adapter boundary that bridges
/// the foreign implementation onto the native provider registry; no data is
/// invented beyond it.
dictionary ProviderFailureDiagnostic {
    /// Wall-clock milliseconds since the Unix epoch, as the seam recorded
    /// the failure.
    u64 timestamp_milliseconds_since_epoch;
    /// Which failure shape this entry captured.
    ProviderFailureClassification failure_classification;
    /// The provider contract the foreign code implements, e.g.
    /// `GeocodingProvider`.
    string provider_contract_name;
    /// The contract method whose call failed, e.g. `forward_geocode`.
    string provider_method_name;
    /// The verbatim failure text: the uniffi callback machinery's reason for
    /// the unclassified shape, or the thrown binding error's display form
    /// for the mapped shape.
    string failure_detail;
};

/// Search and geocoding facade over a `MapSdk`'s registered provider
/// contracts. Constructed over the same `MapSdk` the rest of the app holds;
/// a call into an unregistered contract throws
/// `SdkError::ProviderNotConfigured` with the contract name, exactly like
/// the matching `MapSdk` member.
interface SearchEngine {
    /// Builds the engine over the SDK whose provider registry serves its
    /// calls.
    constructor(MapSdk map_sdk);

    /// Returns full search results for a settled query; the boundary
    /// restricts the search when given. Delegates to `MapSdk::search`.
    [Async, Throws=SdkError]
    sequence<Place> search(string query_text, BoundingBox? search_boundary);

    /// Returns fast completion candidates while the user types; the
    /// boundary restricts the search when given. Delegates to
    /// `MapSdk::suggest`.
    [Async, Throws=SdkError]
    sequence<Place> suggest(string query_text, BoundingBox? search_boundary);

    /// Resolves a coordinate into candidate places describing that
    /// position. Delegates to `MapSdk::reverse_geocode`; the coordinate must
    /// be canonical degrees.
    [Async, Throws=SdkError]
    sequence<Place> reverse_geocode(GeographicCoordinate coordinate);
};

/// Routing facade over a `MapSdk`'s registered provider contracts.
/// Construction and failure semantics match `SearchEngine`'s: the engine
/// shares the SDK's registry and delegates verbatim.
interface RoutingEngine {
    /// Builds the engine over the SDK whose provider registry serves its
    /// calls.
    constructor(MapSdk map_sdk);

    /// Calculates a route through the ordered waypoints with the given
    /// options; every waypoint must be a canonical coordinate. Delegates to
    /// `MapSdk::calculate_route`.
    [Async, Throws=SdkError]
    Route calculate_route(sequence<GeographicCoordinate> waypoints, RouteOptions route_options);

    /// Calculates durations and distances for every origin-destination
    /// pair; every origin and destination must be a canonical coordinate.
    /// Delegates to `MapSdk::calculate_distance_matrix`.
    [Async, Throws=SdkError]
    DistanceMatrix calculate_distance_matrix(
        sequence<GeographicCoordinate> origins,
        sequence<GeographicCoordinate> destinations,
        TransportationMode transportation_mode
    );
};

/// Diagnostics facade over a `MapSdk`'s structured log-event stream and

interface Diagnostics {
    /// Builds the facade over the SDK whose diagnostics it observes.
    constructor(MapSdk map_sdk);

    /// Subscribes the foreign listener to the SDK's structured internal log
    /// events at `minimum_severity` or above. Delegates to
    /// `MapSdk::subscribe_to_diagnostic_events` (re-subscribing a listener
    /// replaces its severity gate).
    void add_listener(SdkDiagnosticEventListener listener, SdkLogSeverity minimum_severity);

    /// non-destructive and synchronous.
    u32 flush_recent(SdkDiagnosticEventListener listener, SdkLogSeverity minimum_severity, u32 maximum_count);
