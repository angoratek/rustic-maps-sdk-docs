MapSdk

Provider entry point of the SDK: resolves every call through the providers registered on the object. Construct the object with no providers, then register them: native integrations through the SDK’s own registration calls and foreign integrations through the register_*_from_foreign methods (see the provider contract interfaces above). A call into a contract with no registered provider throws ProviderNotConfigured naming the contract.

The calls cover geocoding (forward and reverse), routing, distance matrix, place search, traffic incidents, traffic flow and raster tiles. Elevation and offline routing have no provider contract here: offline routing is the standalone offline_route_from_archive_bytes function.

Navigator

The navigation controller: starts and stops trips, accepts position fixes and reroutes, broadcasts every state change to the registered listeners, and answers read-only state and instruction queries. Obtain routes from MapSdk::calculate_route or offline_route_from_archive_bytes and start a trip on them with this controller.

The listener callbacks run synchronously on the thread that drives the controller call; a listener calling back into the controller while a dispatch is still in flight is suppressed, and only the broadcast is skipped. The controller never holds its state lock across a listener callback.

MapView

The native map surface view: renders the camera-driven tiled map plus the overlay list onto a live platform window surface. Construct it with the MapSdk whose registered raster-tile provider the attached surface draws from; the provider is resolved at attach time, so with no registered provider attach throws ProviderNotConfigured.

Lifecycle

attach wraps the platform handle, acquires the surface-compatible graphics context, negotiates the surface format, configures the initial extent and resolves the tile provider. Each step’s failure throws: RenderingSurfaceUnavailable for the GPU or surface path, InvalidRenderInput for a bad handle or extent, and ProviderNotConfigured for the missing provider. resize, called from the platform’s surface-size callback, reconfigures the surface and rejects a zero extent. detach releases the surface state until a re-attach.

Overlay state outlives attach and detach cycles: set_overlays, add_overlay, update_overlay, remove_overlay and clear_overlays all work detached, and the next attach draws the stored list. Generated overlay identifiers also survive detach and attach, so an overlay added while detached stays addressable.

Draw model

Frames are explicit: the platform view calls draw once per rendered frame from its own cadence (a display link, a choreographer, or a resize-then-once pattern) with the current MapCamera. The SDK runs no internal render thread and no continuous redraw loop. Each draw lists the camera’s visible tiles, fetches pooled misses from the surface-attached provider within a per-frame budget, and renders tiles then overlays alpha-blended, presenting to the surface. A failed frame throws and leaves the previous frame on screen.

Draws on one view are serialized: a draw holding the view’s render state reports a concurrent draw or resize with RenderingSurfaceUnavailable, and the platform cadence retries on the next frame.

Async and threading

These calls are asynchronous on Kotlin: offlineRouteFromArchiveBytes, GeocodingProvider.forwardGeocode, GeocodingProvider.reverseGeocode, RasterTileProvider.fetchRasterTile, MapSdk.forwardGeocode, MapSdk.reverseGeocode, MapSdk.calculateRoute, MapSdk.calculateDistanceMatrix, MapSdk.suggest, MapSdk.search, MapSdk.fetchTrafficIncidents, MapSdk.fetchTrafficFlow, MapSdk.fetchRasterTile, MapView.draw, SearchEngine.search, SearchEngine.suggest, SearchEngine.reverseGeocode, RoutingEngine.calculateRoute, RoutingEngine.calculateDistanceMatrix.

Asynchronous calls are suspend functions and do not block the calling thread. The shipped map view members expect the main thread.

  • MapView.draw is frame-driven: call it from the platform display callback. A concurrent draw or resize reports RenderingSurfaceUnavailable; retry the next frame.
  • Navigation listener callbacks run synchronously on the thread that drives the controller. A listener must not block, and a callback made during an in-flight dispatch has its broadcast suppressed because the state change is already applied.
  • A diagnostics listener is called fire-and-forget on the thread that produced the event; it never delays the event stream.
