Rustic Maps SDK

WebAssembly API reference

Generated from the SDK contract and the generated WebAssembly bindings. Do not edit this page by hand; change the contract and regenerate the documentation.

The WebAssembly package gives a browser page a WebGPU map canvas, camera math, search and routing calls, an offline routing seam, diagnostics and a turn-by-turn controller. There is no native view: you supply an HTMLCanvasElement, and the canvas owns the surface and the frame. Values cross the boundary as plain JavaScript objects in camelCase; failures are thrown as verbatim strings.

MapsSdk

The browser SDK root (MapsSdk.create()): the object a page creates once and hands to its [crate::canvas::MapView], mirroring the native MapSdk construction shape. The wasm runtime is module-global, so this root carries the readiness result and the compiled version rather than a second runtime.

MapView

The browser GPU map canvas the page owns. Construct it over an HTMLCanvasElement, [MapView::initialize] it once (acquiring the adapter and device and building the tile pipeline), then call [MapView::render_frame] per wanted frame; each call re-schedules the visible tiles and redraws.

Navigator

Turn-by-turn navigation over a planned route, mirroring the driving and readback core of the contract’s Navigator.

Build it with new Navigator(); startNavigation(route, unitSystem) begins a trip over a Route exactly as calculateRoute answers it (unitSystem is "metric" or "imperial"), updateLocation(update) consumes one NavigationLocationUpdate and answers the trip snapshot (or null without a trip), applyReroute(route) swaps the active trip’s route, stopNavigation() clears it, and currentTripState() answers the latest snapshot (null without a trip).

The snapshot’s phase is "navigating", "offRoute" or "arrived" (the contract’s Navigating/OffRoute/Arrived); instruction is the composed payload (activeManeuver with distancePhraseText and displayText, an optional upcomingManeuver, progress, and the isArrival/isReroutingRequired markers); deviation is {statusChangeKind, distanceFromRouteMeters} exactly while the phase is off route; snappedCoordinate is {latitude, longitude} once a fix has been processed. The event bridge replaces the contract’s foreign-listener trait and delivers the same topics; hasActiveTrip() is the wasm-only helper.

Union and alias shapes

SdkError

Failures the contract throws across the binding surface, mirroring the contract’s SdkError variants one to one with their payload fields.

On the WebAssembly surface a failure is thrown as a JavaScript Error whose message is the verbatim detail and whose code is a stable lower-camel identifier. The code is the matching contract variant name, or one of the documented seam-level codes below when the contract has no matching variant. The error’s name is empty, so String(error) yields the message alone and message comparisons keep working. Branch on error.code, not on message text.

Contract codes: invalidCoordinateInput, networkRequestFailed, responseParsingFailure, providerRequestRejected, rateLimitExhausted, providerNotConfigured, invalidNavigationInput, invalidRenderInput, renderingSurfaceUnavailable, cacheOperationFailure, offlineRoutingFailure.

Seam-level codes: invalidArgument (a malformed argument, an unknown address or a lifecycle misuse), unsupportedCapability, geometryUnavailable (no screen-to-ground or ground-to-screen transform exists), runtimeUnavailable, and internal.

The discriminated union below is the structured contract shape the native surfaces receive.

Async and threading

  • The wasm runtime is module-global; create one root and one MapView per canvas.
  • Asynchronous calls return a Promise and reject with a verbatim string.
  • Frames are explicit and serialized. A second overlapping renderFrame is a borrow violation; keep a busy flag.
  • renderFrame consumes its MapCamera by value; build a fresh camera for each changed pose.
  • The navigation listener callback and diagnostics delivery are synchronous on the calling thread; do not block.
