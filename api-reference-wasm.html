Rustic Maps SDK

WebAssembly API reference

Generated from the SDK contract and the generated WebAssembly bindings. Do not edit this page by hand; change the contract and regenerate the documentation.

The WebAssembly package gives a browser page a WebGPU map canvas (BrowserMapView and the canvas MapCamera), generated from the frozen contract alongside the provider, search, routing, navigation, positioning and diagnostics classes. There is no native view: you supply an HTMLCanvasElement, and the canvas owns the surface and the frame. Contract calls exchange plain camelCase records and reject with a typed SdkError.

BrowserMapView

The browser GPU map canvas the page owns. Construct it over an HTMLCanvasElement, [BrowserMapView::initialize] it once (acquiring the adapter and device and building the tile pipeline), then call [BrowserMapView::render_frame] per wanted frame; each call re-schedules the visible tiles and redraws.

Construction

ConstructorSignaturePurpose
constructorconstructor(canvas: HTMLCanvasElement, tileResolution: TileResolution | null, recordedTileFixturesAreServed: boolean | null)Builds the canvas renderer over the page’s canvas element (new BrowserMapView(canvas, tileResolution?, recordedTileFixturesAreServed?)). The tile pixel resolution is optional: omitted, it follows the same device-pixel-ratio rule as retinaDevicePixelRatioThreshold(); supplied, it is honoured verbatim. The recorded-fixture capability is optional and defaults to enabled. Enabled, a raster fetch probes the same-origin /tiles fixtures before a registered live source, which is what the local dev server and the test harness serve. Disabled, the fetch goes straight to the registered provider and records no fixture attempt, so a page that stages no fixtures issues no 404 for them. Fails when the element cannot host a GPU surface (for example after another context already claimed the element). Call [BrowserMapView::initialize] before the first [BrowserMapView::render_frame].

Async and threading

  • The wasm runtime is module-global; create one MapSdk root and one BrowserMapView per canvas.
  • Asynchronous calls return a Promise and reject with a typed SdkError.
  • Frames are explicit and serialized. A second overlapping renderFrame is a borrow violation; keep a busy flag.
  • renderFrame consumes its canvas MapCamera by value; build a fresh camera for each changed pose.
  • The navigation subscriptions and diagnostics delivery are synchronous on the calling thread; do not block.
