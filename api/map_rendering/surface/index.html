Module surface 

Source
Expand description

Surface rendering of raster tiles plus overlays onto a live native window: the same scene composition as the headless renderer, presented through a real wgpu::Surface.

The renderer draws one textured quad per pooled tile for a single frame and an optional overlay layer (crate::overlay::MapOverlay) after the quads in the same render pass — byte-for-byte the headless pipeline’s geometry and shaders (the private shader sources and encode helpers are verbatim mirrors of crate::headless, the established cross-seam mirror pattern the wasm canvas follows) — but the frame renders into the next acquired surface texture and is presented, not captured. The pipelines therefore target the surface’s negotiated format (for example Bgra8Unorm under Metal), unlike the headless capture’s fixed FRAME_TEXTURE_FORMAT; the negotiation happens once at construction from the documented preference list and every later configuration keeps it.

§Lifecycle (the platform seams’ contract)

Per-platform raw window handles lower into a [wgpu::SurfaceTargetUnsafe] outside this crate, which takes over from there — this module is platform-agnostic and never names a windowing backend:

  1. Wrap the unsafe target with SurfaceRenderTarget::from_unsafe_target, which creates the wgpu::Instance and the 'static [wgpu::Surface] against it. The raw handle must stay valid for the surface’s whole lifetime; wgpu’s own validity rules apply (see [wgpu::SurfaceTargetUnsafe]).
  2. Build the renderer with SurfaceTileRenderer::new, acquiring the adapter/device/queue through the injected SurfaceGraphicsContextSource (production: WgpuSurfaceGraphicsContextSource, which requests an adapter compatible with the surface, unlike the headless source). The surface format is negotiated here.
  3. Size the render area explicitly with SurfaceTileRenderer::configure_extent — resize is a call, not an observation: only a configure changes the swap-chain extent. A zero extent is refused; an already-configured extent reconfigures only when the extent changes (matching the headless-wasm mirror’s behavior).
  4. Draw every frame with SurfaceTileRenderer::render_frame; the frame’s viewport must match the configured extent exactly. A stale surface (window resized or torn down behind the renderer’s back) reconfigures once and retries the acquisition before failing.
  5. Detach by dropping the renderer: the wgpu surface’s own release semantics are its drop behavior (wgpu 30 has no separate un-configure call), so the platform glue’s surface view drops the renderer — and every SurfaceRenderTarget it wraps — when its window handle goes away.

Attach and detach of the underlying platform view itself belong to the caller: dropping the SurfaceRenderTarget while its raw handle is reused elsewhere is the handle owner’s bug to avoid, so the platform glue that owns the view outlives the renderer.

§Native only

Like crate::headless, this module blocks on the asynchronous wgpu initialization and configuration calls (pollster) and is not valid on wasm, where the browser runtime drives webgpu (the wasm seam is the GpuMapCanvas of map-web-bindings).

Structs§

SurfaceFrameStatistics
One presented surface frame’s tile and overlay accounting, straight out of the scheduler’s readiness verdicts and the overlay assembly — every requested tile lands in exactly one of the four readiness counts, so present + fallback + deferred + unavailable always equals requested. Drawn pixels this frame come from the present and fallback tiles; the deferred and unavailable tiles are where later frames may still change pixels (the pending half of the fetch-state taxonomy).
SurfaceGraphicsContext
A surface-compatible adapter/device/queue triple for surface rendering. Carries the [wgpu::Adapter] itself — unlike the headless context — because surface configuration and format negotiation consult the adapter’s capabilities on every extent change.
SurfaceRenderTarget
A live presentation target: the wgpu instance and the surface created against it from a platform-provided [wgpu::SurfaceTargetUnsafe]. The surface is 'static — wgpu relies on the raw handle staying valid while the surface exists, which is the platform glue’s responsibility (see the module documentation on the lifecycle).
SurfaceTileRenderer
Renders raster tiles to a live wgpu surface. Owns the pipelines, sampler, uploaded-texture cache and the negotiated surface format; the graphics context is injected, so production code and tests can supply any surface-backed device through SurfaceGraphicsContextSource. The pipeline pair, upload path and encode helpers mirror the headless renderer exactly (see the module documentation).
WgpuSurfaceGraphicsContextSource
The production source: requests the first available adapter compatible with the wrapping surface, blocking on it with pollster (native only; see the module documentation). The device/queue request itself is the headless source’s call sequence verbatim.
