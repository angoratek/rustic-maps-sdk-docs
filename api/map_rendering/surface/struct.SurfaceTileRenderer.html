Struct SurfaceTileRenderer 

Source 
pub struct SurfaceTileRenderer { /* private fields */ }
Expand description

Renders raster tiles to a live wgpu surface. Owns the pipelines, sampler, uploaded-texture cache and the negotiated surface format; the graphics context is injected, so production code and tests can supply any surface-backed device through SurfaceGraphicsContextSource. The pipeline pair, upload path and encode helpers mirror the headless renderer exactly (see the module documentation).

pub fn configure_extent( &mut self, width_pixels: u32, height_pixels: u32, ) -> Result<(), SurfaceRenderError>

Sizes the render area explicitly — the resize seam of the lifecycle: only this call changes the swap-chain extent. A zero extent is refused (a surface with no pixels is not configurable); reconfiguring happens only when the extent actually changed, so a repeated call on extent change is idempotent. The first configure adopts the negotiated surface format and the documented present and alpha modes; the format is never renegotiated, so a platform surprise that drops support for it surfaces here as a configuration failure.

Renders one frame of tiles plus overlays to the live surface and presents it. The three-layer variant adds the location-indicator layer; this signature keeps the two-layer contract byte-stable by delegating with no indicator.

Source

pub fn render_frame_layers( &mut self, camera: &MapCamera, viewport: &ViewportPixels, prepared_tiles: &[PreparedTile], pool: &mut TileTexturePool, overlays: &[MapOverlay], location_indicator_layer: Option<&LocationIndicatorLayer>, ) -> Result<SurfaceFrameStatistics, SurfaceRenderError>

The frame’s explicit three-layer variant: the pooled tiles’ textured quads, then the overlay layer, then the location-indicator layer (the indicator draws last, the frame’s explicit top layer — see crate::location_indicator::LOCATION_INDICATOR_TOP_LAYER_DRAW_ORDER).

The frame composition — quad assembly, texture uploads with revision-stamped cache reuse, corrupted-payload eviction, the tiles-then-overlays-then-indicator pass order — is the headless renderer’s behavior exactly (see HeadlessTileRenderer’s frame documentation); differences are only the attachment and its outcome: the frame draws into the next acquired surface texture, presented instead of captured.

Returns the frame’s SurfaceFrameStatistics — the scheduler readiness verdicts and the overlay triangles the presented frame carried.

Requires a prior Self::configure_extent; the frame’s viewport must match the configured extent exactly (pixels are physical). An empty frame request set, an empty overlay list, and a cleared indicator naturally render the clear color alone.

pub fn render_frame_with_labels( &mut self, camera: &MapCamera, viewport: &ViewportPixels, prepared_tiles: &[PreparedTile], pool: &mut TileTexturePool, label_layer: Option<&LabelLayer>, ) -> Result<SurfaceFrameStatistics, SurfaceRenderError>

Renders one frame of tiles, overlays and the label layer — no location indicator — and presents it. A None or empty label layer contributes no buffer or draw, leaving the frame identical to the unlabeled pipeline’s.

Source

pub fn render_frame_layers_and_labels( &mut self, camera: &MapCamera, viewport: &ViewportPixels, prepared_tiles: &[PreparedTile], pool: &mut TileTexturePool, overlays: &[MapOverlay], location_indicator_layer: Option<&LocationIndicatorLayer>, label_layer: Option<&LabelLayer>, ) -> Result<SurfaceFrameStatistics, SurfaceRenderError>

The frame’s full four-layer variant: pooled tile quads, overlays, the label layer’s halo and text passes (drawn over the overlays through the textured glyph pipeline), then the location indicator. An absent or empty label layer creates no buffer, no atlas upload and no draw, so frames without labels stay identical to the earlier pipeline’s.
