Struct HeadlessTileRenderer 

Source 
pub struct HeadlessTileRenderer { /* private fields */ }
Expand description

Renders raster tiles headlessly. Owns the pipeline, sampler, and the uploaded-texture cache; the graphics context is injected, so production code and tests can supply any backed device through GraphicsContextSource.

pub fn snapshot_frame_when_idle( &mut self, camera: &MapCamera, viewport: &ViewportPixels, prepared_tiles: &[PreparedTile], pool: &mut TileTexturePool, overlays: &[MapOverlay], ) -> Result<CapturedFrame, HeadlessRenderError>

The idle-gated snapshot: refuses to render while pending tile work remains, and otherwise captures exactly the ordinary frame (see the module documentation for how MapLibre’s snapshot pair maps onto the headless path).

The gate is the idle render-state signal applied to this frame’s own request set at capture time, so it needs no scheduler around: a requested tile is pending when its prepared verdict is anything but crate::tile_scheduler::TileReadiness::Present — a parent fallback still owes the child’s detail, an Unavailable fetch is retried later, a Deferred tile is fetched later — and also when a Present verdict’s payload left the pool between the prepare frame and this snapshot, whose area would otherwise capture as a hole pixels the next fetch could fill. When the verdict is crate::prepared_frame_is_idle and every pooled payload is still in the pool, the frame’s pixels can no longer change through scheduled work and the frame renders and captures — byte-for- byte the ordinary capture’s behavior, so the two are intercomparable.

The refusal is decided before any GPU work: an unresolved frame returns HeadlessRenderError::PendingTileWork immediately and never waits for the pending work to complete. An empty request set is idle by vacuity, so an empty-frame snapshot renders the clear color (as does the ordinary capture).

pub fn render_captured_frame_layers( &mut self, camera: &MapCamera, viewport: &ViewportPixels, prepared_tiles: &[PreparedTile], pool: &mut TileTexturePool, overlays: &[MapOverlay], location_indicator_layer: Option<&LocationIndicatorLayer>, ) -> Result<CapturedFrame, HeadlessRenderError>

The frame’s explicit three-layer variant: the pooled tiles’ textured quads, then the overlay layer, then the location-indicator layer (the indicator draws last, the frame’s explicit top layer — see crate::location_indicator::LOCATION_INDICATOR_TOP_LAYER_DRAW_ORDER).

The frame’s quads are assembled GPU-free by crate::renderer::Renderer::frame_quads; each pooled payload is uploaded once — either freshly decoded, or reused from GpuTileTextureCache when the pool’s payload revision still matches the upload’s stamp — in prepared order, so later detailed tiles paint over any earlier fallback content they overlap. Uploads whose bytes the pool replaced or dropped since are pruned at frame start. Each quad may project into up to two world-copy fragments, which are separate draw quads sharing the quad’s texture. A payload that fails to decode — or one that left the pool between assembly and upload — skips its quads and, when corrupt, is evicted from the pool so the scheduler refetches it; the rest of the frame renders normally.

After the tile draws, the overlay layer — the clip-space solid-color triangles assembled GPU-free by crate::overlay::overlay_triangle_vertices through the same camera pose — draws through a second pipeline into the same render attachment, alpha-blended over the tiles. An empty overlay list contributes no draw at all, keeping such frames identical to the tiles-only pipeline’s.

The location-indicator layer draws third — the clip-space solid-color triangles assembled GPU-free by crate::location_indicator::location_indicator_vertices through the same camera pose, drawn through the same overlay pipeline (shader/layout-identical) and alpha-blended over what the first two layers drew. A None indicator creates no buffer and contributes no draw, keeping indicator-free frames identical to the two-layer pipeline’s.

pub fn render_captured_frame_layers_and_labels( &mut self, camera: &MapCamera, viewport: &ViewportPixels, prepared_tiles: &[PreparedTile], pool: &mut TileTexturePool, overlays: &[MapOverlay], location_indicator_layer: Option<&LocationIndicatorLayer>, label_layer: Option<&LabelLayer>, ) -> Result<CapturedFrame, HeadlessRenderError>

The frame’s full four-layer variant: pooled tile quads, overlays, the label layer’s halo and text passes (drawn over the overlays through the textured glyph pipeline), and the location indicator on top. A cleared indicator and an absent or empty label layer both create no draw, so indicator-free and label-free frames stay byte-identical to the earlier pipelines’ captures.

The glyph atlas uploads once per distinct font: the uploaded page is stamped with the font’s content revision and reused on every later frame that draws the same font.
