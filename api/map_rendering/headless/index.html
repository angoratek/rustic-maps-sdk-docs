Module headless 

Source
Expand description

Headless wgpu rendering of raster tiles plus deterministic frame capture.

The renderer draws one textured quad per pooled tile for a single frame into an off-screen render-attachment texture and reads the pixels back into a CapturedFrame; an optional overlay layer (crate::overlay::MapOverlay) draws after the quads in the same render pass through a separate solid-color pipeline. Pooled payloads that fail to decode are skipped for the frame and evicted from the pool so the scheduler refetches them — one corrupt tile never poisons the frames after it; only structural failures (an overflowing draw list, a failed context acquisition or capture) are errors. No surface is requested, so this works on any native backend (Metal, Vulkan, DirectX): device acquisition lives behind the object-safe GraphicsContextSource seam, keeping wgpu types out of the scheduling core and letting tests substitute their own context source or skip rendering when no adapter exists.

This module is native-only: blocking on the asynchronous wgpu initialization calls and polling the device is not valid on wasm, where the browser’s own async runtime drives webgpu.

§Capturing snapshots (MapLibre snapshot() / snapshotSync())

MapLibre renders the current frame into a bitmap asynchronously (snapshot()) or synchronously (snapshotSync()), and GL JS fires its idle event precisely when no tile loading or animation work remains — the pair exists so captures are deterministic (await the idle state, then snapshot without racing late work). Reading that pattern against what the headless path actually is:

  • Every capture here is already snapshot-shaped: frames compose into an off-screen render attachment that is never presented to a window, and capture_frame_bytes reads the result back — the same separation of scene composition from presented output the MapLibre snapshot relies on, with no capture machinery of a live view to sidestep.
  • There is no async/sync split to port, because no asynchronous runtime drives the device: a capture is inherently blocking on the readback (capture_frame_bytes escalates to a blocking device poll), so an async snapshot() twin would be ceremony over the same call.
  • What is actually missing for deterministic captures is the idle gate. It is implemented as HeadlessTileRenderer::snapshot_frame_when_idle, which refuses to render while pending tile work remains — returning HeadlessRenderError::PendingTileWork immediately, without touching the GPU — and otherwise behaves exactly like the ordinary capture. That makes it the non-blocking half: the refusal decision costs no device work and never waits for pending work to finish; completing the work is the caller’s next prepare frame. MapLibre’s un-gated synchronous variant is the ordinary capture (HeadlessTileRenderer::render_captured_frame_with_overlays) — it always renders and captures, however much tile work is still pending.

The idle gate covers tile fetch state only; camera animations are composed outside this renderer entirely (see crate::tile_scheduler on the full idle semantics).

Constants§

FRAME_TEXTURE_FORMAT
GPU format of both the tile textures and the captured frame. The image crate decodes tile payloads to plain RGBA8, so no sRGB conversion is applied in the pipeline this slice; colors round-trip byte-for-byte.
GLYPH_ATLAS_TEXTURE_FILTER
Filter mode of the glyph atlas sampler: linear interpolation keeps the signed-distance contour smooth when the style’s text size differs from the atlas’ 24-pixel em.
GLYPH_ATLAS_TEXTURE_FORMAT
GPU format of the glyph atlas: one signed-distance byte per pixel, which the label shader thresholds into text coverage.
MAXIMUM_QUADS_PER_FRAME
Draw quads a frame may carry, where a world-copy fragment of a tile counts as one draw quad: the bound keeps both the fragment vertices (four corners each) and the draw list inside a 16-bit index buffer.
TILE_TEXTURE_ADDRESS_MODE
Clamp sampler addressing: quads sample exactly their declared sub-window of the texture, so edge behavior never triggers.
TILE_TEXTURE_FILTER
Filter mode of the tile sampler. Linear interpolation gives smooth minification for both the pitched camera and fallback draws scaled up.
TILE_TEXTURE_MIPMAP_FILTER
Interpolation between mip levels. The textures this slice uploads carry no mip chain, so the mode never applies; linear keeps the sampler consistent should mip chains arrive in a later slice.

capture_frame_bytes
