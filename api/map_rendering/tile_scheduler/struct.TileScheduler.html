pub fn is_idle(&self, requested_tiles: &[TileKey]) -> bool

The idle render-state signal over a request set: whether no pending tile work remains, judged against the pool’s current contents — every distinct requested tile sits pooled at its own zoom level. This is the fetch-state half of GL JS’s idle event (see the module documentation for the full semantics).

Compared with Self::prepare_frame, which fetches misses, this query never fetches: it answers from the state a previous prepare frame left behind, or from a pool the caller filled directly. It reports false for a budget-deferred tile mid-fetch, for a tile whose fetch failed, and for a tile relying on a parent fallback, and it flips back to pending when the pool loses a requested payload.

pub fn delivered_warm_tile_count(&self) -> u64

The number of payloads this scheduler’s background warm tasks have delivered into the pool: the on_tiles_arrived counter of the idle-settled redraw discipline (see the module documentation), which a pump pairs with Self::is_idle and the frame verdicts to resume a settled view when pending detail arrives.

Source

pub fn resolve_frame( &mut self, requested_tiles: &[TileKey], ) -> Vec<PreparedTile>

Resolves every requested tile’s readiness for one frame from the pool’s current state alone — the await-free half of the frame path (see the module documentation): purely synchronous, GPU-free, and never touching the provider, so an uncovered camera pose reports its fallback verdicts immediately instead of stalling the frame on the network. Completed background warm deliveries (see Self::plan_warm_tiles) drain into the pool first, so the freshest fetched detail resolves into this frame.

Duplicate requests keep one verdict per request (deduplication is a fetch concern, not a display one — the renderer draws per request).

Source

pub async fn warm_tiles(&mut self, requested_tiles: &[TileKey]) -> usize

Fetches the requested tiles’ pooled misses — the awaited half of the frame path: deduplication, the most-detailed-first order and the per-call budget (see the module documentation), with the fetches’ outcomes delivering through the shared registry whose Self::resolve_frame drains them into the pool. Designed for callers that await (tests, the blocking reference path); a frame path that must not block plans the detached twin with Self::plan_warm_tiles and runs it on its own background task. Returns the number of fetches the call issued.

Source

pub fn plan_warm_tiles(&mut self, requested_tiles: &[TileKey]) -> TileWarmTask

Plans a detached warm fetch of the requested tiles’ pooled misses: the owned TileWarmTask to run on a background runtime (fire and forget — the frame path never awaits it). The plan marks its tiles in the shared registry, so every Self::resolve_frame until the delivery drains reports them Deferred (the pixels may change when the detail arrives), and the task’s outcomes deliver back through the scheduler’s channel. Returns a task fetching nothing when nothing needs warming.

Source

pub async fn prepare_frame( &mut self, requested_tiles: &[TileKey], ) -> Vec<PreparedTile>

Resolves every requested tile for this frame, fetching misses.

Duplicate requests appear once per request in the returned frame but cost one fetch. The pool is consulted before fetching so pooled ancestors serve as fallbacks immediately.

The blocking reference path (see the module documentation): every fetch it issues is awaited inside the call, so a never-covered camera pose costs the network through this method — the split’s Self::resolve_frame + Self::warm_tiles/Self::plan_warm_tiles never does. Completed detached warm deliveries drain first, so a background fetch’s payload lands in the pool before this frame would refetch it; in-flight warming tiles are left to their own tasks rather than double-fetched.
