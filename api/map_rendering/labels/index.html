Module labels

Expand description

The frame-level label pass (M9 slices S3 and S4): symbol-layer text from the decoded vector tiles becomes screen-space glyph quads, anchored at a point for place and POI names and run along a line for road names.

The pass is deliberately GPU-free, like the overlay assembly: the native headless renderer, the native surface and the browser canvas all call the same functions and upload the same vertices, so the three backends cannot drift in where a label lands or which labels survive.

Three stages:

  1. label_candidates_for_vector_tile walks a decoded tile’s symbol-layer features and reads each label’s text through the style’s ordered fallbacks. Candidates keep the style’s paint, size, priority, rank, placement and overlap rule. A symbol layer also filters before a feature becomes a candidate: its rank must pass the layer’s zoom-stepped rank ceiling, and its class must be useful at the frame’s zoom (a shop waits until the layer’s per-class minimum zoom). A VectorSymbolPlacement::Point layer anchors a candidate at each of the feature’s points; a VectorSymbolPlacement::Line layer carries the feature’s whole line geometry so the frame can place the text along it.

  2. LabelLayer::place projects the candidates through the frame camera, sorts them by priority, then style order, then rank (the documented collision-priority rule: lower priority is more important), and greedily rejects any label whose padded screen rectangle intersects a label already placed. allow_overlap labels skip the test and never block later labels. The frame places at most MAXIMUM_LABELS_PER_FRAME labels: once that budget is spent, every remaining candidate is dropped even if it would fit, so a dense downtown cannot out-shout the places that matter. A label whose text repeats an already-placed label is dropped, so the buffered overlap between adjacent tiles cannot paint one place twice. The output order is a pure function of the input order and the camera.

    A line-placed label projects its geometry and takes its longest straight run (consecutive near-collinear segments) as the text’s run: the text is centered halfway along that run, rotated to its chord bearing, flipped so it always reads upright, and skipped when the run is shorter than the text plus the collision padding at each end. The collision rectangle is the axis-aligned box around the rotated text, so it rejects exactly like a point label’s.

  3. LabelLayer::quad_vertices lays the glyph bitmaps out on the atlas and emits clip-space textured quads, halo first and text second. A rotated label rotates each glyph’s screen-space rectangle about the label’s anchor before converting it to clip space, so every backend that draws these vertices carries rotation without a second vertex format.

Latin text is measured from the decoded glyph ranges and nothing here shapes complex scripts (see map-glyphs). A frame with no symbol layers or no glyphs produces no vertices, so the tiles-only pipelines stay byte-identical.

Constants§

DEFAULT_LABEL_RANK
The rank an unranked label carries: the highest value, so it sorts after every ranked label of the same style layer.
DEFAULT_LATIN_GLYPH_RANGE_PBF_BYTES
The committed Latin glyph range the SDK’s default label font decodes: one real Mapbox glyph-protocol 0-255 payload in Noto Sans Regular, the same file the render fixtures and the browser label suite read (see fixtures/render/glyphs/README.md). Embedding it gives every native surface a glyph source without a fetch or a platform-specific asset seam.
GLYPH_FONT_ASCENDER_PIXELS
The line ascent the glyph protocol subtracts from each glyph’s ink top before storing it: fontnik writes stored_top = ink_top_above_baseline - ascender at the protocol’s 24-pixel em, so a renderer reconstructs the baseline-relative ink top as stored_top + ascender. Noto Sans’ ascender at that size is 26 pixels (the payload’s no-ink space glyph stores -26).
GLYPH_FONT_EM_PIXELS
The em size the Mapbox glyph protocol rasterizes signed-distance-field glyphs at: every glyph metric in a range payload is expressed in these 24-pixel em units and scaled to the style’s text size at draw time.
GLYPH_HALO_SIGNED_DISTANCE_THRESHOLD
The signed-distance value the halo pass treats as covered: a lower threshold spreads the glyph’s edge outward into a legible outline.
GLYPH_TEXT_SIGNED_DISTANCE_THRESHOLD
The signed-distance value at which a glyph bitmap counts as covered: the texture stores the distance to the glyph edge, so the 0.5 contour is the outline.
LABEL_BASELINE_OFFSET_FRACTION
How far below the anchor a label’s baseline sits, as a fraction of the text size. Centering a line of text on its anchor point needs the baseline below the visual center by roughly a third of the em.
LABEL_CLASS_ATTRIBUTE_NAME
The feature attribute a symbol layer reads as its class (shop, restaurant, city, …), which a style can hold back until a closer zoom.
LABEL_COLLISION_PADDING_PIXELS
The transparent margin kept around a placed label’s screen rectangle for collision rejection, in pixels. Labels closer than this read as a single run of text, so the padding is what keeps two names from touching.
LABEL_RANK_ATTRIBUTE_NAME
The feature attribute a symbol layer reads as its collision rank.
LINE_LABEL_STRAIGHT_RUN_ANGLE_TOLERANCE_RADIANS
How far a segment’s bearing may turn from its run’s first segment and still belong to the same straight run, in radians (20 degrees, a ninth of a half turn). Map data splits a street into short blocks between intersections, so a label must run along the straight sequence of segments, not one block alone; the tolerance keeps a name off a road that bends away mid-run.
LINE_LABEL_UPRIGHT_ROTATION_LIMIT_RADIANS
The bearing limit within which a line-placed label reads upright. A segment whose direction would rotate the text past this angle is flipped to run the other way, so a street name never paints upside down: the label’s rotation always lies in [-π/2, π/2].
MAXIMUM_LABELS_PER_FRAME
The maximum number of labels one frame may place. The collision pass alone lets a dense downtown paint far more text than a reader can parse, so the frame stops at this budget after the priority sort: the most important names always win, and a busy tile can only spend the frame’s remaining room. Thirty-two labels is about one per 8,200 screen pixels at the 512- pixel label golden (whose filtered collision pass places ten), so it leaves a full-screen demo headroom while capping the nine-tile downtown demo.

Functions§

default_label_font
The SDK’s default label font: DEFAULT_LATIN_GLYPH_RANGE_PBF_BYTES decoded and packed into one atlas the first time a frame asks for it, then reused. The packed atlas rides in an Arc, so handing the font to LabelLayer::place never re-copies the page, and the renderer’s atlas upload happens once per distinct revision.
label_candidates_for_vector_tile
Reads the label candidates from one decoded tile under the style’s symbol layers, at an explicit style zoom level (the frame camera’s zoom, so size stops evaluate where the camera is rather than where the tile belongs).
