Module overlay 

Source
Expand description

GPU-free overlay assembly: route polylines, filled polygons, point markers, and traffic-flow lines projected into clip-space solid-color triangle lists drawn over the tile quads.

Overlays are the second draw layer of a captured frame: the same camera pose and viewport that assemble the tile quads (crate::renderer::Renderer::frame_quads) also project overlay shapes into clip-space triangles via overlay_triangle_vertices, which the headless renderer draws through a separate solid-color pipeline in the same render pass after the tiles (see the crate-level seam notes in the browser-loop documentation: the wasm canvas mirrors the vertex contract verbatim, so the assembly here is deliberately wgpu-free and emits one flat, non-indexed triangle list).

Design decisions recorded for this slice:

  • World copies / antimeridian. Overlay geometry wraps around the camera exactly like tile spans do (see [crate::renderer::FrameProjection]): the first vertex of a shape sits in the camera’s world copy via the shortest wrapped delta, every following vertex unwraps continuously from it, and each resulting segment or triangle is split against the camera-centered world-copy windows ([WORLD_COPY_WINDOW_OFFSETS], reusing the tile spans’ window half-width). A shape wider than the covered window range clips to nothing beyond it; a single unwrapping step never spans more than half a world, so three windows cover every reachable fragment.
  • Frustum clipping. Assembly relies on the GPU’s clip-space frustum clip, the same mechanism the tile pipeline relies on for near-plane straddling spans; no extra CPU cull runs. Screen-space-thickened shapes (route lines, markers, traffic) additionally drop the segments and markers with a vertex at or behind the camera because the screen-space width offset needs a positive homogeneous weight; filled polygons emit genuine clip-space corners and keep near-plane straddling triangles for the GPU to clip exactly.
  • Line joins. A polyline draws as butt-capped segment quads plus one screen-space square (the line’s width) per interior vertex, oriented along the bend’s bisector. The square fills the wedge the butt caps leave outside a bend, which otherwise reads as a gap between styled road segments; it never grows a miter spike at sharp angles. Endpoints keep their butt caps (a per-feature end has no neighbouring segment to join), and sharp joins can still show a sliver where the wedge exceeds the square — a full round-join fan is the documented later refinement.
  • Polygon holes. A filled polygon carries one outer ring and any number of hole rings. Holes join the outer boundary through the standard bridge-splicing step before ear clipping (FilledPolygonOverlay documents the algorithm), so the emitted triangle stream covers exactly the ring set’s even-odd interior: the overlay pipeline paints a flat triangle list with alpha blending and has no stencil test, so a hole must leave its region out of that list rather than erase it after the fact.
  • Markers. A marker is a regular-octagon triangle fan centered on the projected anchor point (center anchoring, not bottom pinning): the projected coordinate is the fan’s center, so a marker’s center sits exactly at its geographic position. Sprites and label callouts are explicitly not this slice.
  • Pins. A pin is a teardrop anchored the other way: its tip sits on the projected coordinate and the circular head above it carries a hollow center. The teardrop is star-shaped around the head center, so the outline is one radial function of the angle and the hollow center is the annulus between that outline and an inner circle — again a plain triangle list, no erase pass.

Structs§

ClipSpaceOverlayVertex
One overlay triangle-list vertex as consumed by the GPU: a position in clip space (homogeneous coordinates; the perspective divide happens on the GPU) and the solid RGBA color to shade there. repr(C) keeps the field order the vertex buffer layout expects.
FilledPolygonOverlay
A filled polygon: one outer ring plus any hole rings, bridge-joined and ear-clip triangulated in one pass and painted solid FilledPolygonOverlay::rgba_color (through the overlay pipeline’s alpha blending, so translucent fills keep the base tiles readable).
PointMarkersOverlay
Point markers drawn as screen-facing colored octagons anchored with their center at each projected position (center anchoring, not bottom pinning — see the module notes). Sprite/atlas markers are not this slice.
PointPinsOverlay
Teardrop pins: a screen-facing pin per anchor, drawn as a filled teardrop whose point (tip) sits exactly on the projected anchor and whose circular head carries a hollow center — the standard “A/B” route-endpoint marker.
RoutePolylineOverlay
A routed path drawn as a thick line: one traversal-order polyline thickened to RoutePolylineOverlay::width_pixels in screen space and painted solid RoutePolylineOverlay::rgba_color.
TrafficFlowOverlay
Traffic-flow lines: every flow’s shape polyline draws as a thick line colored by its segment congestion classification (traffic_congestion_rgba), reusing the route-line thickening machinery with per-segment colors.
WorldSpaceOverlayFrameUniforms
Per-frame uniform of the world-space overlay shader: everything that changes when the camera moves, while WorldSpaceOverlayGeometry stays cached.
WorldSpaceOverlayGeometry
A camera-independent tessellation of the overlay list in normalized world space, ready to be uploaded once and drawn every frame with WorldSpaceOverlayFrameUniforms.
WorldSpaceOverlayVertex
One vertex of the cached world-space overlay layer: ground geometry in normalized-world units relative to WorldSpaceOverlayGeometry’s origin, plus the screen-space parameters the overlay vertex shader expands with the frame uniform’s view-projection, viewport and pixel scale.

DEFAULT_FILLED_POLYGON_RGBA

DEFAULT_POINT_MARKER_RADIUS_PIXELS
Default point-marker radius in screen pixels; the marker is a regular octagon fan of this radius around the projected anchor.
DEFAULT_POINT_MARKER_RGBA
Default point-marker color: opaque red.
DEFAULT_POINT_PIN_RADIUS_PIXELS
Default point-pin head radius in screen pixels; the tip sits the pin’s height below the head center (see [POINT_PIN_HEIGHT_RADIUS_FACTOR]).
DEFAULT_POINT_PIN_RGBA
Default point-pin color: opaque red, the destination-pin hue of the shared reference-app design language’s A/B markers.
DEFAULT_ROUTE_LINE_RGBA
Default route-line color: opaque blue in the leading map SDK’s route hue.
DEFAULT_ROUTE_LINE_WIDTH_PIXELS
Default route-line width in screen pixels, drawn as screen-space-thickened segment quads (constant width regardless of zoom and pitch).
DEFAULT_TRAFFIC_LINE_WIDTH_PIXELS
Default traffic-flow line width in screen pixels; thinner than the route line, since traffic paints many parallel segments.
OVERLAY_TRIANGLE_VERTEX_COUNT
Vertices per triangle of the overlay layer’s flat, non-indexed clip-space triangle stream (overlay_triangle_vertices); the stream’s length divides evenly by this count into the frame’s triangle tally.
TRAFFIC_BLOCKED_RGBA
RGBA of a blocked traffic segment (roadway effectively closed): dark maroon.
TRAFFIC_CONGESTED_RGBA
RGBA of a congested traffic segment (stop-and-go): red.
TRAFFIC_FREE_FLOW_RGBA
RGBA of a free-flowing traffic segment (at or above free-flow speed): green.
TRAFFIC_SLOW_RGBA
RGBA of a slow traffic segment (moderately below free-flow speed): amber.
WORLD_SPACE_OVERLAY_WORLD_COPY_INSTANCES
Number of world-copy instances a world-space overlay frame draws: the camera’s own copy plus two neighbours on each side. The cached tessellation stores each shape anchored within half a world of the layer’s origin, and the frame folds the origin’s own camera copy into the uniform, so the CPU assembly’s window offsets (the camera’s copy and one neighbour either side) map onto copies -2..=2 even when a shape’s first vertex sits in a different copy from the layer origin.
