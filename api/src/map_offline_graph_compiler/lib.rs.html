1//! Offline routing network graph compiler.
2//!
3//! This crate compiles OpenStreetMap (PBF) extracts into the binary
4//! `OfflineRoutingNetworkGraph` archive defined by `PRD.md` §4.6: nodes,
5//! directed edges with encoded speed/road-class/access columns, lane
6//! guidance, instruction strings with lookup indices, and turn restrictions.
7//! It is a maintainer/CI tool, never shipped inside the SDK, and stays
8//! native-only: its `osmpbf` reader is not wasm-viable.
9//!
10//! # Crate split (recorded 2026-10-29, milestone M7 slice 5)
11//!
12//! The archive *format* — reader, writer and the native `mmap` consumption
13//! seam — lives in the wasm-viable `map-offline-graph-archive` crate (see
14//! its crate docs for the container-format decision), because the SDK's
15//! `OfflineRoutingProvider` consumes compiled archives as in-memory bytes on
16//! every target. This crate therefore depends on it and re-exports its
17//! `archive` module for produce-side path stability:
18//!
19//! - it holds the container-format decision and the archive layout docs;
20//! - it carries the native `mmap` reader (`mmap_reader` lives there,
21//!   cfg-gated to non-wasm targets);
22//! - its validating reader answers both the compiler's own fixture
23//!   byte-equality guard and `map-core`'s in-memory and mapped-file load
24//!   paths.
25//!
26//! The compiled fixture and its guarded regeneration seam live in
27//! `tests/common` here; the format itself is unchanged wherever its
28//! modules physically live.
29
