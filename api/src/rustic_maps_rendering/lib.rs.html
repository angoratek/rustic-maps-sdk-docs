1//! GPU map rendering: camera model, raster tile scheduling with parent
2//! fallback and a texture pool, vector-tile styling (fill, line, circle and
3//! symbol layers), overlays, and location indicators.
4//!
5//! The crate separates scene composition from GPU execution. Projection,
6//! camera math, tile scheduling, overlay and label assembly, and the quad
7//! assembly in [`renderer`] are free of `wgpu` types, so they build and run on
8//! every target, including WebAssembly. The native [`headless`] and
9//! [`surface`] renderers consume that composition and submit it to a `wgpu`
10//! device. On WebAssembly the host page drives WebGPU and consumes the same
11//! vertex and style contracts through the wasm bindings.
