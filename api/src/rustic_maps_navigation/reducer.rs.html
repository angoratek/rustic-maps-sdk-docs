1//! The pure event reducer driving an active trip.
2//!
3//! [`reduce_navigation_event`] maps one event onto the previous session and
4//! returns the next one; it has no I/O, no clock and no mutable globals, so
5//! every outcome is reproducible from the event history. The live
6//! [`StepAdvanceCondition`] and [`DeviationDetector`] instances travel through
7//! [`NavigationSession`], pairing state with its decision objects because they
8//! are swapped for their [`StepAdvanceCondition::fresh_instance`] (or
9//! [`DeviationDetector::fresh_instance`]) counterparts at reset points, and the
10//! exported [`crate::state::TripNavigationState`] must stay free of trait
11//! objects.
12//!
13//! # Reducer semantics
14//!
15//! - [`NavigationEvent::StartTrip`] flattens the route and reports the declared
16//!   step values as remaining progress until the first fix arrives.
17//! - [`NavigationEvent::LocationUpdated`] is judged for deviation first:
18//!   a fix the detector grades *fully* off route *freezes* the session — the
19//!   snapped coordinate and progress stay at the last on-route values, and
20//!   neither the step-advance condition is consulted nor the step advances.
21//!   Deviating positions must not drive route progress. A fix graded *off the
22//!   current step but on the route* ([`DeviationGrade::OffStepOnRoute`], a
23//!   projection onto a future step) never freezes on its own: the grade is
24//!   recorded in the state, the trip stays `Navigating` — no reroute request,
25//!   instructions keep counting down — and the fix is then processed normally
26//!   (the step-advance condition reconciles the step; a delayed condition does
27//!   so within the very fix, via the multi-step advance loop below). A fix
28//!   without an accuracy report is not judged at all: it can neither raise nor
29//!   clear a deviation, because one threshold rule cannot conservatively decide
30//!   both directions. A graded fix inside the allowance lifts an active
31//!   deviation (an `OffRoute` trip recovering from the route line, or a
32//!   lingering wrong-step grade clearing) and the update then proceeds normally
33//!   (condition consulted, position snapped, progress recomputed).
34//!   [`crate::state::NavigationPhase::OffRoute`] is therefore a pause the user
35//!   may recover from by returning to the route, not a terminal state.
36//! - **Arrival-aware advance:** the condition consulted for a hop is not always
37//!   the trip's own. Once the remaining steps — counted with the current step
38//!   itself included — shrink to the arrival window
39//!   ([`ARRIVAL_CONDITION_REMAINING_STEPS_BOUND`]), a separately configured
40//!   *arrival* step-advance condition is consulted instead (falling back to the
41//!   trip's own condition when none was configured, which preserves the
42//!   behavior of every trip that has none). Arrival itself is reachable only
43//!   through that final-step verdict: an `Advance` while on the final step
44//!   cannot pop another step — it declares
45//!   [`NavigationPhase::Arrived`] and
46//!   breaks the loop ahead of any further consult, so neither the loop's
47//!   defensive bound nor a still advancing condition can walk past the route's
48//!   end.
49//! - The trip's course-filtering policy stamps an effective course
50//!   ([`TripNavigationState::course_heading_degrees`]) during each processed
51//!   fix's position snap; see [`crate::course_filtering`].
52//! - One fix may advance through *several* steps: after each single-hop advance
53//!   — which swaps in the fresh condition instance — the freshly computed
54//!   inputs decide whether the same fix advances the next hop too. The loop is
55//!   bounded by [`MAXIMUM_STEP_ADVANCES_PER_FIX`] and terminates by
56//!   construction: a hop can end the trip only by arriving, and every other
57//!   break is the condition's `Remain`.
58//! - [`NavigationEvent::RerouteProvided`] rebuilds the session for the same
59//!   trip from a fresh route. Route computation policy lives at the caller's
60//!   event source; the reducer stays policy-free and pure. See the event
61//!   documentation for the route-anchoring contract it implies.
62//! - Updates after the phase is `Arrived` are ignored; reroutes offered to an
63//!   arrived trip are ignored as well.

78/// Defensive ceiling, in steps, on how many hops a single position fix may
79/// advance through in the multi-step advance loop.
80///
81/// The loop's real terminators are the advance condition itself (a `Remain`
82/// verdict ends the walk) and the trip's arrival on the final step, so the
83/// bound is not what makes the loop safe — it exists to guarantee a bounded
84/// response even against a pathological condition that advances on every
85/// consult (any real fix is unboundedly faster than such a condition could
86/// run out of steps). It is set far above any legitimate fix-to-step skip: a
87/// single jump across a 1,000-step route stays well inside it.
88pub const MAXIMUM_STEP_ADVANCES_PER_FIX: usize = 4096;
89
90/// How few steps may remain — counted with the current step itself included —
91/// while the trip consults its separately configured arrival step-advance
92/// condition instead of its ordinary one.
93///
94/// The bound is 2, so the arrival condition governs the final step and the one
95/// before it: arrival decisions deserve their own (typically narrower, more
96/// eager or more pedestrian-calibrated) policy well before the maneuver
97/// point. A trip that declares no arrival condition runs its ordinary condition
98/// to the end (an explicit `None` in the `StartTrip` event).
99pub const ARRIVAL_CONDITION_REMAINING_STEPS_BOUND: usize = 2;

101/// Inputs the reducer accepts for one active trip.
102pub enum NavigationEvent {
103    /// Begin navigating the given route with the given advance strategy.
104    ///
105    /// The condition and the deviation detector are supplied per trip rather
106    /// than through global configuration, so changing either policy is an
107    /// explicit event in the history.
108    StartTrip {
109        /// The route to navigate.
110        route: RouteData,
111        /// The strategy deciding when to move between steps.
112        step_advance_condition: Arc<dyn StepAdvanceCondition>,
113        /// The strategy deciding when to move onto (and complete) the final
114        /// steps, applied inside the arrival window
115        /// ([`ARRIVAL_CONDITION_REMAINING_STEPS_BOUND`]); `None` keeps the
116        /// ordinary condition for every step. Swapped with
117        /// [`StepAdvanceCondition::fresh_instance`] on every advance hop, like
118        /// the ordinary condition.
119        arrival_step_advance_condition: Option<Arc<dyn StepAdvanceCondition>>,
120        /// The policy deciding how the trip's course is reported
121        /// (see [`crate::course_filtering`]).
122        course_filtering: CourseFiltering,
123        /// The strategy deciding when the trip is judged off route.
124        deviation_detector: Arc<dyn DeviationDetector>,
125    },
126    /// Replace the route of the active trip (a reroute).
127    ///
128    /// This event is the caller's answer to a detected deviation — or a
129    /// proactive route swap. The `remote-first, offline-fallback` policy (ask
130    /// a remote router for a replacement route, fall back to an offline
131    /// graph) decides *where* the replacement comes from and lives at the
132    /// integrator/event-source layer; the reducer only applies it, staying
133    /// pure and policy-free.
134    ///
135    /// # Anchoring contract
136    ///
137    /// [`Self::RerouteProvided`] rebuilds the session exactly as
138    /// [`Self::StartTrip`] does, so the replacement route must be authored to
139    /// *begin at the trip's current snapped coordinate* — which is where a
140    /// reroute router anchors its request anyway. The reducer performs no
141    /// trimming or re-ghosting of the new route's geometry; if the anchoring
142    /// contract is violated, the next graded fix will be judged against the
143    /// remaining route line by the deviation detector (and would flag a
144    /// deviation), so a mis-authored reroute is at worst flagged, never
145    /// silently mis-projected.
146    ///
147    /// The replacement advance condition must be fresh from the caller's side;
148    /// the reducer additionally rebuilds it via
149    /// [`StepAdvanceCondition::fresh_instance`] as a defensive reset so a
150    /// mid-schedule instance carried over from the old route cannot corrupt
151    /// the new step sequence (the double-advance contract).
152    RerouteProvided {
153        /// The replacement route, anchored at the current snapped coordinate.
154        route: RouteData,
155        /// The fresh strategy deciding when to move between steps of the new
156        /// route.
157        step_advance_condition: Arc<dyn StepAdvanceCondition>,
158    },
159    /// A new position fix was received while a trip is active.
160    LocationUpdated(
161        /// The fix to judge, snap and evaluate.
162        NavigationLocationUpdate,
163    ),
164}

166/// An active trip: the plain-data state plus the live decision instances.
167///
168/// This pairing (rather than embedding the conditions in the state) is what
169/// keeps [`TripNavigationState`] serializable end to end. A session is not
170/// meant to be shared between threads while it is reduced; pass it by value
171/// from one event to the next.
172#[derive(Clone)]
173pub struct NavigationSession {
174    /// The plain-data record consumers and UI read.
175    pub state: TripNavigationState,
176    /// The condition consulted on the next location update.
177    pub step_advance_condition: Arc<dyn StepAdvanceCondition>,
178    /// The separately configured arrival-window condition, `None` when the
179    /// trip runs its ordinary condition to the end; consulted (instead of
180    /// [`Self::step_advance_condition`]) while the remaining step count is
181    /// within [`ARRIVAL_CONDITION_REMAINING_STEPS_BOUND`].
182    pub arrival_step_advance_condition: Option<Arc<dyn StepAdvanceCondition>>,
183    /// The trip's course-filtering policy (see [`crate::course_filtering`]).
184    pub course_filtering: CourseFiltering,
185    /// The detector consulted on the next location update.
186    pub deviation_detector: Arc<dyn DeviationDetector>,
187}

205/// Reduces one event onto the previous session.
206///
207/// `None` means no trip is active: `LocationUpdated` and `RerouteProvided`
208/// before any `StartTrip` are dropped, and `StartTrip` begins a session.
209/// `LocationUpdated` and `RerouteProvided` on an arrived trip leave the
210/// session untouched.
211///
212/// # Parameters
213/// - `session` — the previous session, or `None` before the trip starts.
214/// - `event` — the event to apply.
215///
216/// # Returns
217/// The next session, or `None` when the event applies to no active trip.
218///
219/// # Panics
220/// The reducer itself does not panic on any input, but a user-supplied
221/// [`StepAdvanceCondition`] or [`DeviationDetector`] that panics propagates
222/// the panic to the caller. The reducer is pure and synchronous: it performs
223/// no I/O, reads no clock and spawns no thread.
224pub fn reduce_navigation_event(
225    session: Option<NavigationSession>,
226    event: NavigationEvent,
227) -> Option<NavigationSession> {
228    match event {
229        NavigationEvent::StartTrip {
230            route,
231            step_advance_condition,
232            arrival_step_advance_condition,
233            course_filtering,
234            deviation_detector,
235        } => Some(NavigationSession {
236            state: build_trip_state(route),
237            // The route has no traversed step yet: both condition instances
238            // and the course policy install as declared (the reducer rebuilds
239            // the *arrival* instance fresh on every advance hop, exactly as
240            // the ordinary one).
241            step_advance_condition,
242            arrival_step_advance_condition,
243            course_filtering,
244            deviation_detector,
245        }),
246        NavigationEvent::RerouteProvided {
247            route,
248            step_advance_condition,
249        } => {
250            let mut session = session?;
251            // An arrived trip ignores reroutes: the destination was reached,
252            // and a replacement route cannot unreach it.
253            if session.state.phase != NavigationPhase::Arrived {
254                session = apply_reroute(session, route, step_advance_condition);
255            }
256            Some(session)
257        }
258        NavigationEvent::LocationUpdated(update) => {
259            let mut session = session?;
260            // An arrived trip keeps its session untouched; navigating and
261            // off-route trips consume fixes (consuming a fix is the only way
262            // an off-route trip recovers).
263            if session.state.phase != NavigationPhase::Arrived {
264                session = process_location_update(session, update);
265            }
266            Some(session)
267        }
268    }
269}

271/// Builds the initial state for a trip, before any location fix.
272///
273/// Shared by [`NavigationEvent::StartTrip`] and
274/// [`NavigationEvent::RerouteProvided`]: both rebuild the trip's route
275/// projection from scratch.
276fn build_trip_state(route: RouteData) -> TripNavigationState {
277    let step_positions = TripNavigationState::build_step_positions(&route);
278    // A route without traversable steps has nothing to navigate; represent
279    // that as an already-arrived trip rather than wedging in `Navigating`.
280    let phase = if step_positions.is_empty() {
281        NavigationPhase::Arrived
282    } else {
283        NavigationPhase::Navigating
284    };
285    let mut state = TripNavigationState {
286        phase,
287        route,
288        step_positions,
289        current_step_position: 0,
290        progress: TripProgress::default(),
291        deviation: None,
292        snapped_coordinate: None,
293        course_heading_degrees: None,
294    };
295    state.progress = compute_progress(&state);
296    state
297}

299/// Rebuilds the session for the same trip from the replacement route onward.
300fn apply_reroute(
301    mut session: NavigationSession,
302    route: RouteData,
303    step_advance_condition: Arc<dyn StepAdvanceCondition>,
304) -> NavigationSession {
305    session.state = build_trip_state(route);
306    // Defensive reset: the caller may hand back a condition instance that was
307    // mid-schedule on the old route (for example the same `Arc` still held in
308    // its own state); a mid-schedule instance would corrupt the new step
309    // sequence (the double-advance contract).
310    session.step_advance_condition = step_advance_condition.fresh_instance();
311    // The arrival-window condition is a trip configuration: it persists
312    // across the route swap, rebuilt fresh for the new step sequence under
313    // the same contract as the ordinary condition and the deviation detector.
314    if let Some(arrival_step_advance_condition) = &session.arrival_step_advance_condition {
315        session.arrival_step_advance_condition =
316            Some(arrival_step_advance_condition.fresh_instance());
317    }
318    // The course-filtering policy likewise persists (it is a trip-level
319    // policy, not a per-route one).
320    // The deviation detector's configuration persists across the route swap,
321    // but its instance is rebuilt so a future stateful detector's tracking
322    // restarts with the new route context (same contract as the condition
323    // swap on advance).
324    session.deviation_detector = session.deviation_detector.fresh_instance();
325    session
326}

328/// Applies one fix to a navigating session: judge deviation, consult, then act.
329fn process_location_update(
330    mut session: NavigationSession,
331    update: NavigationLocationUpdate,
332) -> NavigationSession {
333    // Deviation judgment comes first, and only for fixes carrying an accuracy
334    // report: one threshold rule cannot conservatively decide both raising
335    // and clearing a deviation, so an ungraded fix can do neither (it still
336    // snaps and progresses when the trip is not already off route, as it did
337    // before deviation detection landed).
338    let is_fix_accuracy_graded = update.horizontal_accuracy_meters.is_some();
339    if is_fix_accuracy_graded {
340        let remaining_route_line = remaining_route_line(&session.state);
341        let distance_from_route_meters =
342            snap_coordinate_to_polyline(&update.coordinate, &remaining_route_line).map(
343                |remaining_route_line_snap| remaining_route_line_snap.distance_to_polyline_meters,
344            );
345        // The two-grade judgment's second measurement: the current step's own
346        // polyline, where the remaining route line's closest projection may
347        // not sit (a future-step projection is the "on route, wrong step"
348        // grade's shape).
349        let current_step = session.state.current_step();
350        let distance_from_current_step_meters = current_step.and_then(|current_step| {
351            snap_coordinate_to_polyline(&update.coordinate, &current_step.shape)
352                .map(|current_step_snap| current_step_snap.distance_to_polyline_meters)
353        });
354        let detection_inputs = DeviationDetectionInputs {
355            coordinate: &update.coordinate,
356            horizontal_accuracy_meters: update.horizontal_accuracy_meters,
357            distance_from_route_meters,
358            distance_from_current_step_meters,
359        };
360        match session
361            .deviation_detector
362            .deviation_status(&detection_inputs, &session.state)
363        {
364            // Freeze: the snapped coordinate and progress stay at the last
365            // on-route values, the step does not advance, and the condition
366            // is not consulted (a deviating fix must not drive route
367            // progress). Only the phase and the recorded measurement change.
368            DeviationStatus::OffRoute {
369                deviation_from_route_meters,
370            } => {
371                session.state.phase = NavigationPhase::OffRoute;
372                session.state.deviation = Some(DeviationInfo {
373                    grade: DeviationGrade::FullyOffRoute,
374                    deviation_from_route_meters,
375                });
376                return session;
377            }
378            // On route, wrong step: the trip never freezes on this grade —
379            // record it and process the fix normally below (a frozen trip the
380            // grade recovers lifts the freeze here).
381            DeviationStatus::OffStepOnRoute {
382                deviation_from_route_meters,
383            } => {
384                session.state.deviation = Some(DeviationInfo {
385                    grade: DeviationGrade::OffStepOnRoute,
386                    deviation_from_route_meters,
387                });
388                session.state.phase = NavigationPhase::Navigating;
389            }
390            // Fully on route: an active full deviation lifts (recovery), a
391            // lingering wrong-step grade clears.
392            DeviationStatus::OnRoute => {
393                session.state.deviation = None;
394                session.state.phase = NavigationPhase::Navigating;
395            }
396        }
397    } else if session.state.phase == NavigationPhase::OffRoute {
398        // Reaching this point on an off-route trip means an ungraded fix: it
399        // can neither raise nor clear the judgment, so the deviation holds
400        // and the session stays frozen. (A graded fix within the allowance
401        // — or graded onto a future step — has already lifted the freeze
402        // above.)
403        return session;
404    }
405
406    // The multi-step advance loop (the reference's speed-run semantics): the
407    // same fix is re-consulted — with freshly computed inputs — after every
408    // single-hop advance, until the condition says to remain or the trip
409    // arrives. Iterative, never recursive, and bounded by
410    // `MAXIMUM_STEP_ADVANCES_PER_FIX` as a defensive ceiling.
411    let mut applied_advances = 0_usize;
412    loop {
413        let decision = {
414            let state = &session.state;
415            // The caller guarantees the phase is `Navigating` with a traversal
416            // built from the route, so the current step always resolves.
417            #[allow(clippy::expect_used)]
418            // internal invariant, upheld by the caller contract (documented above)
419            let current_step = state
420                .current_step()
421                .expect("navigating session must always have a current step");
422            let snap = snap_coordinate_to_polyline(&update.coordinate, &current_step.shape);
423            // Straight-line distance from the raw fix to the maneuver point,
424            // mirroring Ferrostar's eager condition which measures the raw
425            // location, while progress (below) measures the snapped position.
426            let distance_to_end_of_step_meters =
427                current_step.shape.last().map(|terminal_coordinate| {
428                    update
429                        .coordinate
430                        .haversine_distance_meters(terminal_coordinate)
431                });
432            let distance_from_step_meters = snap
433                .as_ref()
434                .map(|snapped| snapped.distance_to_polyline_meters);
435            let inputs = StepAdvanceInputs {
436                coordinate: &update.coordinate,
437                horizontal_accuracy_meters: update.horizontal_accuracy_meters,
438                current_step,
439                next_step: state.step_at(state.current_step_position + 1),
440                snapped_coordinate: snap.as_ref().map(|snapped| &snapped.snapped_coordinate),
441                distance_to_end_of_step_meters,
442                distance_from_step_meters,
443            };
444            // The arrival-aware condition selection: inside the arrival
445            // window the separately configured arrival condition decides the
446            // hop (falling back to the ordinary condition without one).
447            let consulted_condition = if remaining_steps_within_arrival_window(state) {
448                session
449                    .arrival_step_advance_condition
450                    .as_ref()
451                    .cloned()
452                    .unwrap_or_else(|| Arc::clone(&session.step_advance_condition))
453            } else {
454                Arc::clone(&session.step_advance_condition)
455            };
456            consulted_condition.should_advance_step(&inputs, state)
457        };
458
459        if decision != StepAdvanceDecision::Advance {
460            break;
461        }
462        if session.state.is_on_final_step() {
463            session.state.phase = NavigationPhase::Arrived;
464            break;
465        }
466        session.state.current_step_position += 1;
467        // Each hop swaps in the fresh condition instance exactly as the
468        // single-advance slice did: a stale instance's internal progress can
469        // never leak from one step into the next (the double-advance
470        // contract). The arrival-window condition, when configured, is
471        // swapped under the same contract.
472        session.step_advance_condition = session.step_advance_condition.fresh_instance();
473        if let Some(arrival_step_advance_condition) = &session.arrival_step_advance_condition {
474            session.arrival_step_advance_condition =
475                Some(arrival_step_advance_condition.fresh_instance());
476        }
477        applied_advances += 1;
478        if applied_advances >= MAXIMUM_STEP_ADVANCES_PER_FIX {
479            break;
480        }
481    }
482    session.state = apply_location_to_state(session.state, &update, session.course_filtering);
483    session
484}

486/// Whether the trip's remaining steps — the current one itself included — sit
487/// inside the arrival window: the separately configured arrival condition
488/// governs these steps.
489fn remaining_steps_within_arrival_window(state: &TripNavigationState) -> bool {
490    state.step_positions.len() - state.current_step_position
491        <= ARRIVAL_CONDITION_REMAINING_STEPS_BOUND
492}

494/// The polyline of the route remaining from the current step onward: the
495/// current step's shape plus every following step's shape, in traversal order.
496///
497/// Deviation is measured against this line rather than only the current step:
498/// a lagging step — eager advance semantics, pauses at intersections — is then
499/// never mistaken for a deviation. Consecutive steps may repeat their shared boundary coordinate,
500/// which degenerates to a zero-length segment the snapping projection already
501/// treats as a point.
502fn remaining_route_line(state: &TripNavigationState) -> Vec<GeographicCoordinate> {
503    let mut remaining_route_line = Vec::new();
504    for step_position in state
505        .step_positions
506        .iter()
507        .skip(state.current_step_position)
508    {
509        if let Some(step) = state.step_for_position(step_position) {
510            remaining_route_line.extend_from_slice(&step.shape);
511        }
512    }
513    remaining_route_line
514}

516/// Snaps the fix onto the current step and recomputes progress from it.
517///
518/// When the current step's shape carries no geometry, snapping is impossible;
519/// the previous snapped position is retained so the progress projection
520/// degrades continuously instead of flickering. The trip's effective course
521/// is stamped from the same decision: the fix's snap under the trip's
522/// course-filtering policy ([`effective_course_heading_degrees`]).
523fn apply_location_to_state(
524    mut state: TripNavigationState,
525    update: &NavigationLocationUpdate,
526    course_filtering: CourseFiltering,
527) -> TripNavigationState {
528    let snapped = state.current_step().and_then(|current_step| {
529        snap_coordinate_to_polyline(&update.coordinate, &current_step.shape)
530    });
531    state.snapped_coordinate = snapped
532        .as_ref()
533        .map(|snapped| snapped.snapped_coordinate)
534        .or(state.snapped_coordinate);
535    state.course_heading_degrees = effective_course_heading_degrees(
536        course_filtering,
537        update.course_heading_degrees,
538        snapped.as_ref().and_then(|snapped| snapped.bearing_degrees),
539        state.course_heading_degrees,
540    );
541    state.progress = compute_progress(&state);
542    state
543}

545/// Recomputes [`TripProgress`] for the state's current step.
546///
547/// `distance_to_next_maneuver_meters` measures the snapped position against
548/// the step's terminal coordinate; without a snap it
549/// falls back to the provider-declared step distance. The remaining total
550/// adds the provider-declared distances and durations of the steps after the
551/// current one, and the current step's remaining duration is scaled linearly
552/// along the step — an approximation, since providers do not distribute speed
553/// uniformly within a step.
554fn compute_progress(state: &TripNavigationState) -> TripProgress {
555    if state.phase == NavigationPhase::Arrived {
556        return TripProgress::default();
557    }
558    let Some(current_step) = state.current_step() else {
559        return TripProgress::default();
560    };
561
562    let distance_to_next_maneuver_meters = match state.snapped_coordinate {
563        Some(snapped_coordinate) => current_step
564            .shape
565            .last()
566            .map(|terminal_coordinate| {
567                snapped_coordinate.haversine_distance_meters(terminal_coordinate)
568            })
569            .unwrap_or(current_step.distance_meters),
570        None => current_step.distance_meters,
571    };
572    let traveled_fraction = if current_step.distance_meters > 0.0 {
573        // Structural fraction of the step left to walk; a snap is inside the
574        // step geometry, and the clamp keeps noisy declared totals honest.
575        (distance_to_next_maneuver_meters / current_step.distance_meters).clamp(0.0, 1.0)
576    } else {
577        // A zero-distance step is instantaneously complete.
578        1.0
579    };
580    let duration_to_next_maneuver_seconds = current_step.duration_seconds * traveled_fraction;
581
582    let distance_remaining_meters = distance_to_next_maneuver_meters
583        + following_declared_distance_meters(state, state.current_step_position);
584    let duration_remaining_seconds = duration_to_next_maneuver_seconds
585        + following_declared_duration_seconds(state, state.current_step_position);
586
587    TripProgress {
588        distance_to_next_maneuver_meters,
589        distance_remaining_meters,
590        duration_remaining_seconds,
591    }
592}
593
594/// Sums the provider-declared distances of the steps after `from_position`.
595fn following_declared_distance_meters(state: &TripNavigationState, from_position: usize) -> f64 {
596    state
597        .step_positions
598        .iter()
599        .enumerate()
600        .filter(|(position, _)| *position > from_position)
601        .filter_map(|(_, step_position)| state.step_for_position(step_position))
602        .map(|step| step.distance_meters)
603        .sum()
604}
605
606/// Sums the provider-declared durations of the steps after `from_position`.
607fn following_declared_duration_seconds(state: &TripNavigationState, from_position: usize) -> f64 {
608    state
609        .step_positions
610        .iter()
611        .enumerate()
612        .filter(|(position, _)| *position > from_position)
613        .filter_map(|(_, step_position)| state.step_for_position(step_position))
614        .map(|step| step.duration_seconds)
615        .sum()
616}
