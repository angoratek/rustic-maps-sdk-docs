1//! Frame-driven raster tile scheduling with parent fallback.
2//!
3//! Each frame the scheduler receives the XYZ tiles the camera needs (usually
4//! from [`crate::projection::tiles_covering`] on the camera footprint). For
5//! every requested tile it reports one readiness:
6//!
7//! * `Present` — pooled at the requested zoom;
8//! * `FallsBackTo` — a nearest pooled ancestor stands in while the detailed
9//!   tile loads or while its fetch failed, so the map blurs instead of
10//!   flashing holes;
11//! * `Unavailable` — the provider rejected the tile this frame; a later frame
12//!   may retry.
13//!
14//! Fetches are deduplicated within a frame (one provider call per distinct
15//! tile), ordered most-detailed-first, and capped by the configured per-frame
16//! fetch budget; requests beyond the cap report `Deferred`. Fetch overlap
17//! with GPU work and eviction-aware prioritization
18//! are deferred until the render loop measures upload timing.
19//!
20//! # The idle render-state signal
21//!
22//! GL JS's `idle` event fires when no more tile loads and no animation work
23//! remain — the condition golden-image tests await before capturing, so a
24//! capture can never race a late fetch. This module exposes the equivalent
25//! render-state queries: [`TileScheduler::is_idle`] over the fetch state, and
26//! [`prepared_frame_is_idle`] over a captured frame's readiness verdicts.
27//!
28//! What counts as pending is stated over the fetch state, because the
29//! scheduler itself is frame-driven: [`TileScheduler::prepare_frame`] awaits
30//! every fetch it issues, so a fetch is never observable through this API
31//! mid-flight. The pending states are therefore exactly the readiness
32//! verdicts whose pixels a later successful frame can still change:
33//!
34//! * `Deferred` — the fetch budget spent; a later frame fetches the tile.
35//! * `Unavailable` — the provider rejected the tile; a later frame retries
36//!   it.
37//! * `FallsBackTo` — a coarser ancestor covers the area while the detailed
38//!   tile loads or its fetch failed; when the fetch lands, the area re-renders
39//!   at its own detail level.
40//!
41//! A frame is idle when every requested tile resolved `Present`: no
42//! scheduled work can change its pixels. An empty request set is idle by
43//! vacuity. Idle is a *query*, not an event: it can flip back to pending
44//! when the pool loses a requested payload — least-recently-used budget
45//! pressure, or the renderer evicting an undecodable payload after a draw —
46//! until the next prepare frame refetches it.
47//!
48//! Explicitly not part of the verdict: camera animations
49//! (`crate::camera::CameraAnimation`), which are composed entirely outside
50//! the renderer; GPU upload state, which never spans calls on the headless
51//! render path (uploads happen synchronously inside one frame render; the
52//! wasm canvas, in contrast, keeps browser fetches in flight across a render
53//! frame — the mirror of this signal there is deferred to the canvas slice);
54//! and evictions of payloads the current request set does not ask for.
55//!
56//! # The sync resolve / detached warm split
57//!
58//! The frame path never awaits the network: [`TileScheduler::resolve_frame`]
59//! answers every requested tile's readiness from the pool's current state
60//! alone (plus the in-flight warming set it reports as `Deferred`), purely
61//! synchronously, and the misses are fetched by [`TileScheduler::warm_tiles`]
62//! (or its detached twin [`TileScheduler::plan_warm_tiles`], whose
63//! [`TileWarmTask`] runs on the caller's background runtime) so detail
64//! arrives in a later frame. The blocking [`TileScheduler::prepare_frame`]
65//! remains the await-everything reference behavior the tests and goldens
66//! pin; the split's verdicts are the same taxonomy over the same pool.
67//!
68//! The diagnostics: per-frame resolve and warm events emit at Debug and
69//! per-tile fetch events at Trace under the `tile_fetch` target, behind the
70//! diagnostics severity gate (see `map-native-core`'s diagnostics module).

85/// How a requested tile resolves for one frame.
86#[derive(Debug, Clone, Copy, PartialEq, Eq)]
87pub enum TileReadiness {
88    /// Pooled at the requested zoom level.
89    Present,
90    /// Not pooled; the stated ancestor tile shows the same area at lower
91    /// detail while this tile is fetched or was rejected.
92    FallsBackTo {
93        /// Address of the pooled ancestor tile.
94        fallback_tile_key: TileKey,
95        /// Zoom levels between the requested tile and its fallback.
96        zoom_level_difference: u16,
97    },
98    /// The provider rejected the tile this frame.
99    Unavailable,
100    /// Left for a later frame because the per-frame fetch budget was spent.
101    Deferred,
102}

106pub struct PreparedTile {
107    /// The tile the camera asked for.
108    pub requested_tile_key: TileKey,
109    /// How the scheduler resolved it.
110    pub readiness: TileReadiness,
111}

113/// Schedules raster tile fetches into a [`TileTexturePool`].
114pub struct TileScheduler {
115    tile_provider: Arc<dyn RasterTileProvider>,
116    texture_pool: TileTexturePool,
117    requested_image_format: RasterImageFormat,
118    requested_tile_resolution: RasterTileResolution,
119    maximum_fetches_per_frame: usize,
120    /// The shared registry of this scheduler's in-flight background warm
121    /// tasks (see [`Self::plan_warm_tiles`]); resolve_frame reports its
122    /// tiles as `Deferred` and drains its deliveries into the pool.
123    warm_fetch_registry: Arc<WarmFetchRegistry>,
124    /// The receiving half of the warm tasks' delivery channel; only the
125    /// scheduler takes outcomes from it.
126    warm_delivery_receiver: Receiver<WarmFetchOutcome>,

129/// One background warm fetch's outcome, delivered back to the scheduler: the
130/// pool payload on success, `None` on a provider failure (the tile stays
131/// missing; later resolves keep reporting its ancestor or `Unavailable`).
132struct WarmFetchOutcome {
133    tile_key: TileKey,
134    delivered_payload: Option<Vec<u8>>,
135}

137/// The shared in-flight state between a scheduler and its detached warm
138/// tasks: the warming set every resolver reads (it decides the `Deferred`
139/// verdicts), and the delivery channel the tasks' fetch outcomes flow
140/// through. Locks stay inside short set operations — never across an await.
141struct WarmFetchRegistry {
142    warming_tile_keys: Mutex<HashSet<TileKey>>,
143    delivery_sender: Sender<WarmFetchOutcome>,
144    /// Monotonic count of payloads a warm task delivered to the pool: the
145    /// change signal a redraw pump reads to resume a settled view (the
146    /// `on_tiles_arrived` counter of the idle-settled discipline).
147    delivered_tiles_counter: AtomicU64,
148}
149
150impl WarmFetchRegistry {
151    /// Reports whether a tile is currently being warmed in the background.
152    fn is_warming(&self, tile_key: &TileKey) -> bool {
153        self.warming_tile_keys
154            .lock()
155            .expect("the warming set lock is not poisoned")
156            .contains(tile_key)
157    }
158
159    /// Marks tiles as in-flight warm fetches.
160    fn mark_warming(&self, tile_keys: &[TileKey]) {
161        let mut warming_tile_keys = self
162            .warming_tile_keys
163            .lock()
164            .expect("the warming set lock is not poisoned");
165        warming_tile_keys.extend(tile_keys.iter().copied());
166    }
167
168    /// Clears one tile's in-flight flag (the scheduler does this when it
169    /// drains the fetch's delivery).
170    fn unmark_warming(&self, tile_key: &TileKey) {
171        self.warming_tile_keys
172            .lock()
173            .expect("the warming set lock is not poisoned")
174            .remove(tile_key);
175    }
176
177    /// The warm tasks' delivered-payments counter.
178    fn delivered_tile_count(&self) -> u64 {
179        self.delivered_tiles_counter.load(Ordering::Relaxed)
180    }
181}

183impl TileScheduler {
184    /// Builds a scheduler reading tiles from the provider into the pool at
185    /// the requested image format and pixel resolution.
186    pub fn new(
187        tile_provider: Arc<dyn RasterTileProvider>,
188        texture_pool: TileTexturePool,
189        requested_image_format: RasterImageFormat,
190        requested_tile_resolution: RasterTileResolution,
191        maximum_fetches_per_frame: usize,
192    ) -> Self {
193        let (delivery_sender, delivery_receiver) = channel();
194        Self {
195            tile_provider,
196            texture_pool,
197            requested_image_format,
198            requested_tile_resolution,
199            maximum_fetches_per_frame,
200            warm_fetch_registry: Arc::new(WarmFetchRegistry {
201                warming_tile_keys: Mutex::new(HashSet::new()),
202                delivery_sender,
203                delivered_tiles_counter: AtomicU64::new(0),
204            }),
205            warm_delivery_receiver: delivery_receiver,
206        }
207    }

209    /// Read-only access to the pool (recency is not touched).
210    pub fn texture_pool(&self) -> &TileTexturePool {
211        &self.texture_pool
212    }

214    /// The idle render-state signal over a request set: whether no pending
215    /// tile work remains, judged against the pool's current contents — every
216    /// distinct requested tile sits pooled at its own zoom level. This is the
217    /// fetch-state half of GL JS's `idle` event (see the module
218    /// documentation for the full semantics).
219    ///
220    /// Compared with [`Self::prepare_frame`], which fetches misses, this
221    /// query never fetches: it answers from the state a previous prepare
222    /// frame left behind, or from a pool the caller filled directly.
223    /// It reports false for a budget-deferred tile mid-fetch, for a tile
224    /// whose fetch failed, and for a tile relying on a parent fallback, and
225    /// it flips back to pending when the pool loses a requested payload.
226    pub fn is_idle(&self, requested_tiles: &[TileKey]) -> bool {
227        requested_tiles
228            .iter()
229            .all(|tile_key| self.texture_pool.contains(tile_key))
230    }
231
232    /// Borrows the pool mutably, e.g. for a renderer to upload and drain it.
233    pub fn texture_pool_mut(&mut self) -> &mut TileTexturePool {
234        &mut self.texture_pool
235    }

237    /// A snapshot of the tiles with warm fetches in flight (see
238    /// [`Self::plan_warm_tiles`]): the set a prefetch planner deduplicates
239    /// its own request list against, so in-flight fetches neither reappear
240    /// in the plan nor consume its priority slots.
241    pub fn warming_tile_keys(&self) -> std::collections::HashSet<TileKey> {
242        self.warm_fetch_registry
243            .warming_tile_keys
244            .lock()
245            .expect("the warming set lock is not poisoned")
246            .clone()
247    }

249    /// The number of payloads this scheduler's background warm tasks have
250    /// delivered into the pool: the `on_tiles_arrived` counter of the
251    /// idle-settled redraw discipline (see the module documentation), which
252    /// a pump pairs with [`Self::is_idle`] and the frame verdicts to resume
253    /// a settled view when pending detail arrives.
254    pub fn delivered_warm_tile_count(&self) -> u64 {
255        self.warm_fetch_registry.delivered_tile_count()
256    }

258    /// Resolves every requested tile's readiness for one frame from the
259    /// pool's current state alone — the await-free half of the frame path
260    /// (see the module documentation): purely synchronous, GPU-free, and
261    /// never touching the provider, so an uncovered camera pose reports its
262    /// fallback verdicts immediately instead of stalling the frame on the
263    /// network. Completed background warm deliveries (see
264    /// [`Self::plan_warm_tiles`]) drain into the pool first, so the freshest
265    /// fetched detail resolves into this frame.
266    ///
267    /// Duplicate requests keep one verdict per request (deduplication is a
268    /// fetch concern, not a display one — the renderer draws per request).
269    pub fn resolve_frame(&mut self, requested_tiles: &[TileKey]) -> Vec<PreparedTile> {
270        self.drain_warm_fetch_deliveries();
271        tracing::debug!(
272            target: TILE_FETCH_TRACING_TARGET,
273            requested_tile_count = requested_tiles.len(),
274            pooled_tile_count = requested_tiles
275                .iter()
276                .filter(|tile_key| self.texture_pool.contains(tile_key))
277                .count(),
278            "resolve_frame answered from pool state"
279        );
280        requested_tiles
281            .iter()
282            .map(|tile_key| PreparedTile {
283                requested_tile_key: *tile_key,
284                readiness: self.resolve_readiness(tile_key, &[]),
285            })
286            .collect()
287    }

289    /// Fetches the requested tiles' pooled misses — the awaited half of the
290    /// frame path: deduplication, the most-detailed-first order and the
291    /// per-call budget (see the module documentation), with the fetches'
292    /// outcomes delivering through the shared registry whose
293    /// [`Self::resolve_frame`] drains them into the pool. Designed for
294    /// callers that await (tests, the blocking reference path); a frame path
295    /// that must not block plans the detached twin with
296    /// [`Self::plan_warm_tiles`] and runs it on its own background task.
297    /// Returns the number of fetches the call issued.
298    pub async fn warm_tiles(&mut self, requested_tiles: &[TileKey]) -> usize {
299        let warm_task = self.plan_warm_tiles(requested_tiles);
300        let fetch_count = warm_task.run().await;
301        self.drain_warm_fetch_deliveries();
302        fetch_count
303    }
304
305    /// Plans a detached warm fetch of the requested tiles' pooled misses:
306    /// the owned [`TileWarmTask`] to run on a background runtime (fire and
307    /// forget — the frame path never awaits it). The plan marks its tiles
308    /// in the shared registry, so every [`Self::resolve_frame`] until the
309    /// delivery drains reports them `Deferred` (the pixels may change when
310    /// the detail arrives), and the task's outcomes deliver back through
311    /// the scheduler's channel. Returns a task fetching nothing when
312    /// nothing needs warming.
313    pub fn plan_warm_tiles(&mut self, requested_tiles: &[TileKey]) -> TileWarmTask {
314        self.drain_warm_fetch_deliveries();
315        let unique_warm_candidates: Vec<TileKey> = {
316            let mut seen_tiles = HashSet::new();
317            requested_tiles
318                .iter()
319                .copied()
320                .filter(|tile_key| seen_tiles.insert(*tile_key))
321                .filter(|tile_key| !self.texture_pool.contains(tile_key))
322                .filter(|tile_key| !self.warm_fetch_registry.is_warming(tile_key))
323                .collect()
324        };
325        // Most-detailed tiles first: detail arriving last would keep the map
326        // visibly blurry for the whole warm pass. Stable within a zoom level
327        // so callers keep their own input priority order.
328        let mut warm_candidates = unique_warm_candidates;
329        warm_candidates.sort_by_key(|tile_key| std::cmp::Reverse(tile_key.zoom_level));
330        let fetch_budget = self.maximum_fetches_per_frame.min(warm_candidates.len());
331        let fetch_tile_keys = warm_candidates[..fetch_budget].to_vec();
332        self.warm_fetch_registry.mark_warming(&fetch_tile_keys);
333        tracing::debug!(
334            target: TILE_FETCH_TRACING_TARGET,
335            planned_fetch_count = fetch_tile_keys.len(),
336            deferred_candidate_count = warm_candidates.len() - fetch_tile_keys.len(),
337            "warm pass planned"
338        );
339        TileWarmTask {
340            tile_provider: Arc::clone(&self.tile_provider),
341            requested_image_format: self.requested_image_format,
342            requested_tile_resolution: self.requested_tile_resolution,
343            fetch_tile_keys,
344            warm_fetch_registry: Arc::clone(&self.warm_fetch_registry),
345        }
346    }
347
348    /// Moves completed warm tasks' fetch outcomes into the pool (clearing
349    /// their in-flight flags): every finished fetch's payload becomes
350    /// available to this and later frames. Returns the number of delivered
351    /// payloads.
352    fn drain_warm_fetch_deliveries(&mut self) -> usize {
353        let mut delivered_count = 0;
354        while let Ok(warm_fetch_outcome) = self.warm_delivery_receiver.try_recv() {
355            self.warm_fetch_registry
356                .unmark_warming(&warm_fetch_outcome.tile_key);
357            if let Some(delivered_payload) = warm_fetch_outcome.delivered_payload {
358                self.texture_pool
359                    .insert(warm_fetch_outcome.tile_key, delivered_payload);
360                delivered_count += 1;
361            }
362        }
363        delivered_count
364    }

366    /// Resolves every requested tile for this frame, fetching misses.
367    ///
368    /// Duplicate requests appear once per request in the returned frame but
369    /// cost one fetch. The pool is consulted before fetching so pooled
370    /// ancestors serve as fallbacks immediately.
371    ///
372    /// The blocking reference path (see the module documentation): every
373    /// fetch it issues is awaited inside the call, so a never-covered camera
374    /// pose costs the network through this method — the split's
375    /// [`Self::resolve_frame`] + [`Self::warm_tiles`]/[`Self::plan_warm_tiles`]
376    /// never does. Completed detached warm deliveries drain first, so a
377    /// background fetch's payload lands in the pool before this frame would
378    /// refetch it; in-flight warming tiles are left to their own tasks
379    /// rather than double-fetched.
380    pub async fn prepare_frame(&mut self, requested_tiles: &[TileKey]) -> Vec<PreparedTile> {
381        self.drain_warm_fetch_deliveries();
382        let unique_requested_tiles: Vec<TileKey> = {
383            let mut seen_tiles = HashSet::new();
384            requested_tiles
385                .iter()
386                .copied()
387                .filter(|tile_key| seen_tiles.insert(*tile_key))
388                .collect()
389        };
390
391        let mut fetch_candidates = unique_requested_tiles
392            .iter()
393            .copied()
394            .filter(|tile_key| !self.texture_pool.contains(tile_key))
395            .filter(|tile_key| !self.warm_fetch_registry.is_warming(tile_key))
396            .collect::<Vec<TileKey>>();
397        // Most-detailed tiles first: detail arriving last would keep the map
398        // visibly blurry for the whole frame. Stable within a zoom level so
399        // callers keep their own input priority order.
400        fetch_candidates.sort_by_key(|tile_key| std::cmp::Reverse(tile_key.zoom_level));
401
402        let fetch_budget = self.maximum_fetches_per_frame.min(fetch_candidates.len());
403        for tile_key in &fetch_candidates[..fetch_budget] {
404            tracing::trace!(
405                target: TILE_FETCH_TRACING_TARGET,
406                zoom_level = tile_key.zoom_level,
407                tile_x = tile_key.tile_x,
408                tile_y = tile_key.tile_y,
409                "prepare_frame tile fetch issued"
410            );
411            match self
412                .tile_provider
413                .fetch_raster_tile(
414                    tile_key.tile_x,
415                    tile_key.tile_y,
416                    tile_key.zoom_level,
417                    self.requested_image_format,
418                    self.requested_tile_resolution,
419                )
420                .await
421            {
422                Ok(fetched_tile) => {
423                    self.texture_pool
424                        .insert(*tile_key, fetched_tile.image_bytes);
425                }
426                Err(error) => {
427                    // Provider failures are surfaced per-tile; the frame keeps
428                    // resolving so fallbacks can cover the gap.
429                    let _ = error;
430                }
431            }
432        }
433
434        requested_tiles
435            .iter()
436            .copied()
437            .map(|tile_key| PreparedTile {
438                requested_tile_key: tile_key,
439                readiness: self.resolve_readiness(&tile_key, &fetch_candidates[fetch_budget..]),
440            })
441            .collect()
442    }
443
444    fn resolve_readiness(
445        &self,
446        requested_tile_key: &TileKey,
447        deferred_tiles: &[TileKey],
448    ) -> TileReadiness {
449        if self.texture_pool.contains(requested_tile_key) {
450            return TileReadiness::Present;
451        }
452        if self.warm_fetch_registry.is_warming(requested_tile_key) {
453            return TileReadiness::Deferred;
454        }
455        if deferred_tiles.contains(requested_tile_key) {
456            return TileReadiness::Deferred;
457        }
458        // Nearest pooled ancestor stands in while this tile loads or failed.
459        let mut ancestor_tile_key = requested_tile_key.parent_tile_key();
460        let mut zoom_level_difference: u16 = 1;
461        while let Some(candidate) = ancestor_tile_key {
462            if self.texture_pool.contains(&candidate) {
463                return TileReadiness::FallsBackTo {
464                    fallback_tile_key: candidate,
465                    zoom_level_difference,
466                };
467            }
468            zoom_level_difference += 1;
469            ancestor_tile_key = candidate.parent_tile_key();
470        }
471        TileReadiness::Unavailable
472    }
473}

475/// One planned detached warm fetch: the owned inputs (the provider handle,
476/// the request formats) plus the shared in-flight registry, runnable as its
477/// own background task. Built by [`TileScheduler::plan_warm_tiles`]; the
478/// frame path runs it fire-and-forget so no draw ever awaits the network
479/// (see the module documentation).
480pub struct TileWarmTask {
481    tile_provider: Arc<dyn RasterTileProvider>,
482    requested_image_format: RasterImageFormat,
483    requested_tile_resolution: RasterTileResolution,
484    /// The deduplicated, most-detailed-first, budget-capped misses to fetch.
485    fetch_tile_keys: Vec<TileKey>,
486    warm_fetch_registry: Arc<WarmFetchRegistry>,
487}

489/// The panic guard of [`TileWarmTask::run`]: it holds the not-yet-delivered
490/// planned keys, and its `Drop` clears every one of them from the warming
491/// set — so a task that unwinds mid-fetch (or is cancelled because its
492/// runtime dropped the future) cannot leave stale in-flight marks in the
493/// registry, which would otherwise report those tiles `Deferred` forever and
494/// double-fetch nothing in later warm passes. Delivered keys are removed from
495/// the owned list before (or regardless of) the guard's drop, and the
496/// registry's own drain clears each delivered key at resolve.
497struct WarmTaskUnwindGuard {
498    warm_fetch_registry: Arc<WarmFetchRegistry>,
499    remaining_tile_keys: Vec<TileKey>,
500}
501
502impl Drop for WarmTaskUnwindGuard {
503    fn drop(&mut self) {
504        let mut warming_tile_keys = self
505            .warm_fetch_registry
506            .warming_tile_keys
507            .lock()
508            .expect("the warming set lock is not poisoned");
509        for tile_key in &self.remaining_tile_keys {
510            warming_tile_keys.remove(tile_key);
511        }
512    }
513}
514
515impl TileWarmTask {
516    /// The planned fetches' count (an empty task fetches nothing).
517    pub fn fetch_count(&self) -> usize {
518        self.fetch_tile_keys.len()
519    }
520
521    /// Runs the planned fetches to completion, delivering every outcome —
522    /// payload or provider failure — back to the scheduler's channel, and
523    /// returns the number of payloads delivered. The fetch loop is serial
524    /// (one provider call awaited at a time, mirroring
525    /// `TileScheduler::prepare_frame`'s budget behavior); the scheduler
526    /// drains the deliveries into its pool at its next resolve. The unwind
527    /// guard (see [`WarmTaskUnwindGuard`]) keeps a dropped or panicking run
528    /// from stranding stale warming marks.
529    pub async fn run(self) -> usize {
530        let mut unwind_guard = WarmTaskUnwindGuard {
531            warm_fetch_registry: Arc::clone(&self.warm_fetch_registry),
532            remaining_tile_keys: self.fetch_tile_keys,
533        };
534        let mut delivered_count = 0;
535        while let Some(tile_key) = unwind_guard.remaining_tile_keys.first().copied() {
536            tracing::trace!(
537                target: TILE_FETCH_TRACING_TARGET,
538                zoom_level = tile_key.zoom_level,
539                tile_x = tile_key.tile_x,
540                tile_y = tile_key.tile_y,
541                "detached warm tile fetch issued"
542            );
543            let delivered_payload = match self
544                .tile_provider
545                .fetch_raster_tile(
546                    tile_key.tile_x,
547                    tile_key.tile_y,
548                    tile_key.zoom_level,
549                    self.requested_image_format,
550                    self.requested_tile_resolution,
551                )
552                .await
553            {
554                Ok(fetched_tile) => {
555                    self.warm_fetch_registry
556                        .delivered_tiles_counter
557                        .fetch_add(1, Ordering::Relaxed);
558                    delivered_count += 1;
559                    Some(fetched_tile.image_bytes)
560                }
561                Err(_fetch_error) => {
562                    // Provider failures surface per-tile: the delivery's
563                    // None payload keeps the tile missing and the verdicts
564                    // honest, leaving the retry to a later warm pass.
565                    tracing::trace!(
566                        target: TILE_FETCH_TRACING_TARGET,
567                        zoom_level = tile_key.zoom_level,
568                        tile_x = tile_key.tile_x,
569                        tile_y = tile_key.tile_y,
570                        "detached warm tile fetch failed"
571                    );
572                    None
573                }
574            };
575            let _ = self
576                .warm_fetch_registry
577                .delivery_sender
578                .send(WarmFetchOutcome {
579                    tile_key,
580                    delivered_payload,
581                });
582            unwind_guard.remaining_tile_keys.remove(0);
583        }
584        delivered_count
585    }

588/// The idle render-state signal over a captured frame's readiness verdicts:
589/// whether every requested tile of the frame resolved `Present` at its own
590/// zoom level. The verdict-level twin of [`TileScheduler::is_idle`], kept
591/// GPU-free so callers (golden tests, the idle-gated snapshot of
592/// [`crate::headless`]) can assert determinism before any capture.
593///
594/// The two forms agree for a frame checked immediately after the
595/// `prepare_frame` that produced it; they can diverge only if the pool
596/// changed in between — an eviction leaves the recorded verdicts resolved
597/// while `is_idle` reports pending again. The verdict form is exactly the
598/// gate a deterministic capture needs at capture time; the pool form is what
599/// a caller re-checks before a later frame.
600pub fn prepared_frame_is_idle(prepared_tiles: &[PreparedTile]) -> bool {
601    prepared_tiles
602        .iter()
603        .all(|prepared_tile| prepared_tile.readiness == TileReadiness::Present)
604}

641        ) -> Arc<Self> {
642            Arc::new(Self {

650                                .map(|tile_key| (tile_key, Err("unroutable".to_string()))),

652                        .collect(),
653                ),
654                requested_tiles: Mutex::new(Vec::new()),
655            })
656        }

665        async fn fetch_raster_tile(
666            &self,
667            tile_x: u32,
668            tile_y: u32,
669            zoom_level: u8,
670            _image_format: RasterImageFormat,
671            _tile_resolution: RasterTileResolution,
672        ) -> Result<RasterTileData, SDKError> {

691                    image_bytes,
692                }),
693                Some(Err(detail)) => Err(SDKError::NetworkRequestFailed(detail)),
694                None => Err(SDKError::ResponseParsingFailure(
695                    "tile not scripted".to_string(),

697            }
698        }

1073        |_| RawWaker::new(std::ptr::null::<()>(), &NOOP_WAKER_VTABLE),
