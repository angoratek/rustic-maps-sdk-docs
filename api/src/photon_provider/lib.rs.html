1//! Photon implementation of [`geospatial_traits::SearchPlaceProvider`] and
2//! [`geospatial_traits::GeocodingProvider`].
3//!
4//! Photon is an open geocoder that answers forward queries, completion
5//! candidates and reverse lookups without a credential. It is reached by its
6//! deployment URL: the public instance by default, or any self-hosted one
7//! through [`PhotonProviderConfiguration`]. Every request goes through the
8//! shared [`provider_transport`] seam ([`client`]) with bounded
9//! idempotent-GET retries, so the same request, parsing and error-mapping
10//! code runs natively and in browsers.
11//!
12//! # Result mapping
13//!
14//! Photon answers with a GeoJSON `FeatureCollection`. Each feature's point
15//! becomes a [`geospatial_types::PlaceResult`]:
16//!
17//! - the display line is the feature's `name` when Photon published one,
18//!   otherwise the address components (`housenumber street`, `postcode
19//!   city`, `state`, `country`) joined with commas;
20//! - the feature's `type` (`house`, `street`, `locality`, `district`, `city`,
21//!   `county`, `state`, `country`, `postcode`) maps onto the SDK's
22//!   [`geospatial_types::place::GeocodeQuality`] scale, with anything else
23//!   reported as a point.
24//!
25//! Autocomplete asks for five candidates (the reference applications' row
26//! count) and a settled search for ten. A search boundary becomes Photon's
27//! `bbox` filter.
