1//! The pure event reducer driving an active trip.
2//!
3//! `reduce_navigation_event` maps one event onto the previous session and
4//! returns the next one; it has no I/O, no clock and no mutable globals, so
5//! every outcome is reproducible from the event history (the seam Ferrostar
6//! builds its whole controller around). The live
7//! [`StepAdvanceCondition`] and
8//! [`DeviationDetector`] instances are threaded through
9//! [`NavigationSession`] — pairing state with its decision objects exactly as
10//! Ferrostar's `NavState` does — because they are swapped for their
11//! [`StepAdvanceCondition::fresh_instance`] (or
12//! [`DeviationDetector::fresh_instance`]) counterparts at reset points, and the
13//! exported [`crate::state::TripNavigationState`] must stay free of trait
14//! objects.
15//!
16//! Semantics in this slice:
17//! - [`NavigationEvent::StartTrip`] flattens the route and reports the declared
18//!   step values as remaining progress until the first fix arrives.
19//! - [`NavigationEvent::LocationUpdated`] is judged for deviation first:
20//!   a fix the detector grades *fully* off route *freezes* the session — the
21//!   snapped coordinate and progress stay at the last on-route values, and
22//!   neither the step-advance condition is consulted nor the step advances
23//!   (deviating positions must not drive route progress; the reference freezes
24//!   the same way while deviating). A fix graded *off the current step but on
25//!   the route* ([`DeviationGrade::OffStepOnRoute`], a projection onto a
26//!   future step) never freezes on its own: the grade is recorded in the
27//!   state, the trip stays `Navigating` — no reroute request, instructions
28//!   keep counting down — and the fix is then processed normally (the
29//!   step-advance condition reconciles the step; a delayed condition does so
30//!   within the very fix, via the multi-step advance loop below). A fix
31//!   without an accuracy report is not judged at all: it can neither raise
32//!   nor clear a deviation, because one threshold rule cannot conservatively
33//!   decide both directions. A graded fix inside the allowance lifts an
34//!   active deviation (an `OffRoute` trip recovering from the route line, or
35//!   a lingering wrong-step grade clearing) and the update then proceeds
36//!   normally (condition consulted, position snapped, progress recomputed).
37//!   [`crate::state::NavigationPhase::OffRoute`] is therefore a pause the user
38//!   may recover from by returning to the route, not a terminal state.
39//! - **Arrival-aware advance** (the reference's separate arrival condition):
40//!   the condition consulted for a hop is not always the trip's own. Once the
41//!   remaining steps — counted as the reference counts them, the current step
42//!   itself included — shrink to the arrival window
43//!   ([`ARRIVAL_CONDITION_REMAINING_STEPS_BOUND`]), a separately configured
44//!   *arrival* step-advance condition is consulted instead (falling back to
45//!   the trip's own condition when none was configured, which preserves the
46//!   behavior of every trip that has none). Arrival itself is reachable only
47//!   through that final-step verdict: an `Advance` while on the final step
48//!   cannot pop another step — it declares
49//!   [`NavigationPhase::Arrived`](crate::state::NavigationPhase::Arrived) and
50//!   breaks the loop exactly where the reference's arrival arm does, ahead of
51//!   any further consult, so neither the loop's defensive bound nor a still
52//!   advancing condition can walk past the route's end.
53//! - The trip's course-filtering policy stamps an effective course
54//!   ([`TripNavigationState::course_heading_degrees`]) during each processed
55//!   fix's position snap; see [`crate::course_filtering`].
56//! - One fix may advance through *several* steps (the reference's
57//!   loop-until-break speed-run semantics, not recursion): after each
58//!   single-hop advance — which swaps in the fresh condition instance exactly
59//!   as the single-advance slice did — the freshly computed inputs decide
60//!   whether the same fix advances the next hop too. The loop is bounded by
61//!   [`MAXIMUM_STEP_ADVANCES_PER_FIX`] and terminates by construction: a hop
62//!   can end the trip only by arriving, and every other break is the
63//!   condition's `Remain`.
64//! - [`NavigationEvent::RerouteProvided`] rebuilds the session for the same
65//!   trip from a fresh route. The remote-first, offline-fallback policy
66//!   (compute the replacement route remotely, fall back to an offline graph)
67//!   lives at the integrator/event-source layer, which owns the route request;
68//!   the reducer stays policy-free and pure. See the event documentation for
69//!   the route-anchoring contract it implies.
70//! - Updates after the phase is `Arrived` are ignored; reroutes offered to an
71//!   arrived trip are ignored as well.
72//!
73//! Later slices, deliberately deferred: observers and listeners, and
74//! programmatic step advance.

89/// Defensive ceiling, in steps, on how many hops a single position fix may
90/// advance through in the multi-step advance loop.
91///
92/// The loop's real terminators are the advance condition itself (a `Remain`
93/// verdict ends the walk) and the trip's arrival on the final step, so the
94/// bound is not what makes the loop safe — it exists to guarantee a bounded
95/// response even against a pathological condition that advances on every
96/// consult (any real fix is unboundedly faster than such a condition could
97/// run out of steps). It is set far above any legitimate fix-to-step skip:
98/// the stack-safety fixture in this module replays a 1,000-step route with a
99/// single huge jump and stays well inside it, as does any recorded trace at
100/// the reference applications' 50× replay acceleration.
101pub const MAXIMUM_STEP_ADVANCES_PER_FIX: usize = 4096;
102
103/// How few steps may remain — measured the reference's way, the *current*
104/// step itself included — while the trip consults its separately configured
105/// arrival step-advance condition instead of its ordinary one.
106///
107/// The reference's selector reads `remaining_steps.len() <= 2`, so the
108/// arrival condition governs the final step and the one before it: arrival
109/// decisions deserve their own (typically narrower, more eager or more
110/// pedestrian-calibrated) policy long before the maneuver point. There is no
111/// configured trip without the pairing: a trip that declares no arrival
112/// condition runs its ordinary condition to the end (unchanged behavior, an
113/// explicit `None` in the `StartTrip` event).
114pub const ARRIVAL_CONDITION_REMAINING_STEPS_BOUND: usize = 2;

116/// Inputs the reducer accepts for one active trip.
117pub enum NavigationEvent {
118    /// Begin navigating the given route with the given advance strategy.
119    ///
120    /// The condition and the deviation detector are supplied per trip (the
121    /// reference's controller receives them the same way) rather than through
122    /// configuration, so changing either policy is an explicit event in the
123    /// history.
124    StartTrip {
125        /// The route to navigate.
126        route: RouteData,
127        /// The strategy deciding when to move between steps.
128        step_advance_condition: Arc<dyn StepAdvanceCondition>,
129        /// The strategy deciding when to move onto (and complete) the final
130        /// steps, selected by the reference's arrival window
131        /// ([`ARRIVAL_CONDITION_REMAINING_STEPS_BOUND`]); `None` keeps the
132        /// ordinary condition for every step. Swapped with
133        /// [`StepAdvanceCondition::fresh_instance`] on every advance hop, like
134        /// the ordinary condition.
135        arrival_step_advance_condition: Option<Arc<dyn StepAdvanceCondition>>,
136        /// The policy deciding how the trip's course is reported
137        /// (see [`crate::course_filtering`]).
138        course_filtering: CourseFiltering,
139        /// The strategy deciding when the trip is judged off route.
140        deviation_detector: Arc<dyn DeviationDetector>,
141    },
142    /// Replace the route of the active trip (a reroute).
143    ///
144    /// This event is the caller's answer to a detected deviation — or a
145    /// proactive route swap. The `remote-first, offline-fallback` policy (ask
146    /// a remote router for a replacement route, fall back to an offline
147    /// graph) decides *where* the replacement comes from and lives at the
148    /// integrator/event-source layer; the reducer only applies it, staying
149    /// pure and policy-free.
150    ///
151    /// # Anchoring contract
152    ///
153    /// [`Self::RerouteProvided`] rebuilds the session exactly as
154    /// [`Self::StartTrip`] does, so the replacement route must be authored to
155    /// *begin at the trip's current snapped coordinate* — which is where a
156    /// reroute router anchors its request anyway. The reducer performs no
157    /// trimming or re-ghosting of the new route's geometry; if the anchoring
158    /// contract is violated, the next graded fix will be judged against the
159    /// remaining route line by the deviation detector (and would flag a
160    /// deviation), so a mis-authored reroute is at worst flagged, never
161    /// silently mis-projected.
162    ///
163    /// The replacement advance condition must be fresh from the caller's side;
164    /// the reducer additionally rebuilds it via
165    /// [`StepAdvanceCondition::fresh_instance`] as a defensive reset so a
166    /// mid-schedule instance carried over from the old route cannot corrupt
167    /// the new step sequence (the double-advance contract).
168    RerouteProvided {
169        /// The replacement route, anchored at the current snapped coordinate.
170        route: RouteData,
171        /// The fresh strategy deciding when to move between steps of the new
172        /// route.
173        step_advance_condition: Arc<dyn StepAdvanceCondition>,
174    },
175    /// A new position fix was received while a trip is active.
176    LocationUpdated(
177        /// The fix to judge, snap and evaluate.
178        NavigationLocationUpdate,
179    ),
180}

182/// An active trip: the plain-data state plus the live decision instances.
183///
184/// This pairing (rather than embedding the conditions in the state) is what
185/// keeps [`TripNavigationState`] serializable end to end.
186#[derive(Clone)]
187pub struct NavigationSession {
188    /// The plain-data record consumers and UI read.
189    pub state: TripNavigationState,
190    /// The condition consulted on the next location update.
191    pub step_advance_condition: Arc<dyn StepAdvanceCondition>,
192    /// The separately configured arrival-window condition, `None` when the
193    /// trip runs its ordinary condition to the end; consulted (instead of
194    /// [`Self::step_advance_condition`]) while the remaining step count is
195    /// within [`ARRIVAL_CONDITION_REMAINING_STEPS_BOUND`].
196    pub arrival_step_advance_condition: Option<Arc<dyn StepAdvanceCondition>>,
197    /// The trip's course-filtering policy (see [`crate::course_filtering`]).
198    pub course_filtering: CourseFiltering,
199    /// The detector consulted on the next location update.
200    pub deviation_detector: Arc<dyn DeviationDetector>,
201}

219/// Reduces one event onto the previous session.
220///
221/// `None` means no trip is active: `LocationUpdated` and `RerouteProvided`
222/// before any `StartTrip` are dropped, and `StartTrip` begins a session.
223/// `LocationUpdated` and `RerouteProvided` on an arrived trip leave the
224/// session untouched.
225pub fn reduce_navigation_event(
226    session: Option<NavigationSession>,
227    event: NavigationEvent,
228) -> Option<NavigationSession> {
229    match event {
230        NavigationEvent::StartTrip {
231            route,
232            step_advance_condition,
233            arrival_step_advance_condition,
234            course_filtering,
235            deviation_detector,
236        } => Some(NavigationSession {
237            state: build_trip_state(route),
238            // The route has no traversed step yet: both condition instances
239            // and the course policy install as declared (the reducer rebuilds
240            // the *arrival* instance fresh on every advance hop, exactly as
241            // the ordinary one).
242            step_advance_condition,
243            arrival_step_advance_condition,
244            course_filtering,
245            deviation_detector,
246        }),
247        NavigationEvent::RerouteProvided {
248            route,
249            step_advance_condition,
250        } => {
251            let mut session = session?;
252            // An arrived trip ignores reroutes: the destination was reached,
253            // and a replacement route cannot unreach it.
254            if session.state.phase != NavigationPhase::Arrived {
255                session = apply_reroute(session, route, step_advance_condition);
256            }
257            Some(session)
258        }
259        NavigationEvent::LocationUpdated(update) => {
260            let mut session = session?;
261            // An arrived trip keeps its session untouched; navigating and
262            // off-route trips consume fixes (consuming a fix is the only way
263            // an off-route trip recovers).
264            if session.state.phase != NavigationPhase::Arrived {
265                session = process_location_update(session, update);
266            }
267            Some(session)
268        }
269    }
270}

272/// Builds the initial state for a trip, before any location fix.
273///
274/// Shared by [`NavigationEvent::StartTrip`] and
275/// [`NavigationEvent::RerouteProvided`]: both rebuild the trip's route
276/// projection from scratch.
277fn build_trip_state(route: RouteData) -> TripNavigationState {
278    let step_positions = TripNavigationState::build_step_positions(&route);
279    // A route without traversable steps has nothing to navigate; represent
280    // that as an already-arrived trip rather than wedging in `Navigating`.
281    let phase = if step_positions.is_empty() {
282        NavigationPhase::Arrived
283    } else {
284        NavigationPhase::Navigating
285    };
286    let mut state = TripNavigationState {
287        phase,
288        route,
289        step_positions,
290        current_step_position: 0,
291        progress: TripProgress::default(),
292        deviation: None,
293        snapped_coordinate: None,
294        course_heading_degrees: None,
295    };
296    state.progress = compute_progress(&state);
297    state
298}

300/// Rebuilds the session for the same trip from the replacement route onward.
301fn apply_reroute(
302    mut session: NavigationSession,
303    route: RouteData,
304    step_advance_condition: Arc<dyn StepAdvanceCondition>,
305) -> NavigationSession {
306    session.state = build_trip_state(route);
307    // Defensive reset: the caller may hand back a condition instance that was
308    // mid-schedule on the old route (for example the same `Arc` still held in
309    // its own state); a mid-schedule instance would corrupt the new step
310    // sequence (the double-advance contract).
311    session.step_advance_condition = step_advance_condition.fresh_instance();
312    // The arrival-window condition is a trip configuration: it persists
313    // across the route swap, rebuilt fresh for the new step sequence under
314    // the same contract as the ordinary condition and the deviation detector.
315    if let Some(arrival_step_advance_condition) = &session.arrival_step_advance_condition {
316        session.arrival_step_advance_condition =
317            Some(arrival_step_advance_condition.fresh_instance());
318    }
319    // The course-filtering policy likewise persists (it is a trip-level
320    // policy, not a per-route one).
321    // The deviation detector's configuration persists across the route swap,
322    // but its instance is rebuilt so a future stateful detector's tracking
323    // restarts with the new route context (same contract as the condition
324    // swap on advance).
325    session.deviation_detector = session.deviation_detector.fresh_instance();
326    session
327}

329/// Applies one fix to a navigating session: judge deviation, consult, then act.
330fn process_location_update(
331    mut session: NavigationSession,
332    update: NavigationLocationUpdate,
333) -> NavigationSession {
334    // Deviation judgment comes first, and only for fixes carrying an accuracy
335    // report: one threshold rule cannot conservatively decide both raising
336    // and clearing a deviation, so an ungraded fix can do neither (it still
337    // snaps and progresses when the trip is not already off route, as it did
338    // before deviation detection landed).
339    let is_fix_accuracy_graded = update.horizontal_accuracy_meters.is_some();
340    if is_fix_accuracy_graded {
341        let remaining_route_line = remaining_route_line(&session.state);
342        let distance_from_route_meters =
343            snap_coordinate_to_polyline(&update.coordinate, &remaining_route_line).map(
344                |remaining_route_line_snap| remaining_route_line_snap.distance_to_polyline_meters,
345            );
346        // The two-grade judgment's second measurement: the current step's own
347        // polyline, where the remaining route line's closest projection may
348        // not sit (a future-step projection is the "on route, wrong step"
349        // grade's shape).
350        let current_step = session.state.current_step();
351        let distance_from_current_step_meters = current_step.and_then(|current_step| {
352            snap_coordinate_to_polyline(&update.coordinate, &current_step.shape)
353                .map(|current_step_snap| current_step_snap.distance_to_polyline_meters)
354        });
355        let detection_inputs = DeviationDetectionInputs {
356            coordinate: &update.coordinate,
357            horizontal_accuracy_meters: update.horizontal_accuracy_meters,
358            distance_from_route_meters,
359            distance_from_current_step_meters,
360        };
361        match session
362            .deviation_detector
363            .deviation_status(&detection_inputs, &session.state)
364        {
365            // Freeze: the snapped coordinate and progress stay at the last
366            // on-route values, the step does not advance, and the condition
367            // is not consulted (a deviating fix must not drive route
368            // progress). Only the phase and the recorded measurement change.
369            DeviationStatus::OffRoute {
370                deviation_from_route_meters,
371            } => {
372                session.state.phase = NavigationPhase::OffRoute;
373                session.state.deviation = Some(DeviationInfo {
374                    grade: DeviationGrade::FullyOffRoute,
375                    deviation_from_route_meters,
376                });
377                return session;
378            }
379            // On route, wrong step: the trip never freezes on this grade —
380            // record it and process the fix normally below (a frozen trip the
381            // grade recovers lifts the freeze here).
382            DeviationStatus::OffStepOnRoute {
383                deviation_from_route_meters,
384            } => {
385                session.state.deviation = Some(DeviationInfo {
386                    grade: DeviationGrade::OffStepOnRoute,
387                    deviation_from_route_meters,
388                });
389                session.state.phase = NavigationPhase::Navigating;
390            }
391            // Fully on route: an active full deviation lifts (recovery), a
392            // lingering wrong-step grade clears.
393            DeviationStatus::OnRoute => {
394                session.state.deviation = None;
395                session.state.phase = NavigationPhase::Navigating;
396            }
397        }
398    } else if session.state.phase == NavigationPhase::OffRoute {
399        // Reaching this point on an off-route trip means an ungraded fix: it
400        // can neither raise nor clear the judgment, so the deviation holds
401        // and the session stays frozen. (A graded fix within the allowance
402        // — or graded onto a future step — has already lifted the freeze
403        // above.)
404        return session;
405    }
406
407    // The multi-step advance loop (the reference's speed-run semantics): the
408    // same fix is re-consulted — with freshly computed inputs — after every
409    // single-hop advance, until the condition says to remain or the trip
410    // arrives. Iterative, never recursive, and bounded by
411    // `MAXIMUM_STEP_ADVANCES_PER_FIX` as a defensive ceiling.
412    let mut applied_advances = 0_usize;
413    loop {
414        let decision = {
415            let state = &session.state;
416            // The caller guarantees the phase is `Navigating` with a traversal
417            // built from the route, so the current step always resolves.
418            #[allow(clippy::expect_used)]
419            // internal invariant, upheld by the caller contract (documented above)
420            let current_step = state
421                .current_step()
422                .expect("navigating session must always have a current step");
423            let snap = snap_coordinate_to_polyline(&update.coordinate, &current_step.shape);
424            // Straight-line distance from the raw fix to the maneuver point,
425            // mirroring Ferrostar's eager condition which measures the raw
426            // location, while progress (below) measures the snapped position.
427            let distance_to_end_of_step_meters =
428                current_step.shape.last().map(|terminal_coordinate| {
429                    update
430                        .coordinate
431                        .haversine_distance_meters(terminal_coordinate)
432                });
433            let distance_from_step_meters = snap
434                .as_ref()
435                .map(|snapped| snapped.distance_to_polyline_meters);
436            let inputs = StepAdvanceInputs {
437                coordinate: &update.coordinate,
438                horizontal_accuracy_meters: update.horizontal_accuracy_meters,
439                current_step,
440                next_step: state.step_at(state.current_step_position + 1),
441                snapped_coordinate: snap.as_ref().map(|snapped| &snapped.snapped_coordinate),
442                distance_to_end_of_step_meters,
443                distance_from_step_meters,
444            };
445            // The arrival-aware condition selection: inside the arrival
446            // window the separately configured arrival condition decides the
447            // hop (falling back to the ordinary condition without one).
448            let consulted_condition = if remaining_steps_within_arrival_window(state) {
449                session
450                    .arrival_step_advance_condition
451                    .as_ref()
452                    .cloned()
453                    .unwrap_or_else(|| Arc::clone(&session.step_advance_condition))
454            } else {
455                Arc::clone(&session.step_advance_condition)
456            };
457            consulted_condition.should_advance_step(&inputs, state)
458        };
459
460        if decision != StepAdvanceDecision::Advance {
461            break;
462        }
463        if session.state.is_on_final_step() {
464            session.state.phase = NavigationPhase::Arrived;
465            break;
466        }
467        session.state.current_step_position += 1;
468        // Each hop swaps in the fresh condition instance exactly as the
469        // single-advance slice did: a stale instance's internal progress can
470        // never leak from one step into the next (the double-advance
471        // contract). The arrival-window condition, when configured, is
472        // swapped under the same contract.
473        session.step_advance_condition = session.step_advance_condition.fresh_instance();
474        if let Some(arrival_step_advance_condition) = &session.arrival_step_advance_condition {
475            session.arrival_step_advance_condition =
476                Some(arrival_step_advance_condition.fresh_instance());
477        }
478        applied_advances += 1;
479        if applied_advances >= MAXIMUM_STEP_ADVANCES_PER_FIX {
480            break;
481        }
482    }
483    session.state = apply_location_to_state(session.state, &update, session.course_filtering);
484    session
485}

487/// Whether the trip's remaining steps — the current one itself included, as
488/// the reference counts its `remaining_steps` — sit inside the arrival
489/// window: the separately configured arrival condition governs these steps.
490fn remaining_steps_within_arrival_window(state: &TripNavigationState) -> bool {
491    state.step_positions.len() - state.current_step_position
492        <= ARRIVAL_CONDITION_REMAINING_STEPS_BOUND
493}

495/// The polyline of the route remaining from the current step onward: the
496/// current step's shape plus every following step's shape, in traversal order.
497///
498/// Deviation is measured against this line rather than only the current step
499/// (the reference's route-line semantics): a lagging step — eager advance
500/// semantics, pauses at intersections — is then never mistaken for a
501/// deviation. Consecutive steps may repeat their shared boundary coordinate,
502/// which degenerates to a zero-length segment the snapping projection already
503/// treats as a point.
504fn remaining_route_line(state: &TripNavigationState) -> Vec<GeographicCoordinate> {
505    let mut remaining_route_line = Vec::new();
506    for step_position in state
507        .step_positions
508        .iter()
509        .skip(state.current_step_position)
510    {
511        if let Some(step) = state.step_for_position(step_position) {
512            remaining_route_line.extend_from_slice(&step.shape);
513        }
514    }
515    remaining_route_line
516}

518/// Snaps the fix onto the current step and recomputes progress from it.
519///
520/// When the current step's shape carries no geometry, snapping is impossible;
521/// the previous snapped position is retained so the progress projection
522/// degrades continuously instead of flickering. The trip's effective course
523/// is stamped from the same decision: the fix's snap under the trip's
524/// course-filtering policy ([`effective_course_heading_degrees`]).
525fn apply_location_to_state(
526    mut state: TripNavigationState,
527    update: &NavigationLocationUpdate,
528    course_filtering: CourseFiltering,
529) -> TripNavigationState {
530    let snapped = state.current_step().and_then(|current_step| {
531        snap_coordinate_to_polyline(&update.coordinate, &current_step.shape)
532    });
533    state.snapped_coordinate = snapped
534        .as_ref()
535        .map(|snapped| snapped.snapped_coordinate)
536        .or(state.snapped_coordinate);
537    state.course_heading_degrees = effective_course_heading_degrees(
538        course_filtering,
539        update.course_heading_degrees,
540        snapped.as_ref().and_then(|snapped| snapped.bearing_degrees),
541        state.course_heading_degrees,
542    );
543    state.progress = compute_progress(&state);
544    state
545}

547/// Recomputes [`TripProgress`] for the state's current step.
548///
549/// `distance_to_next_maneuver_meters` measures the snapped position against
550/// the step's terminal coordinate (Ferrostar's approach); without a snap it
551/// falls back to the provider-declared step distance. The remaining total
552/// adds the provider-declared distances and durations of the steps after the
553/// current one, and the current step's remaining duration is scaled linearly
554/// along the step — an approximation, since providers do not distribute speed
555/// uniformly within a step.
556fn compute_progress(state: &TripNavigationState) -> TripProgress {
557    if state.phase == NavigationPhase::Arrived {
558        return TripProgress::default();
559    }
560    let Some(current_step) = state.current_step() else {
561        return TripProgress::default();
562    };

564    let distance_to_next_maneuver_meters = match state.snapped_coordinate {
565        Some(snapped_coordinate) => current_step
566            .shape
567            .last()
568            .map(|terminal_coordinate| {
569                snapped_coordinate.haversine_distance_meters(terminal_coordinate)
570            })
571            .unwrap_or(current_step.distance_meters),
572        None => current_step.distance_meters,
573    };
574    let traveled_fraction = if current_step.distance_meters > 0.0 {
575        // Structural fraction of the step left to walk; a snap is inside the
576        // step geometry, and the clamp keeps noisy declared totals honest.
577        (distance_to_next_maneuver_meters / current_step.distance_meters).clamp(0.0, 1.0)
578    } else {
579        // A zero-distance step is instantaneously complete.
580        1.0
581    };
582    let duration_to_next_maneuver_seconds = current_step.duration_seconds * traveled_fraction;
583
584    let distance_remaining_meters = distance_to_next_maneuver_meters
585        + following_declared_distance_meters(state, state.current_step_position);
586    let duration_remaining_seconds = duration_to_next_maneuver_seconds
587        + following_declared_duration_seconds(state, state.current_step_position);
588
589    TripProgress {
590        distance_to_next_maneuver_meters,
591        distance_remaining_meters,
592        duration_remaining_seconds,
593    }
594}

596/// Sums the provider-declared distances of the steps after `from_position`.
597fn following_declared_distance_meters(state: &TripNavigationState, from_position: usize) -> f64 {
598    state
599        .step_positions
600        .iter()
601        .enumerate()
602        .filter(|(position, _)| *position > from_position)
603        .filter_map(|(_, step_position)| state.step_for_position(step_position))
604        .map(|step| step.distance_meters)
605        .sum()
606}

612        .iter()

615        .filter_map(|(_, step_position)| state.step_for_position(step_position))
616        .map(|step| step.duration_seconds)
617        .sum()
618}
