The provider catalog table shared by the SDK’s native and browser bindings.

The native catalog and the browser dispatch each carry a row per provider: its key, display name, credential requirement and the contracts it serves. That table used to exist three times — once per binding and once in the shared registry — so a provider could be advertised on one target and refused on another. It lives here once; both bindings read it and their tests compare their own rows against it, and the registry test compares the descriptors in platform/providers.json against it.

The vendor implementations stay in their own crates. This crate carries no vendor URL, credential value or transport; adding a provider adds one row here and one construction function in the binding’s shared seam.
