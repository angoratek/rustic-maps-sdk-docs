The executor seam for blocking work.

Some SDK work is synchronous by nature: the response store that backs the cache-then-network policy reads and writes SQLite, and the offline routing engine runs a CPU-bound graph search. Running either on the async reactor monopolizes the thread that drives every other future.

BlockingWorkExecutor is the seam that moves such a job to where blocking is acceptable. A target with worker threads (the native bindings) implements it over a blocking thread pool; a target without threads (the browser) uses InlineBlockingWorkExecutor, which runs the job where it is awaited. The cache and routing layers depend only on the trait, so neither names an executor implementation.
