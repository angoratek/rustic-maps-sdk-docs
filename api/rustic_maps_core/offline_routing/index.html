Offline route calculation over compiled routing graph archives.

ArchiveOfflineRoutingProvider implements [OfflineRoutingProvider] over a compiled routing graph archive. It loads the archive from a memory-mapped file on native targets or from in-memory bytes on every target, validates it with the archive reader, and builds the adjacency and turn-restriction indexes once. Route requests are then answered with A* under a haversine heuristic.

§Targets

The whole module compiles on every target; only graph loading differs.

  • [OfflineGraphSource::Memory] is available everywhere and is the only graph source on WebAssembly.
  • [OfflineGraphSource::FilePath] memory-maps the archive on native targets. On WebAssembly it returns [SDKError::ProviderRequestRejected] with a message that directs the caller to [OfflineGraphSource::Memory], because the browser has no memory mapping.

§Routing behavior

  • Only automobile routing is supported. The archive carries an automobile profile, so a request for another transportation mode is rejected with [SDKError::ProviderRequestRejected] rather than answered.
  • Costs follow [RouteOptions::route_strategy]: Fastest minimizes edge durations and Shortest minimizes edge distances. Edge speeds and road classes come from each edge record.
  • Steps are derived from graph metadata. Besides road-class and speed runs, a step boundary occurs at every junction whose signed bearing change leaves the straight band; the step then carries the matching [TurnDirection]. A road-class or speed change without a turn produces a Continue step. The archive carries no street names, so instruction text stays name-free and faithful to the geometry, for example "Turn right" or "U-turn". A strongly curved road yields a step at each junction.
  • Display and speech text on a step names the maneuver at the step’s end junction, the point a countdown to the next maneuver refers to. [ManeuverType] stays anchored to the maneuver that opens the step. See end_anchored_instruction_text.
  • Turn restrictions are evaluated against the incoming edge of the settled path. The approximation is exact unless a node is reachable through several best-cost paths with differently restricted incoming edges; in that case it can over-restrict, never under-restrict.

§Threading and async

[OfflineRoutingProvider::load_offline_graph] validates the archive and builds the graph indexes, and [OfflineRoutingProvider::calculate_offline_route] snaps the endpoints and runs A*. Both are CPU-bound and run through the blocking-work seam (crate::blocking_work::BlockingWorkExecutor): a target with a blocking pool runs them on a worker thread, and the browser runs them inline on its single task queue. No lock is held across an await; the search clones the loaded graph handle and releases the read lock before running.

A load validates the new archive completely before replacing the current graph; a failed load leaves the previous graph loaded. The provider is safe to share across threads.

§Search engine and performance measurement

[a_star_search] and [dijkstra_reference_search] expose the search engine directly so performance can be measured over the same loaded graph. Dijkstra is a reference baseline only: production routing always goes through A*. Both searches expose [ComputedRoute::settled_node_count], a deterministic expansion metric for comparing them. These items are hidden from generated documentation and are not part of the supported API.
