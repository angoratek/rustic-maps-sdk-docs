Expand description

Failures thrown across the native binding surface of map-native-core.

The camera/projection surface produces SdkError::InvalidCoordinateInput only; the async provider surface additionally produces the transport, parsing, application-level, rate-limit and not-configured variants below; the navigation surface (M6) produces SdkError::InvalidNavigationInput for route records and navigation policies failing native validation. The variants mirror the SDKError subset returned by the frozen calls (see src/map_native_core.udl); later slices extend this enum as their surfaces start returning further variants.

§

InvalidNavigationInput

A navigation input failed native-boundary validation; either a policy carried an unusable threshold (non-finite or negative) or a route record carried a step maneuver label the converter cannot map onto the native maneuver classification. Unlike the camera surface this variant is not a mirror of a core SDKError variant: navigation policies and route records enter the SDK at this boundary and have no core-side validator of their own yet.

Fields

§detail: String

Verbatim description of the refused navigation input.

§

InvalidRenderInput

An overlay descriptor did not describe a usable overlay (wrong kind payload, an out-of-range color channel, or a non-positive or non-finite width or radius) or a surface input was structurally unusable (a null or ambiguous platform surface pointer, or a non-positive viewport extent). Unlike the camera surface this variant is not a mirror of a core SDKError variant: overlay descriptors and surface handles enter the SDK at the surface-view boundary and have no core-side validator of their own.

Fields

§detail: String

Verbatim description of the refused surface input.

§

RenderingSurfaceUnavailable

The live rendering could not proceed on the platform surface: the platform handle or surface was unusable, the graphics context could not be acquired, the surface format could not be negotiated or configured, the frame texture could not be acquired even after the stale-surface retry, the draw list would overflow, or the frame’s resources were busy in another draw. Unlike the camera surface this variant is not a mirror of a core SDKError variant: it carries the surface renderer’s own failures across the binding surface.

Fields

§detail: String

Verbatim description of the unavailable rendering surface.

impl From<SDKError> for SdkError

Source§

fn from(sdk_error: SDKError) -> Self

Maps a core SDKError onto the binding error model, preserving every variant the frozen calls can produce one-to-one with its verbatim detail. The only unreachable variants are the cache and offline routing ones — no frozen call goes through the cache or the offline graph yet — and those surface under SdkError::InvalidCoordinateInput with their native display message so an unexpected failure stays diagnosable and the conversion never panics.

Source§

impl From<SdkError> for SDKError

Source§

fn from(sdk_error: SdkError) -> Self

Maps the binding error back onto the core error model, exact for the six SDKError-mirroring variants: the forward From<SDKError> for SdkError conversion and this one round-trip them without information loss. This is the direction the foreign-callback provider adapters need — a foreign implementation throws SdkError across the FFI and the adapter re-raises it as the core error of the implemented provider contract. The navigation-only SdkError::InvalidNavigationInput has no core equivalent (nothing re-raises a navigation-input failure into a provider contract), so it carries its detail under InvalidCoordinateInput to keep the conversion total and the failure diagnosable.

impl From<UnexpectedUniFFICallbackError> for SdkError

Source§

fn from(unexpected_callback_error: UnexpectedUniFFICallbackError) -> Self

Maps a foreign provider implementation’s unclassified failure onto the binding error model. A foreign implementation of a provider callback contract that throws its contract’s SdkError takes the typed error round trip exactly (lift_error); a foreign impl that fails some other way (any exception the contract does not spell) is reported by the foreign vtable as an unexpected callback failure. Without this conversion uniffi would turn that report into a Rust panic — correctly contained by the FFI scaffolding’s panic boundary (see crate::panic_boundary) but only as the untyped “unexpected error” status. With it, the provider contracts’ async exports resolve with a typed failure: this is the closest existing variant — the failing party is the provider implementation — carrying the foreign failure’s verbatim reason verbatim.

The variant’s meaning is thus extended at this seam alone; this conversion is Rust-only (the UDL surface and the enum’s contract variants are untouched: addition-only).
