Module engines 

Source
Expand description

The M17 engine facades (addition-only contract slice): typed capability objects constructed over an existing MapSdk.

Each engine holds the very same MapSdk the application already owns — one provider registry, one tile-cache installation, one diagnostics ring set — and delegates every member to the matching MapSdk method verbatim. The engines add no validation, no mapping and no error rewriting of their own: a typed failure is the SDK’s typed failure with the same variant and the same detail message, so an integrator moving from map_sdk.search(...) to search_engine.search(...) observes no behavioural change. Their point is vocabulary: the same engine names reach Kotlin, Swift, React Native and the wasm mirror through one UDL contract, and an application holds one MapSdk plus one engine per capability instead of a single object with every call on it.

The async members await the SDK’s runtime-independent futures directly, so the exported futures stay Send (the provider reactor work already hands back through [crate::runtime::drive]).
