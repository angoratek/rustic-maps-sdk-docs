Struct Navigator

pub struct Navigator { /* private fields */ }
Expand description

The exported navigation controller: drives the native reducer’s session, broadcasts every state change to the registered foreign listeners, and answers read-only state and instruction queries.

The active-trip lock is never held across a broadcaster dispatch (see the module-head notes on the re-entrancy rules across the seam).

pub fn add_navigation_listener( &self, listener: Arc<dyn NavigationListener>, ) -> Arc<Subscription> ⓘ

Subscribes one listener to all four navigation topics — instructions, deviation status, phase changes and speech instructions — and answers the composite subscription that cancels all four. The listener is wrapped once and registered on each topic list, so every topic dispatches to the same foreign object on its own method; the composite cancel() removes every registration (idempotent, like a single-topic subscription).

Source

pub fn begin_reroute_calculation(&self) -> bool

Evaluates the reroute-recalculation gates over one reroute-request signal at the wall clock: true when every gate passed and a calculation is now in flight (readable as the trip state’s is_calculating_new_route); false when the signal was refused (a calculation in flight, inside the cooldown window, or inside the movement threshold — check the trip state for which fact applies). A signal without an open, still-navigable trip (no trip, or the trip has arrived) is refused before the gates are consulted.

The trip’s eligibility is read under a short active-trip lock released before the gate lock; neither is held across a dispatch or a listener callback. A passing caller owes a settle: the eventual apply_reroute (applied or ignored) or Navigator::cancel_reroute_calculation.

Source

pub fn cancel_reroute_calculation(&self)

Settles an in-flight reroute calculation without applying a route (the integrator abandoned the request): the request-in-flight gate reopens. The cooldown keeps running from the calculation’s beginning and the movement reference stays where it was. Idempotent; without an active trip the gate is still settled (the gate is controller configuration and memory, not trip state).

Source

pub fn configure_reroute_policy( &self, reroute_policy: ReroutePolicy, ) -> Result<(), SdkError>

Swaps the reroute-recalculation hysteresis policy in force, keeping the gate’s memory as it stands. Both thresholds must be finite and non-negative (InvalidNavigationInput otherwise, and the policy in force is then untouched).

Source

pub fn start_navigation( &self, route: Route, unit_system: UnitSystem, step_advance_policy: StepAdvancePolicy, deviation_policy: DeviationPolicy, ) -> Result<(), SdkError>

Begins navigating route with the given policies, replacing any active trip. The initial instruction payload is dispatched; no deviation or phase transitions exist yet.

A route without traversable steps represents an already-arrived trip (the reducer’s own semantics), not a rejection.

Source

pub fn stop_navigation(&self)

Ends the active trip and clears the trip state: current_trip_state and current_instructions answer None afterwards, and location updates, reroutes, reroute-request signals and speech evaluations are dropped until start_navigation begins a new trip. The speech-trigger band memory and the reroute-recalculation gate are reset with the trip — the utterance identifier counter is deliberately not reset, so identifiers stay monotonic across a stop, and the configured reroute policy persists. Listener subscriptions are controller configuration, not trip state: they are untouched and serve the next trip. Stopping without an active trip is a no-op.

No event is dispatched for the stop: the native reducer has no stop transition, and the frozen phase channel has no stop variant, so inventing one here would be a semantics the reducer does not own.

Source

pub fn update_location(&self, location_update: NavigationLocationUpdate)

Delivers one position fix to the active trip; without one the fix is dropped (the reducer’s own semantics for event-before-trip). The fix is judged for deviation, snapped and evaluated by the active step-advance condition exactly as the native reducer documents, and the resulting transition is broadcast. A broadcast suppressed by the broadcaster’s re-entrancy guard is not reported here; the state change behind it has already been applied.

Source

pub fn apply_reroute( &self, route: Route, step_advance_policy: StepAdvancePolicy, ) -> Result<(), SdkError>

Replaces the route of the active trip (a reroute). The replacement route must be anchored at the trip’s current snapped coordinate (the reducer’s anchoring contract; no trimming happens here). The step advance strategy for the new route is configured by step_advance_policy; the active deviation policy persists.

A reroute offered to an arrived trip is ignored by the reducer and produces no phase transition; without an active trip the event is dropped.

Source

pub fn current_trip_state(&self) -> Option<TripNavigationState>

The plain state of the active trip, or None without one. The is_calculating_new_route fact is the controller’s own reroute gate readback (a wall-clock controller fact the pure trip state cannot carry); the two reads are short, sequential and never nested.

Source

pub fn current_instructions(&self) -> Option<NavigationInstruction>

The composed turn-by-turn instruction payload of the current trip state, or None without an active trip. Emission is pure in the native core, so repeated reads of an unchanged state return the same payload.
