The diagnostics sink (round 10, OQ6): the SdkDiagnosticEventListener foreign-callback contract foreign code implements to receive the SDK’s structured internal log events, plus the ring-buffer tracing subscriber and the sink’s privacy scrubbing behind MapSdk::subscribe_to_diagnostic_events and MapSdk::flush_recent_diagnostic_events.

§Architecture (the Mozilla ADR 0009 pattern)

The SDK crates emit plain tracing events under per-subsystem targets (tile_fetch, renderer, navigation, binding_camera, cache); DiagnosticsHandle::shared is the only writer into the bounded rings — a [DiagnosticsSubscriber] installed as the process’s global subscriber at the first MapSdk construction — and the FFI seams are two read-only views of it. Delivery is fire-and-forget: an event is copied into the ring and to any live listener and the emitting thread moves on immediately, so a host’s slow listener never slows the code whose events it observes.

The state is process-wide because a tracing global subscriber is: a second MapSdk in the same process shares the single rings-and-listeners state — the documented, honest shape of a process-wide logging facade. A host that already installed its own global subscriber keeps it (the host then owns the process’s logging policy, and the rings and the live stream stay empty — the flush seam answers an empty list).

§The severity gate

The rings record at DIAGNOSTIC_IDLE_RECORDING_SEVERITY or above while no fine-grained subscription is live. Trace- and debug-severity events — the GPU-hot render path’s instrumentation — are recorded and dispatched only once a subscription requested them: the subscriber’s enabled check consults the gate before any argument formatting runs, so an idle foreign listener leaves the frame path at near-zero logging cost. The gate never raises back: once fine-grained events have been subscribed, they keep recording while the process lives (the rings are bounded).

§Privacy (scrubbing at the sink)

A structured event’s latitude and longitude fields are rounded to DIAGNOSTIC_COORDINATE_DECIMALS decimals when the line is composed (≈ 110 m at the equator, the survey’s granularity), in exactly one place — the subscriber’s event visitor — regardless of which crate emitted. Call sites never embed raw coordinates in free-text messages, and the API key never appears in any event.

Structs§

DiagnosticsHandle
The process-wide diagnostics state: the per-subsystem bounded rings, the live subscription list, and the severity gate, behind the single tracing subscriber. Constructed through DiagnosticsHandle::shared (the FFI objects take the leaked handle).

Constants§

DIAGNOSTIC_COORDINATE_DECIMALS
Decimals coordinate values are rounded to at the sink, per the survey’s privacy granularity (≈ 110 m at the equator).
DIAGNOSTIC_IDLE_RECORDING_SEVERITY
The severity the rings record down to while no fine-grained subscription is live: only the coarse (informational and above) events pass, keeping the GPU-hot frame path’s trace instrumentation off when nothing listens.
DIAGNOSTIC_RING_CAPACITY
The capacity of each subsystem’s diagnostics ring, in events (bounded so a chatty subsystem cannot grow the process’s memory unboundedly).

Traits§

SdkDiagnosticEventListener
The exported SdkDiagnosticEventListener contract: foreign code implements it to receive the SDK’s structured internal log events — either streamed live (through MapSdk::subscribe_to_diagnostic_events, which also lowers the sink’s severity gate) or replayed from the bounded recent-events rings (through MapSdk::flush_recent_diagnostic_events). Callbacks are fire-and-forget: the sink cannot fail on a listener’s failure, and a listener emitting its own events is not recursed into.
