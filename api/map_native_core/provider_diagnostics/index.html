Module provider_diagnostics

Expand description

The provider-failure diagnostic seam (round 12, addition-only; the owner ruling of 2026-10-29 on unclassified foreign provider failures): the bounded per-MapSdk ring ProviderFailureDiagnosticsRing recording every failed foreign-callback provider call, read back through MapSdk::latest_provider_failure_diagnostics.

The write sites are the crate::foreign_providers adapters — the only boundary that sees both what the foreign implementation threw and the contract/method it occurred on. When the failure was the round-11 unclassified-callback conversion’s subject, the adapter classifies it (through the crate’s SdkError::unclassified_foreign_callback_reason) and records the callback machinery’s verbatim reason; otherwise the failure was a typed SdkError round trip and the entry carries its verbatim display form. Nothing is parsed or invented beyond that text — see the UDL seam section for the honest limitation.

The ring is per MapSdk (one registration passes the owning object’s ring into the adapters, mirroring how the adapters wrap exactly the callbacks registered on it), bounded so a systematically failing foreign provider cannot grow the process’s memory unboundedly, and read-only from the foreign side: the readback neither records nor clears.
