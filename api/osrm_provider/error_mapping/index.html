OSRM response interpretation: HTTP status and provider error envelopes become typed SDKError values.

OSRM reports application failures in a JSON envelope:

{"code": "NoRoute", "message": "Impossible route between points"}

The envelope is checked before the HTTP status, so the provider’s own message survives even when the service returns it with a 4xx status. A non-success status without such an envelope is a transport-level failure.
