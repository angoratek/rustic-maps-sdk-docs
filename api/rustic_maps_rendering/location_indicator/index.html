Module location_indicator 

Source
Expand description

GPU-free location-indicator assembly: the position fix drawn as a screen-facing two-mode puck over its optional ground-projected accuracy ring, in the same clip-space stream pattern the overlay layer uses (see crate::overlay).

The indicator is the third draw layer of a frame — the explicit draw order is tiles, then overlays, then the indicator (LOCATION_INDICATOR_TOP_LAYER_DRAW_ORDER) — so the fix’s visuals always paint over route lines and polygons without the overlay list growing or reordering. The vertices reuse the crate::overlay::ClipSpaceOverlayVertex type and draw through the existing overlay solid-color pipeline (a shader/layout-identical third pass), alpha-blended over what the first two layers drew.

The puck has two modes:

  • Tracking mode (LocationIndicatorVisualKind::TrackingDot, or a fix without a course): a soft dot — an accent core disc, a white ring around it, and a subtle dark halo under both for legibility on light and dark maps.
  • Navigation mode (LocationIndicatorVisualKind::GuidedCourseArrow with a reported course): an up-course dart with a white outline and the accent fill inside the same white ring and halo, rotating with the course. Without a course the navigation form degrades to the tracking dot.

Layer semantics:

  • Screen anchoring. The puck is a screen-space shape anchored at the fix’s projected position — the fix’s pixel stays fixed under zoom and pan while the layers beneath move, exactly like point markers do (center anchoring, “screen-facing”). At pitch this keeps the puck legible where a ground-projected dot would foreshorten to a sliver, and the dart rotates with the camera’s bearing so a course heading reads as the same compass direction it reads on the ground.
  • Accuracy ring. A ground-projected circle of the fix’s horizontal accuracy — the honest reading of “this fix is this accurate” — drawn through the filled-polygon machinery, so it foreshortens into the ellipse the ground shows at pitch and splits at world-copy boundaries like every other ground shape. A fix more accurate than MINIMUM_ACCURACY_RING_DRAW_METERS draws no ring (a circle inside the puck itself carries no information), and an absurdly coarse fix clamps to MAXIMUM_ACCURACY_RING_DIAMETER_PIXELS on screen instead of flooding the viewport.
  • World copies. The screen-facing shapes anchor once per visible world-copy window like the tile spans’ fragments, so at the zoom < 1 world-copy views the indicator draws in every copy that renders the fix; the ground ring splits across windows in the polygon machinery.
  • Behind the camera. A screen-shape anchor whose homogeneous weight is not positive (the fix behind the camera plane) draws no puck — the screen-space shapes’ documented skip — while the ground-projected ring still projects by genuine corners and leaves near-plane straddling to the GPU’s frustum clip.

DEFAULT_ACCURACY_RING_RGBA

Default accent-core radius in screen pixels: about 11 px, small enough not to hide the map beneath the puck and large enough to read at a glance.

DEFAULT_LOCATION_HALO_RGBA
Default halo color: near-black at low alpha, drawn under the puck so the white ring reads on a light map as well as on a dark one.
DEFAULT_LOCATION_RING_RGBA
Default ring color: opaque white, used for the ring around the puck and for the navigation dart’s outline.

Functions§

location_indicator_vertices
Assembles the location-indicator layer of one frame into the flat clip-space triangle list the overlay pipeline draws. A None layer (the cleared state) produces no vertices; a fix whose anchor projects behind the camera produces no puck for any window, while its accuracy ring (a ground-projected polygon) still assembles with genuine corners for the GPU’s frustum clip.
