Module source_binding 

Source
Expand description

The provider seam between a style document’s abstract sources and the tiles a provider fetches.

A style document names its sources ("base", "terrain", …) and never carries a vendor URL or a credential. The host binds each declared source id to a provider through StyleSourceBindings:

style JSON: { "sources": { "base": { "type": "vector" } } }
       │
       ▼  StyleSourceBindings::bind_style
BoundVectorSource { source_id: "base", provider_key: "…",
                    provider: Arc<dyn VectorTileProvider>, policy }
       │
       ▼  provider crates own the URL template and credential
       fetch, decode, style in global layer order

The renderer never sees a URL: it holds a VectorTileProvider or a RasterTileProvider and the TileJSON policy the style declared. Provider crates construct those providers from the shared registry, so a product style, a test and a reference-app shell all bind by id rather than copying a vendor address.

§TileJSON policy

SourceFetchPolicy folds the style source’s TileJSON fields into the provider descriptor:

  • minzoom/maxzoom clamp the requested zoom level (BoundVectorSource::served_zoom_level);
  • scheme: "tms" flips a tile’s row before the provider fetch;
  • bounds drops a tile whose geographic span does not intersect them;
  • attribution is the presentation text the base reports, preferring the style’s declaration over the provider’s descriptor.

§Multi-source frames

resolve_multi_source_vector_frame fetches each vector source’s tiles independently and styles them through the compiled plan’s global layer order. A layer therefore reads only its own source’s geometry, and two sources contribute to the same frame. Raster layers are not part of that frame: raster_layer_requests routes them to the existing crate::tile_scheduler::TileScheduler.
