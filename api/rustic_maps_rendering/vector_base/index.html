Module vector_base 

Source
Expand description

Shared vector-tile base pipeline: one scheduler that fetches a vector tileset through the VectorTileProvider trait, decodes each tile once, styles it, and answers the overlay primitives the frame draws beneath its own overlays.

Every target serves its vector base through this one implementation, so the native surfaces and the browser cannot drift in what a tile paints. The scheduler owns two caches:

  • Decoded tiles, keyed by the tile address: a tile’s bytes are fetched and decoded once and never again while it stays cached; a style change restyles the decoded tile instead of refetching it.
  • Styled geometry, keyed by the tile address, the style revision and the style’s zoom bucket: the style’s zoom span (min_zoom/max_zoom) and width stops are evaluated at the camera’s zoom level, so a camera pan across a width stop repaints the tile from the style it already carries — no refetch, no decode. The zoom level quantizes to VECTOR_BASE_STYLE_ZOOM_QUANTIZATION_STEPS_PER_LEVEL steps per level so a continuous zoom gesture cannot grow the styled cache without bound.

A tile that fails to fetch or decode does not fail the frame: the scheduler skips it, keeps painting the tiles that succeeded, and reports the failure in the frame’s counts and its last failure detail. The base map is one layer of a frame, never the frame’s reason to fail.

§Latency: payload cache, deliberate prefetch, progressive draw

The camera-facing VectorBaseScheduler::cached_frame never waits on the network: it paints the decoded tiles the cache holds, reports the rest as pending or failed, and lets a detached prefetch fill the gaps. A missing tile whose ancestor is cached draws that ancestor at the same camera zoom (the raster path’s parent-fallback semantics), so a new area blurs in at coarse detail instead of flashing holes.

Fetched wire payloads additionally pass through a rustic_maps_core::CachedResponseStore keyed by the tileset’s source name and the tile address. The native surfaces install their disk store (TTL, LRU and quota), so a region browsed once survives the next session; the browser installs VectorTileMemoryCache, the same policy in memory where no SQLite exists.

VectorBaseScheduler::prefetch_missing_tiles claims the visible misses; VectorBaseScheduler::prefetch_ring_tiles then claims the ring around the viewport (and the coarse parents that back a fallback) under a small budget. Both return cancellable detached futures: a dropped future releases its claims, so a scheduler that is replaced mid-fetch never strands a tile address as permanently in flight.

The scheduler is camera-agnostic: the caller lists the visible tile addresses (through MapCamera::visible_tile_keys or the page’s own grid) and names the camera’s zoom level; VectorBaseScheduler::served_zoom_level clamps that listing to the tileset’s declared zoom span.

Each resolved frame also carries the drawn tiles’ label candidates, read from the active style’s symbol layers. VectorBaseFrame::label_layer places them at a camera pose through the SDK’s embedded default glyph font, so every platform surface draws the same place names without a platform-specific asset. A frame without candidates yields None and costs the renderer nothing.

Constants§

DEFAULT_VECTOR_BASE_MAXIMUM_CACHED_STYLED_TILE_COUNT
The styled-geometry cache’s default capacity, in styled tiles. One decoded tile can be styled once per zoom bucket the camera passed through, so this cache is bounded on its own rather than only by decoded-tile eviction: four buckets’ worth of the decoded capacity covers a pan and a zoom while a tile stays resident, and nothing beyond that is retained.
DEFAULT_VECTOR_BASE_MAXIMUM_CACHED_TILE_COUNT
The decoded-tile cache’s default capacity. A 1080p frame asks for a few dozen tiles, so the cache holds several camera positions’ worth of decoded geometry: a pan back over visited ground repaints without refetching.
DEFAULT_VECTOR_BASE_PREFETCH_RING_TILE_BUDGET
How many ring tiles one detached prefetch plan may claim. The ring is an anticipation, not a requirement: a few tiles around the viewport turn the first pan into a cache hit without spending the service’s low-volume budget on a whole neighborhood.
DEFAULT_VECTOR_BASE_RING_PREFETCH_MINIMUM_INTERVAL_MILLISECONDS
The minimum interval between two ring prefetch plans. A plan is an anticipation, so one every half second is enough to stay ahead of a sustained pan while leaving the service and the frame loop alone; the plan also waits until the visible set’s own fetches have landed.
DEFAULT_VECTOR_TILE_MEMORY_CACHE_MAXIMUM_TILE_COUNT
The in-memory vector-tile payload cache’s default capacity, in tiles. The browser has no disk store, so the cache is process memory: a hundred-odd wire payloads cover a viewport’s worth of panning and a style switch without holding a whole session’s tiles decoded as well.
DEFAULT_VECTOR_TILE_PAYLOAD_TIME_TO_LIVE_SECONDS
The default time-to-live of one persisted vector-tile payload: thirty calendar days, the tile-imagery policy the provider crates assert against the cache’s ResponseCategory::VectorTiles default. A host that declares a stricter ceiling passes its own value through VectorBaseScheduler::with_payload_cache.
VECTOR_BASE_STYLE_ZOOM_QUANTIZATION_STEPS_PER_LEVEL
How many style-zoom buckets one zoom level divides into. A bucket is the granularity at which a restyle repaints: the camera zoom quantizes to the nearest bucket, so a continuous zoom gesture restyles at most this many times per level instead of once per frame.
