Native, memory-mapped consumption seam for OfflineRoutingNetworkGraph archive files.

This is milestone M7 slice 2’s zero-copy handoff: the mapped file answers byte slices that the fully validating in-memory reader (OfflineRoutingNetworkGraph::from_bytes) consumes unchanged, so both load paths — the file-mapped one here and the in-memory one in crate::archive — share the entire typed corruption model. The module is compiled only for native targets (see the workspace manifest): the browser loads the graph from in-memory bytes, with no mmap in the wasm path.

§Alignment validation

Opening the mapping validates the file-level alignment invariants the archive format fixes (crate::archive):

  • the mapped region covers at least FILE_HEADER_BYTES;
  • its byte length is a multiple of ARCHIVE_RESOURCE_ALIGNMENT — the deterministic writer always pads the archive’s total length to that boundary, so a region that breaks it is a truncated or corrupt archive;
  • the mapped base address honors the same alignment, which keeps the little-endian u64 table-of-contents field reads naturally aligned. Page-granular mapping guarantees this; it is validated, not assumed.

Deeper structure (table of contents, record widths, cross-references) is validated by the reader, exactly as for in-memory bytes.

§Error mapping

File-level failures (missing, unreadable, mapping refused) surface as SDKError::OfflineRoutingFailure(OfflineGraphInvalidReason::ArchiveMalformed): the typed corruption vocabulary deliberately has no I/O cause (the [SDKError] variants serialize across the frozen FFI contract), and an archive that cannot be mapped is unusable in exactly the way a malformed one is. A recognized-but-unsupported archive still fails as VersionUnsupported out of the shared reader.
