Benchmark support for the offline routing engine — the M7 slice 6 gate (PLAN.md M7 item 3; PRD.md §4.6’s “Dijkstra upgraded to A*” claim, measured in crate::offline_routing).

Not SDK surface: this module exists for the test suite and the criterion benches of this crate (benches/offline_search_benchmark.rs, run natively only, wasm is gated lib-only); production routing never calls anything here, and routing always goes through [crate::offline_routing::a_star_search].

Synthetic graphs are built the same way production loads build the router state: archive bytes are written with the same deterministic builder, read back through the same validating reader, and indexed by the same [LoadedRoutingGraph::new] — so the benchmark measures the real loaded-graph structures, on deterministic seeds, with no network.

Costs are column-honest so both strategies’ heuristics stay admissible: the distance column is always at least the endpoints’ straight-line distance, and the duration column is always distance / speed at a speed below the packed column’s saturation limit.

Constants§

BENCHMARK_GRID_SIDE_LENGTHS
Grid graph side lengths the criterion suite sweeps (squares of side * side nodes). Small enough for a fast job, large enough that the settled-set and wall-clock growth of Dijkstra against A*’s corridor is visible at the top size.
BENCHMARK_RANDOM_SPANNING_NODE_COUNTS
Random-spanning graph node counts the criterion suite sweeps. The spanning topology (branching corridors plus shortcut arcs instead of a lattice) is the second, differently-shaped case for Dijkstra.
BENCHMARK_RANDOM_SPANNING_SEED
Fixed seed of the random-spanning generator: the benchmark graphs are part of the recorded baseline, so the suite regenerates byte-identical archives every run (BenchmarkRng is a plain SplitMix64).
BENCHMARK_SPANNING_LOAD_BENCH_NODE_COUNT
Node count of the synthetic graph the load benches time the validating read and the routing-index build over (a larger column count than the committed fixture’s, so load regressions are visible).
