Expand description

The consumption path of compiled OfflineRoutingNetworkGraph archives: the in-repo [OfflineRoutingProvider] implementation.

The provider loads a compiled archive (from a memory-mapped file on native targets or from in-memory bytes everywhere — both validated by the same typed reader in map-offline-graph-archive::archive), keeps the validated graph plus a prebuilt half-edge adjacency and the turn-restriction rules, and answers route calculations over it with A* under a haversine heuristic (the M7 engine of PRD.md §4.6).

§Wasm path (milestone M7, PRD.md §4.6/§4.7)

PRD.md §4.6 turns the browser into a “compile-time target switch, not a runtime one”: the whole module compiles on every target — the A* search, snap, restriction and maneuver logic is target-agnostic — and the graph-loading seam is what differs:

  • OfflineGraphSource::Memory (in-memory archive bytes) is the seam every target loads through; on wasm it is the only graph source, with no mmap in the browser path.
  • OfflineGraphSource::FilePath maps the archive file natively; on wasm it is rejected typed instead of being silently unavailable: SDKError::ProviderRequestRejected, with a message that names the OfflineGraphSource::Memory seam to use in the browser (the wasm_file_path_rejection_message constant).

§Honest scope of this slice

  • Routing covers automobile travel only: the archive profile is the minimal drivable-ways profile, so a RouteOptions request for another mode is rejected instead of being answered dishonestly.
  • The cost weight follows RouteOptions::route_strategy (Fastest = graph edge durations, Shortest = graph edge distances); edge speeds and the packed road classes come out of each edge record.
  • Route steps are graph-metadata maneuvers: besides the road-class/ speed runs, a step boundary occurs at every junction whose derived turn — the signed bearing change between the two route edges measured on their real geometry — leaves the straight band, and the step then carries a Turn maneuver from the SDK’s shared [TurnDirection] vocabulary (the same enum the reducer, instruction emitter and FFI labels speak; no competing classification is invented here). The archive carries no street names, so step texts stay name-free and true to the geometry ("Turn right", "U-turn"); a class/speed change without a turn stays a Continue step. A step’s displayed and spoken text is end-anchored like the online provider’s re-anchor: a step’s banner names the maneuver at the step’s end — the junction node the countdown points at — while the head-anchored ManeuverType is unchanged (see [end_anchored_instruction_text]). The per-turn-restriction instruction strings remain restriction records — they describe forbidden turns, which a route by construction never traverses — and are not step content. Derived from adjacent graph-edge bearings, a strongly curved way yields a step per junction: the honest answer of the minimal schema (the accepted PRD §4.6 richness trade-off); no maneuver is invented beyond the bearing the graph itself records.
  • The turn-restriction approximation follows the classic caveat of a node-keyed A*: a restriction applies against the settled path’s incoming edge, which is exact unless a node can be reached on several best-cost paths through differently-restricted incoming edges (over-restrictive rather than understating).

§Benchmark reference (M7 slice 6)

PRD.md §4.6’s engine decision — “Dijkstra upgraded to A*” — is measured here, not asserted: [dijkstra_reference_search] is a plainly named Dijkstra over the same [LoadedRoutingGraph], differing from [a_star_search] in exactly the heuristic (zero instead of haversine). It is not a production path and nothing consumes it outside the criterion benchmark suite and the test suite (benches/ offline_search_benchmark.rs, offline_routing_benchmark.rs); it exists so “A* beats Dijkstra” is a recorded benchmark, and for nothing else.

Both searches expose their settled-node count on [ComputedRoute::settled_node_count] — a deterministic, noise-free expansion metric — and the coarse CI alarm (an asserted generous upper bound, offline_routing_benchmark’s budget test) guards gross regressions; the criterion numbers are the recorded trend baseline, not a CI pass/fail (shared-runner wall clock is too noisy to gate on).

§Runtime rules

load_offline_graph performs its mmap/read/validate work synchronously inside the async method — short-lived, with no await points, so no lock or I/O ever crosses an await (on wasm, bytes are read and validated in the same synchronous span; there is no mmap step). calculate_offline_route is pure computation over the loaded graph. A load fully validates the new source and only then replaces an already-loaded graph; a failed load leaves the previous graph loaded.
