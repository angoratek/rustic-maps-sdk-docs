Reroute-recalculation hysteresis (round 11, Ferrostar B3’s mechanism with our own expressions): the gates a reroute request must pass before it may begin.

A fully off-route excursion asks the integrator for a replacement route, but the request itself is an expensive asynchronous calculation that must not be spammed by jittery fixes: three hysteresis gates stand between the signal and the request, exactly the three Ferrostar’s FerrostarCore applies before it recalculates (no request in flight, a minimum recalculation cooldown and a minimum movement threshold), plus their observable isCalculatingNewRoute readback:

  • Request-in-flight gate. While one recalculation is still in flight, a new one is refused; the integrator settles the request (applies or abandons it) before the gates open again.
  • Cooldown. A new calculation waits out ReroutePolicy::recalculation_cooldown_seconds of wall clock since the last one began (a fix jittering in and out of the route within the cooldown window cannot fire repeated requests).
  • Movement threshold. A new calculation also waits until the raw position has moved at least ReroutePolicy::recalculation_movement_meters from the fix current at the last calculation’s beginning (Raw fixes, not the snapped position: a fully off-route trip freezes its snap, so a movement gate read off the snap could never be satisfied while it is most needed).

The gate is a stateful, wall-clock seam — deliberately not reducer state: the navigation reducer stays a pure, clock-free event function, and the exported controller holds the gate beside the session and evaluates it with the fix instant, the same seam its crate::speech::SpeechInstructionPlanner uses. now is injected into RerouteRecalculationGate::begin_calculation so tests pin the gates.

ReroutePolicy
The reroute-recalculation hysteresis policy values (the FFI-facing ReroutePolicy mirror record over the controller names the same facts).
RerouteRecalculationGate
Stateful per-trip reroute-recalculation gate: consumed by the exported navigation controller on each reroute-request signal and reset on trip start; the navigation reducer stays untouched (the gates are wall-clock controller facts, never reducer state).

Constants§

DEFAULT_REROUTE_RECALCULATION_COOLDOWN_SECONDS
The default minimum wall-clock seconds between the beginnings of two reroute calculations (Ferrostar’s minimumTimeBeforeRecalculation = 5).
DEFAULT_REROUTE_RECALCULATION_MOVEMENT_METERS
The default minimum displacement, in meters, between the raw fix current at a calculation’s beginning and the one current at the previous calculation’s beginning (Ferrostar’s minimumMovementBeforeRecalculation = 50).
