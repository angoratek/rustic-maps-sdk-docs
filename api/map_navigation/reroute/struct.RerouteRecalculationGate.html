Struct RerouteRecalculationGate 

Source 
pub struct RerouteRecalculationGate { /* private fields */ }
Expand description

Stateful per-trip reroute-recalculation gate: consumed by the exported navigation controller on each reroute-request signal and reset on trip start; the navigation reducer stays untouched (the gates are wall-clock controller facts, never reducer state).

pub fn set_policy(&mut self, policy: ReroutePolicy)

Swaps the hysteresis policy in force, keeping the gate’s memory as it stands (reconfiguring mid-trip never silently resets an in-flight window or a cooldown the caller may still read on).

Source

pub fn reset(&mut self)

Forgets all gate memory (trip start): nothing is in flight, no cooldown runs, no fix reference is held. The policy in force is kept — it is a controller configuration, not a trip memory.

Source

pub fn record_fix(&mut self, fix_coordinate: GeographicCoordinate)

Records the raw fix coordinate of one consumed position fix (the movement gate’s current side). Called for every fix the controller consumes, in flight or not.

Source

pub fn is_calculating_new_route(&self) -> bool

Whether a recalculation is currently in flight (the trip state’s is_calculating_new_route readback).

Source

pub fn begin_calculation(&mut self, now: Instant) -> bool

Applies the gates to one reroute-request signal, given the fix instant now. true means every gate passed and a calculation is now tracked in flight: the caller owes a settle (the reroute event or a cancellation). false means the request was refused by the first gate that failed (in flight, then cooldown, then movement) and the gate’s memory is untouched.

Source

pub fn settle_calculation(&mut self)

Settles the in-flight calculation (the integrator applied the replacement route, or abandoned the request): the request-in-flight gate reopens. The cooldown keeps running from the calculation’s beginning and the movement reference stays where it was, so the next request still waits out both — settle never reads as movement.
