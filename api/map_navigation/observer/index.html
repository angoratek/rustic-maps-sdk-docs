Mapbox-pattern per-topic observers over the navigation state machine.

Following the Mapbox Navigation observer split, this module registers listeners per topic behind one NavigationStateChangeListener trait, each subscription with an explicit TopicSubscription::cancel, so a consumer subscribes to only what it needs and each subscription cancels exactly itself:

  • instructions (dispatch_* always): the composed NavigationInstruction payload of every dispatched state change, produced by crate::instruction::compose_navigation_instructions;
  • deviation status (on change): DeviationStatusChange as the detector’s judgment enters, deepens/updates or clears — the per-fix judgment stream, including measurement drift while the phase stays OffRoute;
  • phase (on transition): NavigationPhaseChange — one-shot transitions OffRoute entered/cleared, RerouteProvided applied, and Arrived.

§Threading contract

Dispatch is synchronous and single-threaded by contract: callbacks run on the caller’s thread, in the dispatch’s own stack frame. The foreign callback wiring into the frozen UDL contract is a later slice and will own platform-side thread hop; this stays a Rust-side seam. Cross-thread calls are data-race-free (the trait requires Send + Sync) and are at worst suppressed by the re-entrancy guard, but the ordering guarantee is stated for single-threaded use only.

§Dispatch rules

  • No lock is held across listener callbacks. The registry lock is taken once to snapshot the (cheaply cloned) listener lists and released before the first callback runs, so a listener may freely call back into the broadcaster — including TopicSubscription::cancel — without deadlocking (Mapbox’s rule in spirit).
  • Delivery order: within a topic, strict registration order; across topics, instructions first, then deviation status, then phase.
  • One dispatch in flight. The deliberate re-entrancy bound: a dispatch that starts while another dispatch is still in flight — typically a listener driving the reducer and re-dispatching from its own callback — delivers nothing and reports NavigationDispatchOutcome::SuppressedReentrant. Nothing is queued (no unbounded growth, no re-entrant cascade): the state change behind a suppressed dispatch is never lost — it already happened in the reducer — but its broadcast is skipped, so a listener that re-dispatches must let the outer dispatch finish and dispatch again from the top level. The common listener shapes (recording, platform notification) are fully synchronous and unaffected.
  • Listener errors cannot poison the reducer. Listener methods return nothing, so there is no error channel by construction; the dispatch runs after the reducer has already produced its new state and only reads the state it is handed. A listener that panics propagates the panic to the dispatch caller (this is a synchronous Rust seam, not a foreign boundary), and cannot corrupt the trip state or wedge the broadcaster: the in-flight guard releases on unwind. Whether to catch panics per listener is deferred to the foreign-wiring slice, which owns the actual FFI error policy.
  • Snapshot semantics for cancel: a subscription cancelled during a dispatch may still receive that dispatch’s callbacks (the snapshot was taken before); cancellation is guaranteed for every dispatch started after cancel returns.
