Expand description

One listener’s callback surface, split by topic.

The methods have default no-op bodies: implementing only the topics a consumer needs is trivial. Registered subscriptions select which method a dispatch may call — subscribing to instructions delivers only Self::on_navigation_instruction to that subscription, and so on.

Payloads are flat immutable records with no error channel: the listener cannot fail into the broadcaster (see the module-head dispatch rules).

fn on_navigation_instruction(&self, _instruction: &NavigationInstruction)

Receives the composed NavigationInstruction payload of every dispatched state change (the instructions topic).

Source

fn on_deviation_status_change( &self, _deviation_status_change: &DeviationStatusChange, )

Receives a deviation-status stream update (the deviation topic): DeviationStatusChange::OffRoute on entry and on every recorded measurement update while the deviation persists, DeviationStatusChange::OnRoute when it clears.

Source

fn on_navigation_phase_change( &self, _navigation_phase_change: &NavigationPhaseChange, )

Receives one NavigationPhaseChange per transition (the phase topic): OffRoute entered or cleared, a reroute applied, arrival.

Source

fn on_speech_utterance(&self, _speech_utterance: &SpeechUtterance)

Receives one speech-trigger utterance the controller’s pacing policy judged newsworthy (round 10, the speech topic). Never emitted while no listener subscribes to the topic; the composed speech text is carried verbatim and the platform owns playback.
