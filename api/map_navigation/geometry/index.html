Polyline snapping mathematics for route progress.

The navigation state machine repeatedly needs two measurements against the current step’s shape: the closest point on the polyline (the snapped position) and the distance from a raw position fix to the polyline (the same minimum the deviation detector consumes later). Both live here so the projection error is documented and tested in exactly one place.

§Projection model

Each segment is projected into a local equirectangular plane around its own midpoint: a north/south offset of y meters becomes y / RADIUS radians of latitude and an east/west offset of x meters becomes x / (RADIUS * cos(reference_latitude)) radians of longitude. This is exact along the reference parallel and along meridians within the small-angle approximation; the residual grows with segment length and distance from the equator. For the road-scale segments a navigation step carries (well under 1 km) at inhabited latitudes the distortion is far below a meter, comfortably inside GNSS accuracy. The minimization over segments uses this planar space; the reported distance is then recomputed exactly with the haversine formula. Antimeridian-crossing shapes are not supported in this slice: longitudes are treated as a plain number line.
