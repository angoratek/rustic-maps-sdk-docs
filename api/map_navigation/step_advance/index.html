Module step_advance

Expand description

Step-advance conditions, following the Ferrostar pattern in a leaner form.

A StepAdvanceCondition is a pure decision object consulted by the reducer on every location update. Conditions are passed into the reducer as Arc<dyn StepAdvanceCondition> parameters (as Ferrostar’s controllers do) and never live inside the exported TripNavigationState, which must stay plain data for UniFFI.

§The fresh-instance contract

StepAdvanceCondition::fresh_instance returns the same configuration with any internal state reset. The reducer swaps the active condition for fresh_instance() the moment it advances. This is the seam that prevents Ferrostar’s rapid-double-advance bug: a condition that tracks progress within a step (for example, one awaiting several consecutive fixes) would otherwise carry saturated internal state across the advance and immediately advance again on the next update. Stateless conditions can simply return a clone of themselves, but the contract is uniform so composite conditions (a later slice) can reset every nested condition recursively.

§Combinators

OrStepAdvanceCondition and AndStepAdvanceCondition wrap two inner conditions and decide on their combined verdicts. Both consult every inner condition on every update (even when the outcome is already decided for And): a stateful inner condition must observe every update for its internal schedule to stay sound. fresh_instance rebuilds both inner conditions fresh, which is what makes the reducer’s whole-composite reset on advance equivalent to the reference’s per-child next_iteration swap.

Deferred to later slices, deliberately: the entry-and-exit condition variants and the deviation-aware calculation_policy surface of DistanceFromStepCondition (which need a richer deviation status than this slice’s on/off-route judgment).

Constants§

DEFAULT_DISTANCE_FROM_STEP_THRESHOLD_METERS
Threshold, in meters from the current step’s polyline, beyond which DistanceFromStepCondition advances. Ferrostar’s DEFAULT_DELAYED_STEP_ADVANCE_DISTANCE for the delayed-off-polyline condition.
DEFAULT_DISTANCE_TO_END_OF_STEP_THRESHOLD_METERS
Threshold, in meters from the end of the current step, below which DistanceToEndOfStepCondition advances. Ferrostar’s recommended default for the eponymous condition (DEFAULT_STEP_ADVANCE_DISTANCE): large enough to absorb GNSS noise near the maneuver, small enough not to swallow short steps.
DEFAULT_MINIMUM_HORIZONTAL_ACCURACY_METERS
Fixes with a reported horizontal accuracy worse than this, in meters, may never trigger an advance in the distance conditions. Ferrostar’s DEFAULT_STEP_ADVANCE_MIN_HORIZONTAL_ACCURACY.
