Deviation (off-route) detection, the second decision seam beside the crate::step_advance conditions.

A DeviationDetector follows the step-advance pattern: the reducer consults it on every location update carrying the measurements it already computed, and the live instance rides in NavigationSession beside the state (never inside the exported plain-data record).

§Judgment semantics

The shipped detector is a pure per-fix predicate over the measured distance: a fix is off route when its distance to the remaining route line exceeds the configured threshold widened by the fix’s reported horizontal accuracy. Widening (instead of the reference’s hard accuracy gate) is a deliberate choice: the accuracy radius is exactly the plausible gap between the raw fix and the truth, so a genuinely on-route position may legitimately read up to one accuracy radius away from the line; a widened allowance suppresses those false flags gracefully instead of failing abruptly at a gate. The measurement is taken against the remaining route line (the current step onward) rather than only the current step, mirroring the reference’s route-line detection: a lagging step — eager advance semantics, pauses at intersections — is then never mistaken for a deviation.

§Two grades (the reference’s OffStepOnRoute distinction)

A fix beyond the allowance from the remaining route line is judged fully off route. A fix inside the remainder’s allowance but beyond the allowance from the current step’s own polyline projects onto a future step: the reference’s OffStepOnRoute grade, returned here as DeviationStatus::OffStepOnRoute (“on route, wrong step”). A shortcut, a self-intersecting route, or a lagging step-advance can all legitimately put a fix on a later step, so the wrong-step grade is guidance feedback — the reducer neither freezes on it nor asks for a reroute, and the step-advance condition (with a delayed condition, within the very fix that produced the grade, via the reducer’s multi-step advance loop) reconciles the step. Only DeviationStatus::OffRoute is the freezing grade.

§Hysteresis

The ported Ferrostar reference carries the deviation status through its state (consumed by deviation-aware step-advance conditions) but ships no hysteresis itself: no separate recovery threshold, no minimum off-route time. Porting that shape therefore means one threshold for both raising and clearing a deviation, so the flag can flicker around the allowance edge; hysteresis (a wider clearance than detection, or a time gate) remains a documented deferral rather than an invention here.

The reducer’s contract with the detector, documented in crate::reducer: a fix without an accuracy report is never judged at all — it can neither raise nor clear a deviation.
