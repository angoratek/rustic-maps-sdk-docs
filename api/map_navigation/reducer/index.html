Module reducer 

Source
Expand description

The pure event reducer driving an active trip.

reduce_navigation_event maps one event onto the previous session and returns the next one; it has no I/O, no clock and no mutable globals, so every outcome is reproducible from the event history (the seam Ferrostar builds its whole controller around). The live StepAdvanceCondition and DeviationDetector instances are threaded through NavigationSession — pairing state with its decision objects exactly as Ferrostar’s NavState does — because they are swapped for their StepAdvanceCondition::fresh_instance (or DeviationDetector::fresh_instance) counterparts at reset points, and the exported crate::state::TripNavigationState must stay free of trait objects.

Semantics in this slice:

  • NavigationEvent::StartTrip flattens the route and reports the declared step values as remaining progress until the first fix arrives.
  • NavigationEvent::LocationUpdated is judged for deviation first: a fix the detector grades fully off route freezes the session — the snapped coordinate and progress stay at the last on-route values, and neither the step-advance condition is consulted nor the step advances (deviating positions must not drive route progress; the reference freezes the same way while deviating). A fix graded off the current step but on the route (DeviationGrade::OffStepOnRoute, a projection onto a future step) never freezes on its own: the grade is recorded in the state, the trip stays Navigating — no reroute request, instructions keep counting down — and the fix is then processed normally (the step-advance condition reconciles the step; a delayed condition does so within the very fix, via the multi-step advance loop below). A fix without an accuracy report is not judged at all: it can neither raise nor clear a deviation, because one threshold rule cannot conservatively decide both directions. A graded fix inside the allowance lifts an active deviation (an OffRoute trip recovering from the route line, or a lingering wrong-step grade clearing) and the update then proceeds normally (condition consulted, position snapped, progress recomputed). crate::state::NavigationPhase::OffRoute is therefore a pause the user may recover from by returning to the route, not a terminal state.
  • Arrival-aware advance (the reference’s separate arrival condition): the condition consulted for a hop is not always the trip’s own. Once the remaining steps — counted as the reference counts them, the current step itself included — shrink to the arrival window (ARRIVAL_CONDITION_REMAINING_STEPS_BOUND), a separately configured arrival step-advance condition is consulted instead (falling back to the trip’s own condition when none was configured, which preserves the behavior of every trip that has none). Arrival itself is reachable only through that final-step verdict: an Advance while on the final step cannot pop another step — it declares NavigationPhase::Arrived and breaks the loop exactly where the reference’s arrival arm does, ahead of any further consult, so neither the loop’s defensive bound nor a still advancing condition can walk past the route’s end.
  • The trip’s course-filtering policy stamps an effective course (TripNavigationState::course_heading_degrees) during each processed fix’s position snap; see crate::course_filtering.
  • One fix may advance through several steps (the reference’s loop-until-break speed-run semantics, not recursion): after each single-hop advance — which swaps in the fresh condition instance exactly as the single-advance slice did — the freshly computed inputs decide whether the same fix advances the next hop too. The loop is bounded by MAXIMUM_STEP_ADVANCES_PER_FIX and terminates by construction: a hop can end the trip only by arriving, and every other break is the condition’s Remain.
  • NavigationEvent::RerouteProvided rebuilds the session for the same trip from a fresh route. The remote-first, offline-fallback policy (compute the replacement route remotely, fall back to an offline graph) lives at the integrator/event-source layer, which owns the route request; the reducer stays policy-free and pure. See the event documentation for the route-anchoring contract it implies.
  • Updates after the phase is Arrived are ignored; reroutes offered to an arrived trip are ignored as well.

Later slices, deliberately deferred: observers and listeners, and programmatic step advance.

Defensive ceiling, in steps, on how many hops a single position fix may advance through in the multi-step advance loop.
