Module provider_contract_names 

Source
Expand description

The one mapping between the shared provider registry’s served_contracts names and the contract’s capability enum.

The shared registry spells every capability in snake_case (geocoding, distance_matrix, …) while the frozen contract names the same capabilities as ProviderContract variants. The mapping lives here, in the contract, and the platform surfaces resolve names through these two functions: the Kotlin registration plan and descriptor accessors, and the Swift registry catalog and registration path, whose generated bindings carry both calls. Adding a capability to the registry therefore never requires a per-surface table.

ProviderContract::registry_name is the single table; both functions read it, and the module’s tests prove that every variant has exactly one name and that parsing round-trips.
